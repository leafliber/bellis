# 游戏桥

Bellis 与独立的 Game Runtime 之间的桥接插件（普通插件）。Bellis 只下发语言子目标与输入许可，接收局面、决策点和已发生的动作；逐帧控制全部留在 Game Runtime（D-04、D-27）。P3 实现，契约在 P3 开工前与 Game Runtime 共同冻结。

## 职责

- 维护与 Game Runtime 的连接、认证与心跳。
- 把决策模型的游戏目标转为命令，并持有和续约游戏输入许可。
- 把 Game Runtime 的事件转为 Bellis 的事实，供决策与解说使用。

## 不负责

画面采集、OCR 与 VLM 感知、VLA 策略、按键时序。这些在 [bellis-game-runtime](https://github.com/leafliber/bellis-game-runtime) 中实现，各自是可独立开关的插件（D-08）。

## 契约草案

命令用 `对象.动作`，事件用 `对象.过去式`。字段在 P3 冻结前可调整。

### 下行命令

| 命令 | 内容 |
| --- | --- |
| `goal.submit` | 语言子目标、结构化约束、模式（自主 / 等待投票 / 暂停 / 人工）、过期时间 |
| `lease.renew` | 续约游戏输入许可（一种执行许可，见[安全核](safety-core.md#执行许可与急停)）。过期则 Game Runtime 自行释放全部输入 |
| `decision.resolve` | 对某个决策点给出选项（来自投票或决策模型自选） |
| `input.stop` | 立即停止并释放全部输入；幂等 |

### 上行事件

| 事件 | 内容 |
| --- | --- |
| `situation.observed` | 局面摘要（场景类型、剧情文本、可交互元素），约 1–2Hz 并在变化时触发 |
| `decision_point.opened` | 选项，是否计时，计时的截止时间 |
| `action.committed` | 已经实际发生的动作，解说只讲这里出现的事 |
| `input.released` | 全部输入已释放 |
| `health.reported` | 首动作时间、帧龄、队列深度、风险分 |

潜向量只在 Game Runtime 内部使用，不跨仓库传递（D-27）。

## 决策点（《魔女审判》）

- 没有计时的选项：决策模型决定直接自选，或发起观众投票；Game Runtime 以“等待投票”模式停在该决策点，直到收到 `decision.resolve`。
- 有计时的选项（审判环节）：决策模型在截止前自选；超时由 Game Runtime 按自身默认策略处理，并上报实际结果（D-07）。
- 操作员可随时把模式切为“人工”接管。

## 安全

- 游戏输入许可与 Stage 音频输出许可是两份独立的执行许可，急停时一起吊销。
- Game Runtime 的输入代理是受信组件：键位白名单、速率与长按上限、前台窗口校验；急停时主动发出全部按键抬起并核验，而不只是停止发送（SendInput 不会自动重置键盘状态）。
- Game Runtime 在游戏需要时以管理员权限运行，由其自身方式启动，并按 R-23 获取连接信息；Bellis 宿主始终不提权，并作为本机通道的服务端（见 [Windows 平台](../platform/windows.md)）。
- 风险分超过阈值时，Game Runtime 停止注入并上报，Bellis 让角色口播过渡并通知操作员。
