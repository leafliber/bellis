# 发声

把决策模型的文本变成观众听到的话：分句、（可选）审核、排队、合成、播出，并保证“一张嘴”。发声仲裁属于关键平面；TTS 以 `tts@1` 服务接入。P0 由模拟 TTS 直接提供该服务。P1 起云端优先（R-10）：本项目的云端 TTS 插件直接提供 `tts@1`，同一接口接 MiniMax 与火山引擎，主备由探针 S-07 定；本地降级引擎（Qwen3-TTS）以 sidecar 运行，由 TTS 代理插件把 sidecar 的 RPC 与二进制音频适配成 `tts@1`。

## 职责

- 把文本流切成可以独立合成的句子，生成字幕文本与朗读文本。
- 在“发声前检查”扩展点调用已启用的检查插件（目前只有[审核插件](moderation.md)）。
- **发声仲裁**：决定此刻谁能说话，管理排队、过期与抢占。
- 按 Stage 回报的播放游标，记录观众实际听到了什么。

## 不负责

决定说什么（[决策模型](director.md)）、审核判定（[审核插件](moderation.md)）、音频播放（[Stage](stage.md)）。

## 管线

```text
文本流 ─► 分句 ─► 双文本 ─► 发声前检查（审核插件，可关闭）─► 发声仲裁 ─► TTS 插件 ─► 云端或本地 TTS
                                                              │                          │
                                                              │                    音频回到宿主
                                                              ▼                          ▼
                                                   持有 Stage 音频输出许可 ──► Stage 服务 ─► Stage 页面
                                                              ▲                                     │
                                                              └──── 播放游标、完成、截断 ◄──────────┘
```

各级之间是有界队列，下游满了就向上游施加背压；任何一级被取消，取消沿管线传播，TTS 插件随之取消正在进行的合成（云端用厂商的取消指令，本地停止 sidecar 中的生成）。TTS sidecar 与宿主之间，音频用与控制消息分开的二进制帧传输（D-21）。

云端 TTS 只发送已通过发声前检查的朗读文本（仲裁在检查与授权之后才调用 TTS），每家厂商只有在 profile 中显式开启外发后才会连接，见下文[云端 TTS](#云端-tts)。

### TTS 接口

`tts@1` 的 `synthesize(朗读文本, 中止信号)` 返回一句的合成：采样率、增量产出的 16 位单声道 PCM 帧、总采样数与时间映射。

- 没有任何可用引擎时以错误结束：这一句不播出，发言以“不可用”结束并带上原因。
- 中止信号触发、或使用方提前停止读取音频（例如 Stage 截断了这一句）时，提供方立即停止产出并取消合成。仲裁为每句单独派生中止信号：发言中止，或这一句合成了却没有播完（被打断、截断、出错），都取消这一句的合成。
- 总采样数与时间映射是活的：提供方在合成过程中更新它们（两段式对齐，见[播放游标与写回](#播放游标与写回)），使用方按播放游标换算时现读，不提前取出缓存。

### 云端 TTS

`tts-cloud` 插件直接提供 `tts@1`，内部按厂商适配器接 MiniMax（`t2a_v2_bidi`）与火山引擎（V3 `tts/bidirection`）的双向流式接口，协议细节以[参考资料](../references.md#实时语音与媒体)中的官方文档为准。

- **外发闸门**：每家厂商只有在插件配置中显式开启外发（`egress`）、配置齐全、端点为 `wss://`（本机测试除外）且端点主机已授予 `net.egress:<主机>` 时才会连接，否则视为不可用并在日志里说明原因。清单按两家的官方主机申请外发权限，并申请 `secret:minimax`、`secret:volcengine`，未授予则停在 WAITING。
- **凭据**：经宿主的凭据服务按名读取，值不写日志、不进事件。`minimax` 存 API Key；`volcengine` 存新版控制台的 API Key，只有旧版控制台的 APP ID 与 Access Token 时存 JSON `{"appId": "…", "accessToken": "…"}`。端点、模型、音色、资源 ID 等非机密配置在插件配置里。
- **连接**：每家一条长连接，多句复用，空闲过久主动断开，下一句重新建连。MiniMax 每句发文本与 flush，取消发 `task_cancel`，空闲时定时 ping；火山引擎每句开一个会话，取消发 CancelSession，其它会话的帧一律丢弃。取消之后到达的音频一律丢弃。
- **主备**：按配置的 `primary`、`fallback` 顺序取第一个可用的引擎。连接失败、鉴权失败、超时或服务端出错时，这一家冷却一段时间（`retryAfterMs`），这一句改用下一个，冷却期满后下一句再试主引擎。厂商以文本本身为由拒绝的句子（过长、非法字符过多）不换引擎、也不让引擎冷却，这一句合成失败。每次换用都记事件 `tts.switched`（从哪个到哪个、原因）并写日志提示操作员。
- **只出字幕**：`fallback` 中的 `subtitles`。TTS 插件给出与估计朗读时长等长的静音帧和对应的插值映射，Stage 照常显示字幕、回报游标，仲裁与 Stage 不区分这种模式；写回的是观众看到的字幕。
- **时间戳**：MiniMax 用 `word_streaming` 字幕，随每段音频到达，时间相对当前句从 0 起算；火山引擎的 TTS 1.0 资源用 `enable_timestamp`（随句末返回），TTS 2.0 资源用 `enable_subtitle`（字幕事件），时间相对整个会话（每句一个会话）。时间戳的文本逐码点与朗读文本对照，不依赖厂商的字符偏移。
- **待 S-07 核对（PENDING）**：两家文档都没有写明 PCM 的位深与字节序，按 16 位有符号小端处理；火山引擎字幕事件的编号文档未列出，按载荷中的 `words` 识别；火山引擎在 FinishSession 之后 CancelSession 是否生效；MiniMax 被取消的 flush 是否仍会确认（未确认时取消后断开重连，不冒险复用会话）。

### 分句与双文本

- 在语义完整的边界切句，不按固定字数切。首句尽量短（例如第一个分句），以缩短开口时间；过长的句子在分句处切开。
- 每句生成两份文本：**字幕文本**（显示给观众）和**朗读文本**（交给 TTS，数字、缩写、多音字、角色名已规范化）。审核插件启用时，两份文本一起判定。
- 观众的原始昵称和弹幕原文不直接朗读，改用经过净化的称呼。
- 朗读文本逐码点记录它对应的字幕位置，供按播放游标换算已播出的字幕。

## 发声仲裁

每个发声请求带：

| 字段 | 含义 |
| --- | --- |
| 来源 | 由确定性代码按请求的来源填写，决定优先级；决策模型不能自定优先级（D-33） |
| 过期时间 | 过期即丢弃，避免回复已经滚走的弹幕 |
| 可抢占点 | 句边界，或立即 |
| 去重键 | 同一件事不重复说 |

来源与优先级（从高到低）：

| 来源 | 说明 |
| --- | --- |
| 安全播报 | 安全核或操作员触发的固定提示 |
| 投票结果 | 投票引擎产生 |
| 定时播报 | 操作员预先配置的节目提示 |
| 游戏关键反应 | 由游戏事件触发的解说 |
| 弹幕回复 | 回应观众 |
| 闲聊 | 冷场时的自主发言 |

- 只有发声仲裁持有 Stage 音频输出许可，并把许可令牌随音频一起交给 Stage 服务。
- 只有安全播报、投票结果、定时播报、游戏关键反应可以抢占，且优先级须高于正在进行的发言。抢占发生在被打断的发言自己声明的可抢占点；被打断的发言按播放游标截断，其余句子撤销。
- 普通弹幕不能抢占正在进行的发言，只能排队或过期。
- 每句先经发声前检查，再取得 Stage 音频输出许可、经安全核授权，然后才合成与播放；每次等待之后都重新检查停止、软收尾与抢占，尚未开始播出的句子不再播出。续约间隔由许可时长决定。审核插件的开关为开、但插件不在场时，句子一律跳过，不悄悄放行。
- **M1 的固定延迟加否决**：M1 下每句在发声前检查之后交给放行环节（`speech-review` 插件），等待 profile 配置的延迟再播出；等待期间操作员用 `pnpm operator veto` 否决，被否决的句子跳过、不播出。放行环节不在场时，M1 下一句也不播。每句等待恰好以一个事件结束：放行 `speech.released`、否决 `speech.vetoed`，或因停止、模式变化、发言中止而撤回 `speech.withdrawn`；等待开始时记 `speech.held`，操作员在 `pnpm operator status` 的 `held` 里看到等待中的句子。否决经安全核的控制通道送达，不经普通事件队列。

## 播放游标与写回

- **播放游标**是 Stage 回报的“句编号 + 该句已实际播出的采样数”。
- 把采样数换算成文本位置，需要该句的时间映射：采样偏移 → 朗读文本的字符位置（Unicode 码点）→ 字幕文本的位置。映射分两段取得（R-11）：
  - **插值**：句段一到，就按朗读文本的字数（标点处加权停顿）把它线性铺在该句时长上，字幕立即可用；总采样数未知时按语速估计，合成完成后按实际采样数修正。
  - **细化**：随后用 TTS 返回的字/词级时间戳替换插值；本地 TTS 不出时间戳，用 Qwen3-ForcedAligner 对已合成的句段做强制对齐。对齐对象是朗读文本，结果再经码点对应映射回字幕文本；对不齐的片段在相邻的时间戳之间重新插值。
  - 两段都由 TTS 提供方在合成过程中完成（发声包里的 `Alignment` 是共用实现），仲裁读到的总是换算那一刻的映射；时间戳的文本逐码点与朗读文本对照（半角与全角标点视同），对不上的字词不往远处对。
- 结束时刻不晚于播放游标的朗读码点才算已播出；只计入完整播出的码点。一个码点的结束时刻是下一个码点的开始，最后一个码点的结束时刻是实际总采样数，被取消而总数未知时不计入。
- 没有映射时退化为整句粒度：完整播完的句子算已播出；播到一半被打断的句子只记“在中途被打断”，不猜测具体位置。
- 写回决策模型上下文与记忆的，只能是观众实际听到的部分。

模拟 TTS 为每句给出精确的合成映射，也可以模拟两段式（先按估计的语速插值，再随音频逐字细化），用于验证截断与写回逻辑；真实映射的精度在 P1 实测。

## 停止

| 方式 | 行为 |
| --- | --- |
| 软收尾 | 关闭追加，当前句播到可抢占点，撤销尚未播出的句子 |
| 硬停 | 吊销 Stage 音频输出许可，Stage 立即静音并清空缓冲 |

两者都以 Stage 回报的实际播放位置为准；只发出停止命令、没有收到 Stage 的回报，不算已停。

## 降级

- 主 TTS 不可用：按 profile 配置切到备用引擎，或改为只出字幕的文字模式；切换记入事件日志并提示操作员，不暗中换音色（云端的做法见[云端 TTS](#云端-tts)）。
- 审核插件出错：按其 `on_error` 配置处理（见[审核插件](moderation.md)）。
- Stage 不可用：安全核经 OBS 应急连接静音并切安全场景（D-30）。

## 验收

| 阶段 | 内容 |
| --- | --- |
| P0 | 模拟链路下：按来源定优先级、抢占与截断记录正确；审核插件启用时被判不可说的句子不会播出，关闭时直接放行；硬停后无残余输出；写回只含已播出部分 |
| P1 | 真实 TTS 首包与取消（S-07）；时间戳与对齐结果相对人工标注的偏差；字幕与音频偏差实测 |
| P2 | 真实弹幕负载下的排队、过期与抢占 |
