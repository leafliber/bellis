# 记忆（Iris 客户端与隐私网关）

经隐私网关接入独立的长期记忆服务 Iris（仓库 [iris-core](https://github.com/AirObject/iris-core)）。普通插件，只在慢速通道上工作。P2 实现召回与写入，T1 试播起用于公开直播（D-10）。Iris 以 Docker 部署在本机，由维护者启动，不是宿主的子进程（D-23）。

## 职责

- 在决策前召回与当前话题相关、可以公开说出的记忆。
- 把角色实际说过的话和观众的弹幕异步写入 Iris。
- 在召回前和写入前执行隐私规则；维护本地墓碑。

## 不负责

实时状态（那是[状态存储](state-store.md)）、权限。人设由 Iris 提供、经维护者在 Iris 管理端确认，决策插件怎样选用见[决策模型的人设](director.md#人设)；记忆插件只负责取来并缓存（见下文[人设](#人设)），召回的记忆不能改写人设。不负责 Iris 自己的学习与外发（Iris 把收到的原文发给它配置的模型，由维护者核对，见下文[就绪与开播预检](#就绪与开播预检)）。

## iris-core v1 现状

以下是对 iris-core main 分支提交 7826440（2026-10-14）的核对结果，包括代码、测试与其自述文档；2026-10-19 对照 main 分支提交 cc60a0b（发布版 v0.0.2 之后）的宿主接口契约复核过接口与部署两行。接入设计以此为准，Iris 更新后重新核对：

| 方面 | 现状 | 对 Bellis 的影响 |
| --- | --- | --- |
| 接口 | HTTP + JSON（`/api/v1`，Bearer 令牌），SSE 推送目标提醒；召回准备（`prepare`）可用 `judge=false` 关闭召回判断，判断预算缺省 10 秒、只能调短，没有整体请求时限 | 自写薄客户端（R-19），客户端自己设超时；不用 WebSocket |
| 写入 | 宿主只提交原始消息（`kind` 含 `self_output`），由 Iris 后台学习；必填 `dedupe_key`，同一入口重复提交返回原消息；一次可提交 1–1000 条，整批原子 | 写入是异步的；iris-core README 自述学习批次 P95 约 35–43 秒；去重键由 Bellis 持久保存，重试沿用原键 |
| 可见范围 | 按入口划分三档，没有按主体或用途的访问控制 | 同一直播间入口内的记忆全部共享，只能召回公开事实 |
| 身份 | 按（平台, 账号）区分；缺账号时退回用昵称作键 | Bellis 必须总是传平台稳定 ID（B 站为 `open_id`，见 R-18） |
| 删除 | 宿主接口没有删除；删除后内容可能被重新学回来；不改写备份 | 墓碑在 Bellis 本地维护；私密与个性化功能暂不开放 |
| 外发 | Iris 自己把原文发给它配置的模型 | Iris 的模型配置必须符合 Bellis 的外发与合规要求，维护者核对后在 profile 中确认 |
| 部署 | 只在 macOS 验证过原生运行；提供 Docker 镜像。普通模式只监听回环地址，容器模式（`IRIS_CONTAINER=1`）才允许非回环监听，不提供 TLS；Host 缺省只接受 `127.0.0.1`、`localhost`、`[::1]` | 以 Docker 部署在本机，端口只映射到 127.0.0.1，令牌不出本机（D-23）；容器内运行与召回延迟由探针 S-09 验证 |
| 许可 | iris-core 与其 TS 客户端均为 AGPL-3.0 | 按 HTTP 契约自写客户端（R-19） |
| 人设 | 召回准备的 `persona` 分区是当前角色描述、版本与更新提示：初版来自管理端的角色名与背景，之后从角色的自我记忆中提炼候选；自 2026-10-10 起缺省“全部人工确认”，候选经管理员确认前一直用当前版 | Bellis 用它作人设（见[决策模型的人设](director.md#人设)），要求 Iris 保持全部人工确认；只取正文与版本号 |
| 信任标记 | 消息没有“可信与否”的字段；记忆带说话人（`speaker_name`）、涉及的人（`about`）与来源消息 | 观众消息以 `kind: "message"` 归在观众名下写入，即“观众声称”；召回的一切都放进不可信数据区 |

## 两个插件

收发与解读分开（见[插件内核](plugin-kernel.md#权限)）：

| 插件 | 包 | 提供 | 依赖 | 权限 | 做什么 |
| --- | --- | --- | --- | --- | --- |
| `iris-client` | `packages/iris` | `iris@1` | 时钟、凭据服务 | `net.egress:127.0.0.1`、`secret:iris` | 只负责收发：按宿主接口契约的 HTTP 薄客户端，令牌只进请求头 |
| `memory` | `packages/memory` | `memory@1` | `iris@1`、安全核门面、时钟、随机数；弹幕接入（`danmaku@1?`）、遥测为可选 | `memory.write` | 隐私网关、写入与待发队列、墓碑、召回与过滤、使用反馈；不持凭据 |

`iris@1` 与 `memory@1` 的契约分别在 `packages/memory/src/iris.ts` 与 `service.ts`。决策插件以可选依赖使用 `memory@1`（见[决策模型的上下文](director.md#上下文)）。仿真与测试用模拟 Iris（`iris-sim`，同样提供 `iris@1`，数据在核心服务 `iris.sim-backend@1` 里，跨重启保留）。

### Iris 客户端

- 请求：`Authorization: Bearer <宿主令牌>`、`Accept: application/json`，有正文时 `Content-Type: application/json`；路径为地址加 `/api/v1`；不跟随重定向。入口 ID 按契约核对（1–200 个字符，不全为空白，不含 `?`、`#` 与控制字符），另外不用 `/`、`\` 与 `%`（入口 ID 在路径里，服务端按解码后的路径路由）。
- 用到的接口：写入消息（`POST /entries/{id}/messages`，总以数组提交）、召回准备（`prepare`）、定向查询（`POST /memories/search`，探针用）、使用反馈（`POST /feedback`）、状态（`GET /status`，开播预检用）。返回体只取用到的字段并核对类型，未知字段忽略；至多读 `maxResponseBytes`。
- 不做隐式重试。失败按 HTTP 状态归类（不靠说明文字）：401 `auth`、403 `forbidden`、404 `not_found`、409 `conflict`、413 `too_large`、其余 4xx `invalid`、429 `rate_limit`、503 `unavailable`、其余 5xx `server`；超时 `timeout`、连接失败或读取中断 `network`、返回不合约定 `protocol`、调用方取消 `aborted`。429、503 带上 Iris 建议的等待（错误体的 `retry_after_seconds` 或 `Retry-After`，至多 10 分钟）。
- 说明里只有类别、HTTP 状态、错误码与出错的字段路径，不含 Iris 的说明文字（可能复述了请求内容）与令牌；日志 `iris.failed` 只记操作、类别、HTTP 状态与错误码。
- 激活时核对：维护者已确认 Iris 的外发配置（`egressReviewed`）、地址是 https（本机回环可以是 http）且不带用户名、密码、路径、查询与片段、主机已授予外发、令牌已录入；任何一项不满足就以说明原因的错误加载失败，不发任何请求。

| 配置 | 含义 |
| --- | --- |
| `baseUrl` | Iris 的地址（不含 `/api/v1`），缺省 `http://127.0.0.1:8080` |
| `egressReviewed` | 维护者已核对 Iris 的外发配置：Iris 自己会把收到的原文发给它配置的模型服务，维护者确认那些服务与端点符合 Bellis 的外发与合规要求（[合规](../compliance.md)“Iris 外发”）。缺省 false，不是 true 时插件不激活 |
| `requestTimeoutMs` | 每个请求的截止时间，缺省 10 秒；召回另由调用方给更短的截止时间 |
| `maxResponseBytes` | 返回体的字节上限，缺省 2 MiB |
| `unreadyAfter` | 连续失败达到这么多次就报告未就绪（直到下一次成功），缺省 3；鉴权或权限失败一次就未就绪；内容被拒（`invalid`、`too_large`）与取消不算 |

## 召回

- 决策插件在调用模型之前召回，截止时间是它的 `recallTimeoutMs`（缺省 2 秒，不计入模型调用的 `callTimeoutMs`）：到点、出错或记忆插件不在场都不带记忆继续决策；记忆插件没有及时响应中止信号也照样到点就走，晚到的结果不用。召回跟着这次决策时机走：在途的闲聊被取消时，召回一并取消。
- 查询提示是候选弹幕的净化文本与刚结束的投票题目（至多 `recallQueryChars` 字，缺省 500）；冷场时不给，由 Iris 用本入口的近期消息自己构造。
- 请求只取记忆与人设：关闭召回判断（`judge: false`，打开时才发 `judge_budget_seconds`），不取人物要点（`participants: []`）、人物摘要（`people_limit: 0`）、近期原始消息（`recent_limit: 0`）与目标（`goal_limit: 0`）；`memory_limit` 与 `token_budget` 按配置。返回的 `persona` 分区用来更新人设（见下文[人设](#人设)）；入口画像（`entry_profile`）与人物摘要（`people`）是不可信背景，P2 不进上下文。
- 过滤（召回结果进入上下文前）：
  - 只用直播间入口内的：每条来源的入口都是本入口才用；来源入口在令牌范围外（为 null）或没有来源的不用；
  - 提到有墓碑的观众的不用（见下文[删除](#删除)）；
  - 命中隐私规则或注入检测的不用；
  - 正文去掉不可见字符、合并空白，截到 `recall.maxChars`（缺省 120）个字。
- 留下的记忆按顺序编号 `m1`、`m2`…（只在这次召回里有效），连同 Iris 给的类别与立场放进决策模型上下文的不可信数据区（见[决策模型的提示词](director.md#提示词)）。

## 人设

决策插件选用人设的规则见[决策模型的人设](director.md#人设)；这里是记忆插件怎样从 Iris 取来：

- 来源是召回准备的 `persona` 分区，只取正文（`content`）与版本号（`version`，Iris 没给时为 null）；更新提示（`needs_update`、`stale_basis_count`）不取。人设是角色全局的，任一入口返回同一份。
- 什么时候取：激活时取一次（只取人设、不取记忆的召回准备：`text` 为空串，`memory_limit`、`token_budget` 为 0，截止 5 秒）；之后每次召回成功都带回当前版；开播预检时再取一次（`memory@1` 的 `currentPersona`）。
- 缓存：记住最近一次拿到的非空人设（只在进程内，重启后重新取），召回超时或失败时决策插件用这一份（`memory@1` 的 `persona`）。
- 整理：去掉首尾空白，为空视同没有拿到（缓存不变）；超过 `persona.maxChars`（缺省 2000）个字截断，记日志 `memory.persona-truncated`（版本、原字数、上限）。人设变了记 `memory.persona`（版本与字数）；激活时没取到记 `memory.persona-missing` 或 `memory.persona-failed`（类别）。日志都不写正文。
- 取人设用的入口是 `persona.entryId`，缺省为 `entryId`。直播间入口在第一次写入消息之前不存在，Iris 对它返回 404；写入又要等进入真实输出模式，所以新部署时开播预检会报“Iris 没有当前人设（not_found…）”。这时把 `persona.entryId` 指向令牌范围内一个已经存在的入口（人设是全局的，结果相同），直播间入口有了消息之后可以改回。

## 使用反馈

决策模型在说话与发起投票的意图里用 `memories` 字段写出它用到的记忆编号（可为 null；严格 schema 中它与其它字段一样必填、可为 null，见[意图格式](director.md#意图格式)）。只接受这次召回给出的编号，其余忽略并记日志 `director.memory-unknown`（只记个数）；意图本身照常有效。

每次召回恰好回报一次（`POST /feedback`，Iris 给出了记忆才发）：

| 结局 | 回报 |
| --- | --- |
| 说话，观众听到了至少一个字 | 意图里写的、这次召回给出的编号 |
| 说话，观众一个字也没听到（过期、被抢占在第一句之前等） | 空集 |
| 发起投票，开了票 | 意图里写的编号 |
| 发起投票被拒、保持沉默、非法输出、回应对象不在上下文、模型超时或出错、调用被取消 | 空集 |

记忆插件把本地编号换回 Iris 的记忆 ID，只记最近 32 次召回；不认识的召回不回报。回报不等结果，失败只记日志，不重试。

## 写入

- **来源**：
  - 角色的发言：发声仲裁每段发言结束、记下 `utterance.played` 之后分发扩展点 `speech.played`（见[发声的写回](speech.md#播放游标与写回)），只写其中观众实际听到的部分（`heard`），原样写入；没有人听到的不写。
  - 观众的弹幕：订阅弹幕接入（`danmaku@1`）送出的全部弹幕（不经分诊的合并与降权），净化（去不可见字符、NFKC、合并空白）后截到 `write.maxChars`（缺省 200）个字。
- **怎样写**：观众消息作为 `kind: "message"`、带平台稳定 ID（`account_id`，B 站为 `open_id`）写入，显示名是由平台 ID 派生的代号（`观众` 加 8 位十六进制），不写昵称；角色的发言作为 `kind: "self_output"`，显示名为 `selfName`。`occurred_at` 是排队的时刻；首次创建入口时带 `entry_name`、`entry_kind: "live"` 与 `pace`。
- **过滤**：命中注入检测（与分诊同一套规则）的弹幕与命中隐私规则的弹幕或发言不排队，记事实 `memory.filtered`（来源、来源编号与命中的类别，不记内容）。有墓碑的观众的弹幕不排队、也不记。
- **待发队列**：其余记事实 `memory.queued`（类型、来源编号、平台 ID、显示名、内容），进入投影 `memory.ledger` 的待发队列；状态存储重启时从事件重建。队列有界（`write.capacity`，缺省 500）：满了先记 `memory.dropped`（`overflow`）丢弃最旧的，再排新的，每一段队列满只记一次日志 `memory.overflow`。
- **去重键**：由排队的事实确定地派生，存在状态存储里；重试与重启后补发沿用同一个键，Iris 按键返回原消息，不会重复写入。
  - 角色的发言：`bellis:<前缀>:<memory.queued 的序号>`。同一句话说了两次是两段发言，各写一次。
  - 观众的弹幕：`bellis:<前缀>:m:<平台消息编号>`（编号不是 1–200 个可打印 ASCII 时退回用序号）。平台重发同一条弹幕（断线重连、宿主重启之后）得到同一个键，不会写两次；还在队列里的不再排队。
  - 前缀是 16 位随机十六进制，每个状态存储记一次（`memory.epoch`）：换了数据库、序号从头开始，也不会撞上 Iris 里旧的去重键。
- **按批写**：排队后等 `write.flushDelayMs`（缺省 2 秒）攒成一批，一批至多 `write.batchSize`（缺省 50）条，同时只有一批在写。发出之前按当时的隐私规则再过一次（规则可能在排队之后改过），拦下的记 `memory.dropped`（`privacy`）；成功后记 `memory.written`（序号与 Iris 的消息 ID），从队列移除。
- **失败**：
  - 超时、连接失败、5xx、429、503：按退避重试（`write.retryMinMs` 起翻倍，至多 `write.retryMaxMs`，缺省 1 秒到 60 秒；Iris 给了等待就按它），沿用原键；超时不能当作没写成。
  - 鉴权或权限失败：按 `retryMaxMs` 重试，直到操作员换好令牌。
  - Iris 拒收（400、413）：整批原子，二分找出那一条，记 `memory.dropped`（`rejected`，带 HTTP 状态与错误码）丢弃，其余照常写入。
  - 不阻塞直播：写入与重试都在慢速通道上，与决策、发声无关。
- **执行闸门**：外发请求也是意图（见[安全核](safety-core.md#执行闸门)）。每一批作为一个没有时效的意图申请授权：类型与能力 `memory.write`，目标 `iris:<入口>`，载荷是这批消息（闸门只记摘要），来源含不可信输入（弹幕是观众输入，角色的发言也受弹幕影响）。授权后在执行中写入：先标为执行中再发请求，执行中崩溃的意图重启后为结果未知。
  - `memory.write` 不在 Rule of Two 的禁止清单里：写入的本来就是观众内容，只写公开入口；`memory.private` 仍被禁止。
  - 安全停止、维护态中闸门拒绝一切输出：安全停止中不申请授权（不刷拒绝），队列照常积累（有界），模式恢复后补发；维护态与其它拒绝按退避重试。
  - 重启后：记忆插件激活时把上次执行中的写入意图对账为失败（说明“这批仍在待发队列里，以原去重键补发”），不声称已写入；目标上不再有结果未知的意图，写入随即补发。
  - 只有记忆插件（profile 授予 `memory.write`）能申请；Iris 客户端只负责收发，不申请授权。召回与使用反馈是读取与它的附带回报，不经闸门，由 profile 授予外发在启用层面把关。

## 隐私网关

可配置的确定性规则（`privacy.rules`：类别名与正则，整体替换，空数组表示不过滤），写入前与召回进入上下文前各过一次，命中任何一条就整条不写、不用，不做改写或打码。匹配前先规范化：NFKC（全角数字与字母变半角）、去掉不可见字符与全部空白、转小写。缺省规则在 `packages/memory/src/privacy.ts`：

| 类别 | 拦什么 |
| --- | --- |
| `location` | 自报住址、家乡、坐标，“我在……省、市、区、县、镇、村、街、路、小区、学校”等 |
| `health` | 疾病、就医、手术、用药、怀孕、残疾、过敏，以及感冒、发烧等 |
| `family` | 自己的家庭成员与伴侣（“我妈”“我老婆”“我女朋友”等） |
| `contact` | 手机号、邮箱、QQ 与微信号 |
| `identity` | 身份证号、银行卡号等证件与账号、真实姓名、年龄 |

局限（规则只是关键词与格式，不理解语义）：

- 换个说法就漏：不含规则里的词的说法（“我们这边下雪了”“刚从医院回来”）、谐音、拼音、缩写、emoji、拆字与故意插入的符号都拦不住；拆成几条弹幕分别说，每条单看都不命中。
- 也会多拦：游戏剧情、角色扮演、玩笑里的“我妈”“住院”照样拦下；角色自己的发言同样过这道网关。
- 只看文本，P2 不写图片与语音。
- 这道网关不依赖 Iris 的学习规则，也不能代替它：Iris 学到什么、把原文发给谁仍由它自己决定。

## 删除

观众经核验的删除请求由操作员登记本地墓碑：`pnpm operator forget <平台ID>`（B 站为 `open_id`；1–128 个可打印 ASCII，不含空白；操作台暂不提供）。宿主记事实 `memory.tombstoned`，近期告警只说登记了一名观众，不写平台身份，也不写进宿主日志。墓碑记在本地状态存储的记忆账本里，记忆插件在不在场都生效，重启时从事件重建；P2 不能撤销。

- 待发队列里这名观众的条目在登记的同一刻移除；此后他的弹幕不排队；组好批、还没发出的一批在发出之前再核对一次，含他的就不发，重新组批。已经发出的请求撤不回。
- 召回：记忆的说话人、涉及的人或正文里出现这名观众的代号（或平台 ID 本身）就不用。局限：Iris 把几个人的话合成一条、没有归到他名下的记忆，以及角色复述他的话的发言，认不出来。
- 彻底清除：iris-core 宿主接口没有删除，要由运维经 Iris 管理端执行，或等 Iris 提供宿主删除接口；在那之前内容仍在 Iris 里，删除后也可能被重新学回来。

## 就绪与开播预检

- 记忆插件报告就绪（`memory@1` 的 `report`）：Iris 客户端就绪（最近的请求没有处在连续失败中、也没有鉴权失败），且插件在运行；状态说明后面加上写入为什么暂停（安全停止中、多久后重试）。待发队列、累计写入与丢弃的条数、墓碑数来自状态存储的记忆账本。显示在 `pnpm operator status` 与操作台上（见[运维](operations.md#操作台)）。
- 开播预检中的 Iris 一项（含“Iris 没有当前人设”）见[运维的开播预检](operations.md#开播预检)。

## 配置

记忆插件（`memory`）：

| 配置 | 含义 |
| --- | --- |
| `entryId` | Iris 的入口 ID（直播间），建议带连接器名字作前缀，例如 `bellis:bilibili:<房间号>`；宿主令牌的范围按这个前缀授予。空串表示未配置，插件以“未配置入口 ID（entryId）”加载失败 |
| `entryName`、`pace` | 首次创建入口时的名字（缺省“直播间”）与学习节奏（缺省 `standard`） |
| `platform`、`selfName` | 写入的 `platform`（缺省 `bilibili`）；角色发言的显示名（缺省“主播”） |
| `recall` | `judge`（缺省 false）、`judgeBudgetSeconds`（打开判断时才发）、`memoryLimit`（1–8，缺省 5）、`tokenBudget`（缺省 600）、`maxChars`（缺省 120） |
| `write` | `danmaku`、`speech`（是否写入，缺省都写）、`batchSize`、`flushDelayMs`、`capacity`、`retryMinMs`、`retryMaxMs`、`maxChars`，含义见上文[写入](#写入) |
| `skipInjection` | 命中注入检测的弹幕不写、召回的记忆不用，缺省 true |
| `persona` | `entryId`（取人设用的入口，缺省为 `entryId`）、`maxChars`（人设正文的字数上限，缺省 2000），见上文[人设](#人设) |
| `privacy.rules` | 隐私网关的规则，见上文 |

## 遥测

召回一个 span `memory.recall`（client，以决策插件这次模型调用的 span 为父）：是否打开召回判断、结局（`ok`、`timeout`、`aborted`、`error`、`unavailable`）、Iris 给出与留下的条数、各类过滤丢掉的条数；召回耗时记直方图 `bellis.memory.recall.duration`（口径见[运维的直方图](operations.md#直方图)）。每批写入一个 span `memory.write`（client）：条数与结局（`written`、`failed`、`denied`），失败时 `error.type`。只记条数、类别与耗时，不记查询、正文与平台身份。

## 失败与恢复

- Iris 不可用：召回到点不带记忆继续；写入留在队列里按退避重试，队列满了丢弃最旧的。
- Iris 客户端加载失败（外发配置未确认、令牌没录、地址或授权不对）：记忆插件停在 WAITING，`memory@1` 不在场，决策照常进行、不带记忆；这期间的弹幕与发言不排队。
- 宿主崩溃：待发队列、去重键前缀与墓碑都在状态存储里，重启后重建；执行中的写入意图对账后以原去重键补发。`utterance.played` 记下之后、`memory.queued` 记下之前崩溃，这段发言不写入（不会重复）。

## 需要 iris-core 补充的能力

在以下能力具备前，个性化召回和观众私密记忆保持关闭：

- 宿主可调用的按主体删除与撤回，并能阻止被删除内容重新学回；
- 删除与生命周期事件推送；
- 按主体或用途的可见性标签；
- 宿主可设置的“敏感类别不记”策略；
- 强制要求账号身份的选项；
- 消息的信任标记（“声称”与事实分开）；
- 直播场景的评测和规模评估（iris-core 设计文档假设每日不超过 1 万条消息，热门直播的弹幕量可能超出）。
