# 记忆（Iris 客户端与隐私网关）

经隐私网关接入独立的长期记忆服务 Iris（仓库 [iris-core](https://github.com/AirObject/iris-core)）。普通插件，只在慢速通道上工作。P2 实现召回与写入，T1 试播起用于公开直播（D-10）。Iris 以 Docker 部署在本机，由维护者启动，不是宿主的子进程（D-23）。

## 职责

- 在决策前召回与当前话题相关、可以公开说出的记忆。
- 把角色实际说过的话和经过筛选的直播事件异步写入 Iris。
- 在召回前和写入前执行隐私规则。

## 不负责

实时状态（那是[状态存储](state-store.md)）、权限、人设。人设由操作员管理，记忆不能改写它。

## iris-core v1 现状

以下是对 iris-core main 分支提交 7826440（2026-10-14）的核对结果，包括代码、测试与其自述文档；2026-10-19 对照 main 分支提交 cc60a0b（发布版 v0.0.2 之后）的宿主接口契约复核过接口与部署两行。接入设计以此为准，Iris 更新后重新核对：

| 方面 | 现状 | 对 Bellis 的影响 |
| --- | --- | --- |
| 接口 | HTTP + JSON（`/api/v1`，Bearer 令牌），SSE 推送目标提醒；召回准备（`prepare`）可用 `judge=false` 关闭召回判断，判断预算缺省 10 秒、只能调短，没有整体请求时限 | 自写薄客户端（R-19），客户端自己设超时；不用 WebSocket |
| 写入 | 宿主只提交原始消息（`kind` 含 `self_output`），由 Iris 后台学习；必填 `dedupe_key`，同一入口重复提交返回原消息；一次可提交 1–1000 条，整批原子 | 写入是异步的；iris-core README 自述学习批次 P95 约 35–43 秒；去重键由 Bellis 持久保存，重试沿用原键 |
| 可见范围 | 按入口划分三档，没有按主体或用途的访问控制 | 同一直播间入口内的记忆全部共享，只能召回公开事实 |
| 身份 | 按（平台, 账号）区分；缺账号时退回用昵称作键 | Bellis 必须总是传平台稳定 ID（B 站为 `open_id`，见 R-18） |
| 删除 | 宿主接口没有删除；删除后内容可能被重新学回来；不改写备份 | 墓碑在 Bellis 本地维护；私密与个性化功能暂不开放 |
| 外发 | Iris 自己把原文发给它配置的模型 | Iris 的模型配置必须符合 Bellis 的外发与合规要求，开播预检核对 |
| 部署 | 只在 macOS 验证过原生运行；提供 Docker 镜像。普通模式只监听回环地址，容器模式（`IRIS_CONTAINER=1`）才允许非回环监听，不提供 TLS；Host 缺省只接受 `127.0.0.1`、`localhost`、`[::1]` | 以 Docker 部署在本机，端口只映射到 127.0.0.1，令牌不出本机（D-23）；容器内运行与召回延迟由探针 S-09 验证 |
| 许可 | iris-core 与其 TS 客户端均为 AGPL-3.0 | 按 HTTP 契约自写客户端（R-19） |

## 召回

- 只在慢速通道调用，带硬超时（初值约 2 秒）；超时就不带记忆继续决策。
- 关闭召回判断（`judge=false`）或把它的预算压到很短，避免默认的长等待。
- 使用了召回的哪些记忆，决策后经使用反馈接口回报；没有用到就回报空集，不把召回结果一律当作已用。
- 收发与解读分开（见[插件内核](plugin-kernel.md#权限)）：Iris 客户端插件只负责收发，持有宿主令牌（`secret:iris`），值不写日志、不进事件；隐私网关、墓碑与召回过滤在记忆插件里，它不持有凭据。
- 只取直播间入口内的公开事实；Iris 生成的人物画像、入口画像等分区只当作不可信背景，不能覆盖人设。
- 召回结果进入决策模型上下文前，再按隐私规则过滤一次。

## 写入

- 角色发言只写入观众实际听到的部分（按播放游标截取）。
- 观众消息作为“观众声称”写入，标为不可信；重复或多人附和不能使它变成事实。
- 每条写入都带平台稳定 ID 和幂等键；写入失败进入有界的待发队列，队列满时丢弃最旧的并记录，不阻塞直播。
- 个人敏感信息（所在地、健康、家人等）在提交前由隐私网关过滤，不依赖 Iris 的学习规则。

## 删除

观众经核验的删除请求先在 Bellis 本地登记墓碑：立即阻止相关召回和待发写入。由于 iris-core 宿主接口没有删除，彻底清除需要运维经 Iris 管理接口执行，或等 Iris 提供宿主删除接口。

## 需要 iris-core 补充的能力

在以下能力具备前，个性化召回和观众私密记忆保持关闭：

- 宿主可调用的按主体删除与撤回，并能阻止被删除内容重新学回；
- 删除与生命周期事件推送；
- 按主体或用途的可见性标签；
- 宿主可设置的“敏感类别不记”策略；
- 强制要求账号身份的选项；
- 直播场景的评测和规模评估（iris-core 设计文档假设每日不超过 1 万条消息，热门直播的弹幕量可能超出）。
