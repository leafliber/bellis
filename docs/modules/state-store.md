# 状态存储

安全核的一部分。用单个 SQLite（WAL）文件记录发生过的事实、当前状态和待执行的副作用，保证重启后状态可以重建、副作用永不重做（D-17）。P0 实现。

## 职责

- 保存只追加的事件、由事件派生的投影、副作用意图及其结果。
- 为副作用提供幂等：同一幂等键只执行一次。
- 重启时从事件重建状态，并找出结果未知的意图。

## 不负责

- 音频、画面等大块数据。音频不入库，只记文本、哈希和播放游标。
- 长期记忆。那是 Iris 的职责，见[记忆](memory.md)。
- 跨进程或跨机器的事务。SQLite 只保证本机内的一致性，外部效果靠回执与对账确认。

## 表

| 表 | 内容 | 规则 |
| --- | --- | --- |
| 事件 | 已发生的事实，`对象.过去式` 命名，带来源、发生时间、接收时间 | 只追加，从不修改或删除 |
| 投影 | 由事件归约出的当前状态（发言队列、投票、监督模式、许可等） | 与产生它的事件在同一事务中更新 |
| 意图 | 待执行的副作用（字段见[安全核](safety-core.md#执行闸门)）及其状态：待执行 / 执行中 / 成功 / 失败 / `unknown` | 先写意图再执行，执行后写结果 |
| 许可令牌 | 每个资源的执行许可令牌计数器 | 只增不减，重启后不回退 |

## 副作用流程

```text
写入意图（同事务记录授权事件）→ 执行 → 写入结果事件并更新意图状态
```

- 执行器按幂等键去重，重复提交只返回已有结果。
- 结果未知（例如进程在执行中崩溃）的意图标为 `unknown`，并隔离相关资源，直到对账或人工结案。

## 重启

1. 打开数据库，按事件重建投影；回放期间副作用处理器全部为空操作。
2. 所有执行许可作废，监督模式回到安全停止（见[安全核](safety-core.md)）。
3. 处理停在“执行中”的意图：
   - 说话、游戏输入这类有时效的动作：永不重做，标为 `unknown`。
   - 投票、平台消息这类可以对账的动作：先查询外部状态，再补记结果。
4. 操作员确认后才恢复真实输出。

## 失败

- 写入失败时，新的副作用一律拒绝；急停和拒绝不依赖写入成功。
- 磁盘满、文件损坏等情况，宿主转入安全状态并告警。

## 验收（P0）

- 在每个写入点模拟崩溃，重启后：状态与崩溃前已提交的事件一致；没有副作用被重做；停在执行中的意图被正确标为 `unknown`。
- 同一幂等键重复提交只执行一次。
- Windows 文件系统上的崩溃窗口另由探针 S-06 验证。
