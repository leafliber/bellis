# 状态存储

安全核的一部分。用单个 SQLite（WAL）文件记录发生过的事实、当前状态和待执行的副作用，保证重启后状态可以重建、副作用永不重做（D-17）。P0 实现。

## 职责

- 保存只追加的事件、由事件派生的投影、副作用意图及其结果。
- 为副作用提供幂等：同一幂等键只执行一次。
- 重启时从事件重建状态，并找出结果未知的意图。

## 不负责

- 音频、画面等大块数据。音频不入库，只记文本、哈希和播放游标。
- 长期记忆。那是 Iris 的职责，见[记忆](memory.md)。
- 跨进程或跨机器的事务。SQLite 只保证本机内的一致性，外部效果靠回执与对账确认。

## 表

| 表 | 内容 | 规则 |
| --- | --- | --- |
| 事件 | 已发生的事实，`对象.过去式` 命名，带来源、发生时间、接收时间 | 只追加，从不修改或删除（数据库触发器兜底） |
| 投影 | 由事件归约出的当前状态（发言队列、投票、监督模式、许可等） | 与产生它的事件在同一事务中更新；宿主打开存储时注册，插件经安全核的门面只读 |
| 意图 | 待执行的副作用（字段见[安全核](safety-core.md#执行闸门)）及其状态：待执行 / 执行中 / 成功 / 失败 / `unknown` | 先写意图再执行，执行后写结果 |
| 许可令牌 | 每个资源的执行许可令牌计数器 | 只增不减，重启后不回退（数据库触发器兜底） |

## 副作用流程

```text
写入意图（同事务记录授权事件）→ 执行 → 写入结果事件并更新意图状态
```

- 执行器按幂等键去重，重复提交只返回已有结果；同一幂等键但任何授权字段不同都视为篡改，拒绝。
- 执行前核对载荷与授权时记录的摘要一致，副作用只使用核对过的载荷。
- 意图状态只能按“待执行 → 执行中 → 成功 / 失败”或“执行中 → `unknown` → 成功 / 失败”变化。
- 结果未知（例如进程在执行中崩溃）的意图标为 `unknown`，并隔离其目标，直到结案；隔离与结案见[安全核](safety-core.md#隔离与结案)。

## 重启

1. 打开数据库，按事件重建投影；回放期间副作用处理器全部为空操作。
2. 所有执行许可作废，监督模式回到安全停止（见[安全核](safety-core.md)）。
3. 停在“待执行”的意图从未开始执行，标为失败（放弃），不再执行。
4. 停在“执行中”的意图一律永不重做，先都标为 `unknown`（事实 `intent.orphaned`），再按类别处理：
   - Stage 的发言（类型 `speech.play`、目标 `stage`、所需能力恰好是 `speech.output`、有时效）：在同一次恢复里当场结案为失败，结局“重启中断：播出多少不可知，不重做”，记事实 `intent.interrupted`（原意图的编号、键与目标），`stage` 目标随之不再隔离。Stage 每次启动都重新认证，旧令牌的音频作废，发言意图本来就永不重做，所以重启后这个目标的状态是确定的。
   - 被打断的那段发言不写回：崩溃时它还没记 `utterance.played`，状态存储只存载荷摘要、没有字幕可写；正在播的那一句没有游标依据，按[发声](speech.md#播放游标与写回)“没有映射时退化为整句粒度”的规则也不算已播出。写回只会少算，不会多算。
   - 其余有时效的动作（例如游戏输入）：停在 `unknown`，只能由操作员结案。
   - 投票、平台消息这类可以对账的动作：停在 `unknown`，由其所有者查询外部状态后补记结果。所有者是持有该意图全部所需能力的插件实例，经安全核的门面列出并补记，只能补记没有时效的意图。投票的对账见[投票](audience.md#投票)。
5. 还有结果未知的意图时开播预检不通过；所有者不在场、对不了账的，由操作员核对外部状态后结案（见[安全核](safety-core.md#隔离与结案)）。操作员确认后才恢复真实输出。

## 失败

- 写入失败时，新的副作用一律拒绝；急停和拒绝不依赖写入成功。
- 磁盘满、文件损坏等情况，宿主转入安全状态并告警。

## 验收（P0）

- 在每个写入点模拟崩溃，重启后：状态与崩溃前已提交的事件一致；没有副作用被重做；停在执行中的意图被正确标为 `unknown`。
- 同一幂等键重复提交只执行一次。
- Windows 文件系统上的崩溃窗口另由探针 S-06 验证。
