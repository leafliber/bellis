# 观众接入与投票

接入直播平台的弹幕、礼物等事件，分诊成候选，并运行投票。普通插件。P0 用录制弹幕回放，P2 接真实 B 站直播开放平台。

## 职责

- **接入**：从平台接收弹幕、礼物、进入等事件，转为带来源与时间的事实。
- **分诊**：去重、合并同质内容、过滤刷屏、做提示注入检测、净化称呼，产出候选交给决策模型。
- **投票**：按冻结的规则计票，给出结果。

## 不负责

决定回应谁（[决策模型](director.md)）、播报（[发声](speech.md)）。

## 接入

- 首个平台是 B 站直播开放平台（R-18），见下一节。
- 平台消息里的昵称、头像、留言全部视为不可信输入，只作数据处理。
- 弹幕进入分诊；礼物、SC、大航海、点赞只记为事实，不触发回应（致谢在 T1 前再定）。
- 断线时记录缺口，重连后不把缺口伪装成“没有弹幕”。

### B 站直播开放平台

`danmaku-bilibili` 插件提供 `danmaku@1`。协议细节以[参考资料](../references.md#直播平台)中的官方文档为准；文档没写明或与官方示例矛盾之处参照社区实现，列在本节末尾的 PENDING 中，真机核对后改正。

- **身份**：观众的稳定身份是 `open_id`。它在同一个应用内稳定、跨直播间相同，换了应用就会变；`uid` 已废弃、恒为 0。
- **收发与授权**：接入插件只负责收发，收到的内容只当数据转交（分诊在 `audience-triage` 里，不持凭据，见[插件内核](plugin-kernel.md#权限)）。它持有 `secret:bilibili`（JSON `{"accessKeyId": "…", "accessKeySecret": "…"}`）与 `secret:bilibili-code`（主播身份码），外发申请 `net.egress:live-open.biliapi.com` 与 `net.egress:*.chat.bilibili.com`。项目 ID（`appId`）与接口基址在插件配置里。凭据缺失、`appId` 未配置或接口基址不是 `https://`、未授予时，插件加载失败并说明原因，不连接任何端点。
- **签名**：HTTP 接口一律 POST JSON，HTTP 状态恒为 200，返回体的 `code` 为 0 才算成功。六个 `x-bili-*` 头（访问密钥 ID、请求体的 MD5、`HMAC-SHA256`、每次唯一的 nonce、`1.0`、时间戳）按键名字典序拼成 `键:值`、以换行连接，用 access_key_secret 做 HMAC-SHA256，小写十六进制放进 `Authorization`。时间戳与服务器相差不能超过 10 分钟。
- **场次**：激活后在后台用身份码开启（`/v2/app/start`），拿到场次编号、长连接的认证正文 `auth_body` 与长连接地址；每 20 秒一次项目心跳（`/v2/app/heartbeat`；互动玩法 60 秒、直播工具 180 秒收不到就关闭场次）；停用（含 QUIESCING）时停心跳、关长连接、关闭场次（`/v2/app/end`），都带截止时间，失败只记日志。开启失败按错误码等待：7001（上一局结算中）约 10 秒，7002（已有场次或上一场没有正常结束）与 7010（连接数超限）一分钟以上，4007（IP 白名单）、4009（访问受限）、5004 与 5011（未上架的应用只能连开发者自己的直播间，开发者账号就是主播账号）这类鉴权与配置问题等得更久，原因写进日志；其余按指数退避（有上限）。
- **长连接**：包头 16 字节大端（包长、包头长、版本、操作、序号）。连上后先发认证包（操作 7，正文原样放 `auth_body`），收到认证回复（操作 8）之前不发别的包；之后每 20 秒发心跳（操作 2），一段时间收不到任何包（含心跳回复）就视为断开。消息（操作 5）可能是 zlib（版本 2）或 brotli（版本 3）压缩的一串包，解压后递归拆开。返回的地址逐个核对外发授权，未授予的或不是 `wss://` 的跳过并写日志，全部跳过就不连；其余依次轮换，一个连不上就换下一个，断开后按指数退避重连。
- **失效与重开**：项目心跳返回 7003 或连续失败、收到 `LIVE_OPEN_PLATFORM_INTERACTION_END`（带着别的场次编号时不理）、长连接认证被拒、地址连续连不上、场次开满 6 天（平台说长连接超过 7 天可能收不到消息）时，连接可能还在但收不到消息：关闭旧场次（能关就关）后重新开启。
- **无场次编号**：开启返回的 `game_id` 为空串时（社区实现所见，推测是不分场次的直播工具类项目），不发项目心跳、不关闭场次，只靠长连接维持，日志标 `noGameId`；场次开满 6 天照旧例行重开，`INTERACTION_END` 分不出是不是自己的，一律重开。PENDING，以真机为准。
- **弹幕**：按平台消息编号 `msg_id` 去重（重连后平台可能重发，只记得最近一批），写成事实后以 `Danmaku`（编号、`open_id`、昵称、正文）交给 `danmaku@1` 的订阅者（分诊与投票）；缺 `msg_id` 或 `open_id` 的丢弃并写日志。表情包弹幕（`dm_type` 为 1）只写事实、标 `delivered: false`，不交出：分诊与投票的输入是观众打出的文字，表情包弹幕的正文是表情的名称。
- **其它消息**：礼物、SC、SC 删除、大航海、点赞、开播、下播只写事实；进入房间只计数，不存观众身份；未知命令只写一次日志。SC 留言、点赞文案、头像、粉丝勋章都不存。
- **缺口**：从失去接收（长连接断开或连不上、认证被拒、项目心跳失败、场次失效、开启失败及其等待）到长连接重新认证成功之间是缺口，开始与结束各写一条事实，同时经 `danmaku@1` 告诉订阅者（此刻的缺口与开始、结束的通知，投票据此记下重叠的缺口）；从没连上过时，缺口从开始接入时算起。停用时仍开着的缺口以 `recovered: false` 结束；正常接收时停用不算缺口。
- **事实**：都带 `platform: "bilibili"`；消息类的还带 `msgId`（平台消息编号）、`platformTimestamp`（平台给的秒级时间戳）与 `receivedAt`（本机收到时的墙钟毫秒）。

  | 事实 | 来自 | 其它字段 |
  | --- | --- | --- |
  | `danmaku.received` | 弹幕 | `openId`、`nickname`、`text`（昵称与正文都是不可信数据）、`dmType`、`delivered` |
  | `gift.received` | 礼物 | `openId`、`giftId`、`giftName`、`count`、`unitPrice`（实际单价，1000 = 1 元）、`paid` |
  | `superchat.received` | SC | `openId`、`superChatId`、`rmb`（元） |
  | `superchat.deleted` | SC 删除 | `superChatIds` |
  | `guard.bought` | 大航海 | `openId`、`guardLevel`、`count`、`unit`、`price`（金瓜子，1000 = 1 元） |
  | `like.received` | 点赞 | `openId`、`count` |
  | `live.started`、`live.ended` | 开播、下播 | `roomId` |
  | `danmaku.gap-started` | 缺口开始 | `reason`、`startedAt` |
  | `danmaku.gap-ended` | 缺口结束 | `reason`（开始时的原因）、`startedAt`、`endedAt`、`durationMs`、`recovered` |

- **日志**：只写场次编号、主机、计数、状态与原因，不写弹幕正文、昵称、头像、`auth_body`、签名、身份码与密钥；场次（开启、失败、失效、关闭）与长连接（连接中、连上、断开、失败、跳过的主机）各自的状态都可从日志看清，停用时写一次各类消息的计数。计时都经宿主的时钟服务。
- **PENDING**：签名时间戳的单位按文档用秒（官方 JS 示例用毫秒）；认证回复的 `code` 为 0 表示成功（只有社区实现的出处）；客户端发出的包写版本 1（与社区实现一致，官方文档只说明了 0 与 2）；brotli（版本 3）压缩（官方文档未写，社区实现有处理）；长连接地址的主机都在 `chat.bilibili.com` 之下；`INTERACTION_END` 的数据里带场次编号 `game_id`；表情包弹幕的正文是表情的名称。

## 分诊

- 合并同一观众的连续消息和多名观众的同质内容，记录合并数量。
- 提示注入检测命中的弹幕降权或丢弃，不触发停止，也不升级为全场事件。
- 生成净化后的称呼：去掉控制字符和可能被朗读成违规内容的部分；无法净化时用中性称呼。
- 候选有容量和年龄上限，过期丢弃；普通弹幕从不抢占正在进行的发言或游戏工作。

## 投票

`audience-vote` 插件提供 `vote@1`。它解读观众输入，不授予任何凭据（见[插件内核](plugin-kernel.md#权限)）；订阅原始弹幕 `danmaku@1`，不经分诊的合并与降权，正文只当数据与选项比较，不解析成指令。画面上的[公开展示层](stage.md#公开展示层)在 T1 前再做，P2 只口播。

- **发起**：由决策模型发起（见[动作选择](director.md#输出动作选择)），决策插件经 `vote@1` 交给投票插件，成功、被拒都写日志。同时最多一个投票：已有投票（含正在授权的）时新的发起被拒；参数不合法、同一次发起重复提交也被拒，都记 `vote.rejected` 与原因。
- **授权**：发起投票是副作用，经执行闸门授权：意图类型与所需能力都是 `vote.start`（profile 授予投票插件），目标 `vote`，来源总标为含不可信输入（票来自弹幕）；`vote.start` 不在 Rule of Two 的禁止清单里。幂等键 `vote:<投票编号>`，投票编号就是发起方给的编号，同一次发起不会开两次票，含跨重启。意图没有时效，重启后由投票插件对账。闸门拒绝时不开票。
- **规则**：授权之前冻结，原样写进 `vote.started`，之后不再改变。
  - 题目与选项去掉不可见字符、合并空白。
  - 计票方式（`number-or-text`）：弹幕正文规范化（NFKC、去掉不可见字符、空白、标点、符号与组合附加符号，不分大小写）后恰好是选项编号（从 1 起），或与某个选项的文本规范化后相同，才算一票；“1号”“我选 1”都不算。选项规范化后为空、或投法互相冲突（两个选项相同，或选项文本是别的选项的编号）时不开票。
  - 每人一票（`first`）：每个观众（平台的稳定身份，B 站是 `open_id`）只计第一张有效票，之后再投不改票。
  - 平票（`no-winner`）：票数最多的选项不止一个时不判胜者，结果为平票；没有有效票时结果为“无有效票”。
  - 时长：开票说明完整播出后才开始倒计时。
- **计票时段**：从开票（`vote.started`）到截止之前本系统收到的弹幕，截止时刻 = `vote.announced` 的记录时刻 + 时长；截止那一刻及之后到达的不算。不匹配的、改投的、截止时到达的分别计数，写进结果。
- **缺口**：接入插件经 `danmaku@1` 报告缺口的开始与结束；与投票时段（开票到截止）重叠的缺口次数、总时长与原因写进结果，平台缺口单独记录，结果不声称是平台全量。
- **开票说明**：固定模板“投票开始！〈题目〉？1是「〈选项〉」，……。发弹幕打编号或者选项就算一票，每人只算第一票，〈时长〉秒后截止。”，时长与票数用中文读法。题目与选项来自模型（受不可信输入影响），照常经发声前检查与仲裁。来源用“弹幕回复”：它是请观众参与的互动发言，与回应观众同级、排在闲聊之前；不用“投票结果”或更高的来源，免得模型借发起投票抬高自己文本的优先级（D-33）。它不抢占别的发言，只能排队，`openingTtlMs`（缺省 20 秒）内没开始播就过期。
  - 完整播出（结束方式为完整、没有句子被跳过）后记 `vote.announced`，开始倒计时：“几秒后截止”从观众听完时算起。
  - 没有完整播出（过期、被拒、被停止、被抢占、有句子被审核或操作员拦下）时投票中止。
- **结果**：截止时按冻结的规则判定，先记 `vote.ended`，再以“投票结果”来源播报：胜出、平票、无有效票各一个固定模板，有重叠的缺口时加一句中断了多久、结果只算收到的票。可在句边界抢占，`resultTtlMs`（缺省 30 秒）内没开始播就过期。
- **只播一次**：开票说明与结果播报的去重键分别是 `vote:<投票编号>:opening` 与 `vote:<投票编号>:result`，每个投票各只请求一次；重启后不再请求。
- **中止**：中止的投票不出结果、不播报，记 `vote.aborted` 与原因类别 `cause`：开票说明没有完整播出（`opening`）、急停或进入安全停止（`stopped`）、投票插件停用或它依赖的服务消失（`unloaded`）、重启（`restart`）。
- **重启**：投票结果是可对账的副作用，重启后先查状态再补记。投票插件激活时读投票账本（状态存储的投影，由投票的事实归约，重启时从事件重建）：
  1. 结果未知的开票意图（重启时停在执行中）按账本对账：已记下 `vote.started` 的补记为成功，没有的补记为失败，目标不再隔离；
  2. 账本上没有结束的投票记为中止（`restart`）：倒计时被重启打断、停机期间的弹幕收不到，按冻结的时长出不了结果；重启后先回到安全停止，也没法及时播报；
  3. 已经结束的投票不补记、不补播（结果在重启前没播完的也不再播）。之后照常可以开新的投票，同一次发起不会再开。
- **事实**：票不逐张写事实：B 站的每条弹幕已有 `danmaku.received`，中止的投票不重算，结束的投票的计数在 `vote.ended` 里。

  | 事实 | 字段 |
  | --- | --- |
  | `vote.started` | `voteId`、`question`、`options`、`durationMs`、`decisionPoint`（没有时为 null）、`ballot`、`perViewer`、`tie` |
  | `vote.announced` | `voteId`、`durationMs` |
  | `vote.ended` | `voteId`、`decisionPoint`、`counts`（按选项顺序）、`valid`、`ignored`（`unmatched`、`repeat`、`late`）、`outcome`（`winner`、`tie`、`none`）、`winners`（选项编号）、`gaps`（`count`、`durationMs`、`reasons`） |
  | `vote.aborted` | `voteId`、`decisionPoint`、`cause`、`reason` |
  | `vote.rejected` | `voteId`、`reason` |

- **游戏决策点**：投票只用于没有计时的决策点（D-07）：绑定决策点编号，时长由决策模型设定并在开始时冻结，Game Runtime 在该决策点等待结果。有计时的决策点不开投票，由决策模型自选。P2 只把决策点编号原样带上、记进事实，与 Game Runtime 的对接在 P3。
