# 运维：操作台、观测与评测

操作员如何监督直播，系统如何被观测、测试和评估。操作台与遥测是普通插件；确定性仿真贯穿各阶段。

## 操作台

推荐为本机页面，独立来源，需登录认证（R-20）。P0 先提供命令行 `pnpm operator`（查看状态、切换模式、确认在场、急停；P1 加上 M1 中的否决与只跑开播预检），以 `operator` 角色经本机通道连接宿主。操作台提供：

- 开播、下播、进入或退出维护态。
- 切换监督模式。升级只能在这里显式执行；降级也可由安全核自动触发。
- 急停。操作台不是唯一的急停入口：另有物理热键与外部看门狗。
- 在场确认（M2 的前提）。
- M1 模式下逐句放行或否决。
- 查看插件状态与 WAITING 原因、结果未知的意图、近期降级与告警。

## 开播预检

开播前逐项确认，任一失败则不允许进入真实输出。操作员切到 M1–M3 时，先由安全核核对模式本身的前置条件（见[安全核](safety-core.md#监督模式)），满足后宿主再跑以下各项，未通过的项随拒绝一起返回并记入事件；`pnpm operator preflight` 只跑预检、不切换。

- 监督模式有效，M2 下在场确认未过期；
- 安全场景、Stage 静音目标存在，看门狗连接正常；Stage 浏览器源的设置符合 [Stage](stage.md#obs-配置要求) 的要求，安全场景里不含 Stage 源（经 OBS 应急连接只读核对）；
- Stage 已认证，AI 标识可见；
- 审核插件的状态已确认（启用且审核模型可用，或已显式关闭）；
- TTS、形象、弹幕接入、Iris、Game Runtime 按 profile 就绪（profile 中启用的插件全部激活）；TTS 路由配置中第一个音频引擎（只出字幕不算）就绪，例如本地模型已加载完成；形象还要求已连上 VTube Studio 并认证、嘴型参数没有被其他插件占用；M1 还要求逐句放行环节在场；
- 合规清单中试播门禁项已满足（见[合规](../compliance.md)）。

## 观测

- **事件日志是事实来源**，遥测是可以丢失的派生数据。
- 链路追踪覆盖：弹幕接入 → 分诊 → 决策 → 审核（启用时，逐句）→ TTS → 播出；跨进程调用在 JSON-RPC 参数中携带 `traceparent`。
- 推荐采用 OpenTelemetry 的 GenAI 语义约定并锁定版本，自定义属性用 `bellis.*` 前缀；内容采集默认关闭（R-21）。
- 关键直方图：弹幕到首音、逐句审核耗时、TTS 首包、停止到静音、许可续约滞后、事件循环延迟、游戏首动作时间。

## 确定性仿真

- 自研（R-07）：时钟、随机数、传输、模型、TTS、弹幕源都是插件服务；`sim` profile 把它们整体换成由种子驱动的模拟实现；用 fast-check 生成与收缩失败轨迹。
- 整个世界（状态存储、安全核、插件内核与全部插件）在一个进程里由同一个手动时钟驱动；同时到期的定时器按种子决定先后，以覆盖不同的交错。
- 场景由 fast-check 生成：录制弹幕（含提示注入、控制字符、禁词）、模型输出（含非法输出）、定时播报、审核开关与出错、审核耗时、慢 TTS 与 TTS 中途出错，以及操作员的急停、升级与崩溃重启。
- 不变量：
  - 每一步：每个资源的执行许可至多一个持有者；许可令牌不回退。
  - 追踪上：审核插件启用时被判不可说的句子从未在 Stage 上开始；安全停止期间 Stage 没有播出任何采样；写回恰好是 Stage 回报已播出的部分（由页面回报的采样数独立推出）；同一句与同一意图从未执行两次（含跨重启）。
  - 结束时：排空后没有卡住的意图与插件。
  - 同一场景与种子两次运行得到完全相同的追踪与事件。
- 每次提交在固定种子集上运行；收缩出的失败场景加入回归用例。
- `pnpm sim [--seed N] [--runs N]` 做更大规模的探索；失败时打印收缩后的场景，并给出“种子 + 路径”的复现命令，配合提交即可复现。

## 评测

- 把真实直播中的弹幕会话导出为回放样本，在 `sim` profile 下做回归。
- 中文红队语料（谐音、拼音、emoji、分步诱导、昵称注入）用来评估审核插件；进入无人值守前须达标。
- 对话质量用模型评审辅助，并用人工抽样校准，注意评审标准会漂移。
- 实测指标报告样本数与 p50/p95/p99，失败样本不剔除。
