# 运维：操作台、观测与评测

操作员如何监督直播，系统如何被观测、测试和评估。操作台与遥测是普通插件；确定性仿真贯穿各阶段。

## 操作台

推荐为本机页面，独立来源，需登录认证（R-20）。提供：

- 开播、下播、进入或退出维护态。
- 切换监督模式。升级只能在这里显式执行；降级也可由安全核自动触发。
- 急停。操作台不是唯一的急停入口：另有物理热键与外部看门狗。
- 在场确认（M2 的前提）。
- M1 模式下逐句放行或否决。
- 查看插件状态与 WAITING 原因、结果未知的意图、近期降级与告警。

## 开播预检

开播前逐项确认，任一失败则不允许进入真实输出：

- 监督模式有效，M2 下在场确认未过期；
- 安全场景、Stage 静音目标存在，看门狗连接正常；
- Stage 已认证，AI 标识可见；
- 审核链路（L0/L1）可用；
- TTS、形象、弹幕接入、Iris、Game Runtime 按 profile 就绪；
- 合规清单中试播门禁项已满足（见[合规](../compliance.md)）。

## 观测

- **事件日志是事实来源**，遥测是可以丢失的派生数据。
- 链路追踪覆盖：弹幕接入 → 分诊 → 决策 → 审核（逐句）→ TTS → 播出；跨进程调用在 JSON-RPC 参数中携带 `traceparent`。
- 推荐采用 OpenTelemetry 的 GenAI 语义约定并锁定版本，自定义属性用 `bellis.*` 前缀；内容采集默认关闭（R-21）。
- 关键直方图：弹幕到首音、逐句审核耗时、TTS 首包、停止到静音、许可续约滞后、事件循环延迟、游戏首动作时间。

## 确定性仿真

- 推荐自研（R-07）：时钟、随机数、传输、模型、TTS、弹幕源都是插件服务；`sim` profile 把它们整体换成由种子驱动的模拟实现。
- 每一步检查不变量，例如：Stage 音频输出许可至多一个持有者；进入 TTS 的句子都带审核凭证；急停后无新输出；重启不重做副作用。
- 失败用“种子 + 提交”复现。

## 评测

- 把真实直播中的弹幕会话导出为回放样本，在 `sim` profile 下做回归。
- 中文红队语料（谐音、拼音、emoji、分步诱导、昵称注入）作为合并门禁。
- 对话质量用模型评审辅助，并用人工抽样校准，注意评审标准会漂移。
- 实测指标报告样本数与 p50/p95/p99，失败样本不剔除。
