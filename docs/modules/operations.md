# 运维：操作台、观测与评测

操作员如何监督直播，系统如何被观测、测试和评估。操作台与遥测是普通插件；确定性仿真贯穿各阶段。

## 操作台

命令行 `pnpm operator`（查看状态、切换模式、确认在场、急停、M1 中的否决、只跑开播预检）以 `operator` 角色经本机通道连接宿主，一直保留。P2 起另有本机网页（R-20）：

- 宿主在 127.0.0.1 上另开一个随机端口提供页面，与 Stage 不同源；页面写法与 Stage 相同（带 JSDoc 的 JS，`checkJs` 检查，不用前端框架）。
- 登录：`pnpm operator console` 经本机通道向宿主要一个一次性令牌，用浏览器打开带令牌的地址，令牌放在 URL 片段里，不随请求发出、不进 Referer。页面用它换取 HttpOnly、SameSite=Strict 的会话 cookie，随即从地址栏抹掉片段；令牌只能用一次，过期作废。
- 每个请求与 WebSocket 升级都严格核对 Host 与 Origin（含端口）。cookie 不按端口隔离，同一台机器上其它端口的页面算同站，所以写请求另带自定义请求头里的 CSRF 令牌。
- 页面在线不算在场：在场确认仍要操作员主动点。

操作台提供：

- 开播、下播、进入或退出维护态。
- 切换监督模式。升级只能在这里显式执行；降级也可由安全核自动触发。
- 急停。操作台不是唯一的急停入口：另有 OBS 热键（R-27，见[安全核](safety-core.md#执行许可与急停)）与外部看门狗。
- 在场确认（M2 的前提）。
- M1 模式下逐句放行或否决。
- 查看插件状态与 WAITING 原因、结果未知的意图、近期降级与告警。

## 开播预检

开播前逐项确认，任一失败则不允许进入真实输出。操作员切到 M1–M3 时，先由安全核核对模式本身的前置条件（见[安全核](safety-core.md#监督模式)），满足后宿主再跑以下各项，未通过的项随拒绝一起返回并记入事件。`pnpm operator preflight` 只跑预检、不切换：先由安全核核对目标模式的前置条件（已处于该模式不算未满足），未满足就把原因列为第一项，再跑以下各项。

- 监督模式有效，M2 下在场确认未过期；
- 安全场景、Stage 静音目标存在，看门狗连接正常；Stage 浏览器源的设置符合 [Stage](stage.md#obs-配置要求) 的要求，安全场景里不含 Stage 源；Stage 源没有被静音，节目场景不是安全场景（以上经 OBS 应急连接只读核对）。急停之后由操作员先取消静音、切回直播场景，再进入输出模式，Bellis 不自动切回；
- Stage 已认证，AI 标识可见；
- 审核插件的状态已确认（启用且审核模型可用，或已显式关闭）；
- TTS、形象、弹幕接入、决策模型、Iris、Game Runtime 按 profile 就绪（profile 中启用的插件全部激活）；弹幕接入已开启场次、长连接已认证；Iris 能以宿主令牌访问且外发配置已核对；TTS 路由配置中第一个音频引擎（只出字幕不算）就绪，例如本地模型已加载完成；本地 TTS 作主引擎时，它的 sidecar 读回为 HighQoS（见 [Windows 平台](../platform/windows.md#定时与调度)）；形象还要求已连上 VTube Studio 并认证、嘴型参数没有被其他插件占用；M1 还要求逐句放行环节在场；
- 合规清单中试播门禁项已满足（见[合规](../compliance.md)）。

## 观测

- **事件日志是事实来源**，遥测是可以丢失的派生数据。
- 链路追踪覆盖：弹幕接入 → 分诊 → 决策 → 审核（启用时，逐句）→ TTS → 播出；跨进程调用在 JSON-RPC 参数中携带 `traceparent`。
- 按 R-21 自写最小实现：宿主生成 W3C `traceparent` 并沿链路透传；span 与直方图写入单独的 JSONL 文件，不进事件库，写不进时直接丢弃，不阻塞直播；字段按 OTLP 的结构命名，GenAI 属性按锁定到某一提交的语义约定，自定义属性用 `bellis.*` 前缀；模型与观众的内容默认不采集。需要可视化时，由进程外的 OTel Collector 导入。
- 关键直方图：弹幕到首音、逐句审核耗时、TTS 首包、停止到静音、许可续约滞后、事件循环延迟、游戏首动作时间。

## 确定性仿真

- 自研（R-07）：时钟、随机数、传输、模型、TTS、弹幕源都是插件服务；`sim` profile 把它们整体换成由种子驱动的模拟实现；用 fast-check 生成与收缩失败轨迹。
- 整个世界（状态存储、安全核、插件内核与全部插件）在一个进程里由同一个手动时钟驱动；同时到期的定时器按种子决定先后，以覆盖不同的交错。
- 场景由 fast-check 生成：录制弹幕（含提示注入、控制字符、禁词）、模型输出（含非法输出）、定时播报、审核开关与出错、审核耗时、慢 TTS 与 TTS 中途出错、0–300ms 的呈现延迟（仿真里没有 OBS 音量表，stage-sync 一直用初值），以及操作员的急停、升级与崩溃重启。
- 不变量：
  - 每一步：每个资源的执行许可至多一个持有者；许可令牌不回退。
  - 追踪上：审核插件启用时被判不可说的句子从未在 Stage 上开始；安全停止期间 Stage 没有播出任何采样；写回恰好是 Stage 回报已播出的部分（由页面回报的采样数独立推出，急停且应急动作成功时扣掉呈现延迟，见[发声](speech.md#播放游标与写回)）；页面显示的字幕不早于游标，页面回报一句截断时它的字幕已清除，播完时至迟在呈现延迟之后清除；同一句与同一意图从未执行两次（含跨重启）。
  - 结束时：排空后没有卡住的意图与插件。
  - 同一场景与种子两次运行得到完全相同的追踪与事件。
- 每次提交在固定种子集上运行；收缩出的失败场景加入回归用例。
- `pnpm sim [--seed N] [--runs N]` 做更大规模的探索；失败时打印收缩后的场景，并给出“种子 + 路径”的复现命令，配合提交即可复现。

## 评测

- 把真实直播中的弹幕会话导出为回放样本，在 `sim` profile 下做回归。
- 中文红队语料（谐音、拼音、emoji、分步诱导、昵称注入）用来评估审核插件；进入无人值守前须达标。
- 对话质量用模型评审辅助，并用人工抽样校准，注意评审标准会漂移。
- 实测指标报告样本数与 p50/p95/p99，失败样本不剔除。
