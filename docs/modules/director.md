# 决策模型

角色唯一的“决定做什么”的来源：读取局面，选择回应哪条弹幕、说什么、是否发起投票、交给游戏什么目标。普通插件，通过 `llm` 服务调用模型。P0 用回放的模型输出，P2 接真实模型。

## 职责

- 在决策时机到来时，组装上下文并调用模型。
- 把模型输出解析成**枚举的意图**，交给安全核授权。
- 处理游戏的决策点：无计时的选项决定是否交给观众投票，有计时的选项在截止前自己选（D-07）。

## 不负责

执行任何动作、审核、安排发声顺序、游戏的逐帧控制。

## 决策时机

- 不对每条弹幕都调用模型。触发条件包括：新一批候选弹幕经分诊合并后到达、游戏上报决策点或重要局面变化、投票结束、冷场计时到期。
- 默认同时只有一个在途调用；新的时机到来时，按优先级决定是合并、排队还是取消在途调用。
- 每次调用都有截止时间，可随时取消。

## 输出：动作选择

模型只能从以下意图类型中选择，参数由确定性代码校验，不能自己拼出新的动作：

| 意图 | 参数 |
| --- | --- |
| 说话 | 文本（可流式）、回应对象、过期时间。优先级由确定性代码按触发来源决定，模型不能指定（见[发声](speech.md#发声仲裁)）。回应观众的发言在句边界才能被抢占，自主闲聊可以立即让位 |
| 发起投票 | 题目（至多 60 字）、2–4 个选项（各至多 20 字）、时长（10–300 秒）；用于游戏决策点时绑定决策点编号。交给投票插件，开票说明与结果的发声来源由它按规则决定，见[投票](audience.md#投票) |
| 游戏目标 | 语言子目标、约束、模式（自主 / 等待投票 / 暂停），见[游戏桥](game-bridge.md) |
| 选择 | 对有计时决策点直接给出选项 |
| 保持沉默 | 原因 |

说话意图的文本以流的形式进入[发声](speech.md)管线，逐句（审核插件启用时先经判定）播出。

## 上下文

| 包含 | 不包含 |
| --- | --- |
| 人设与核心价值（操作员管理，观众和记忆都不能改写） | 凭据、密钥、平台管理权限 |
| 观众实际听到的近期发言 | OBS 与游戏的控制能力 |
| 分诊后的候选弹幕（净化后的称呼） | 私密记忆、观众个人信息 |
| 游戏局面摘要与决策点 | 未净化的原始昵称与原文 |
| 记忆中标记为公开安全的片段 | |

右列的排除是 Rule of Two 的要求：决策模型同时读取不可信输入并对外发声，就不能再接触敏感能力或私密数据（见[安全核](safety-core.md)）。

## 模型接入

- 真实模型按 R-17 接入：`llm` 服务由单独的模型客户端插件提供，它是 OpenAI 兼容的 Chat Completions 薄客户端，流式读取，端点、型号与思考档位写在它的配置里。
- 决策插件本身不持有任何凭据；模型客户端只持有模型服务的 API Key（`secret:ark`）与外发许可（`net.egress:<主机>`，见[插件内核](plugin-kernel.md#权限)），Key 的值不写日志、不进事件。
- 客户端不做隐式重试；每次调用的截止时间与取消由决策插件掌握，取消即断开连接。
- 思考内容（如有）不进入任何上下文、日志正文或事件。
- 遥测：决策插件为每次调用记一个 GenAI span（见[运维的观测](operations.md#链路)）。`llm` 服务给出模型标识（厂商与型号）；拿到 token 用量与实际应答的型号时经调用选项 `onUsage` 报给决策插件，流式读取收到第一块时调用 `onFirstChunk`，决策插件据此记流式首块的耗时；请求里的 `traceparent` 只用于本机遥测，不发给模型服务。

## 失败与降级

- 模型超时或出错：本次时机放弃，必要时播一句预先准备的固定过渡语（同样走发声管线）。
- 连续失败：通知安全核降级，并提示操作员。
- 输出无法解析为合法意图：丢弃，不做修补猜测。

## 验收

| 阶段 | 内容 |
| --- | --- |
| P0 | 回放模型输出：意图解析、非法输出被丢弃、上下文中不出现被排除的内容 |
| P2 | 真实模型：决策时机合并、取消、截止时间；人设漂移检测信号 |
| P3 | 游戏决策点：投票或自选的选择及截止时间内完成 |
