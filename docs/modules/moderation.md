# 审核插件

对角色将要说出的每一句话做一次独立判定。普通插件，不属于安全核，可在 profile 中关闭；前期从简，不作为重点（D-18）。P0 用模拟实现，P2 接真实审核模型。

## 职责

- 对发声管线中的每一句，调用一个与决策模型分开的独立审核模型，判定“可说”或“不可说”。
- 不可说的句子跳过，并记录原因。

## 不负责

- 弹幕的提示注入检测（由[观众接入](audience.md)的分诊负责）。
- 授权、急停、监督模式（由[安全核](safety-core.md)负责）。
- 保证内容绝对安全。它只是独立的第二道检查。

## 接入方式

[发声](speech.md)管线在“分句”与“发声仲裁”之间提供一个“发声前检查”扩展点（串行模式）。审核插件启用时注册到这个扩展点；未启用时扩展点上没有监听者，句子直接进入仲裁。

开关为开、但审核插件不在场时（例如审核模型不可用、插件停在 WAITING），发声仲裁把句子一律跳过。

## 判定

| 项 | 规则 |
| --- | --- |
| 输入 | 该句的字幕文本与朗读文本，必要时附上一句作为上下文 |
| 输出 | 可说 / 不可说，以及原因 |
| 不可说 | 跳过该句，记录原因；不影响同一发言中的其它句子 |
| 超时或出错 | 默认按不可说处理（跳过）；插件配置 `on_error` 可改为 `pass`（放行）。连续失败在操作台告警 |
| 时机 | 每句判定一次；可以在第 n 句播放时判定第 n+1 句，以隐藏延迟 |

## 开关

- 在 profile 中显式设置启用或关闭，没有隐含默认。
- 操作台常显当前状态；关闭时显示“审核已关闭”。
- 开关变化作为事件写入状态存储。
- 审核关闭时，安全核不允许进入无人值守（M3）；其它监督模式不受影响。

## 模型

审核模型的选择待 R-12（P2 前定）。P0 用模拟插件按脚本返回判定。

## 验收

| 阶段 | 内容 |
| --- | --- |
| P0 | 模拟插件：启用时不可说的句子被跳过；出错时按 `on_error` 跳过或放行；关闭时句子直接放行、状态常显并记录；审核关闭时无法进入 M3 |
| P2 | 真实审核模型的逐句延迟与判定准确率（探针 S-08） |
