# 安全核

随宿主构建、启动时直接装配的模块，不经过插件加载器，不能被 profile 移除，永不热替换（D-15、D-19）。另有一个外部看门狗进程兜底。P0 实现。

## 职责

- **执行闸门**：授权所有对外动作。
- **执行许可与急停**：执行器只在持有有效执行许可时动作；急停一次吊销全部许可。
- **OBS 应急连接**：安全核自己持有的一条 OBS 连接，只用于静音与切安全场景。
- **监督模式**：维护 M0–M3 与安全停止，自动降级。
- **速率与异常检测**：限速、预算、重复和漂移检测。
- **状态存储**：见[状态存储](state-store.md)。

## 不负责

内容是否有趣、该回应哪条弹幕、游戏怎么玩。这些由插件和决策模型决定，安全核只决定能不能执行、何时必须停。

## 执行闸门

所有副作用（说话、切场景、静音、发起投票、给游戏的目标、外发请求）都先表达为**意图**。意图的字段只在这里定义：

| 字段 | 含义 |
| --- | --- |
| 类型与目标 | 例如“播出一句话到 Stage”“切到某场景” |
| 载荷摘要 | 载荷的哈希，防止授权后被替换 |
| 幂等键 | 同一意图重复提交只执行一次 |
| 来源 | 由谁、基于哪些输入产生，用于判断是否混入了不可信输入 |
| 所需能力 | 例如 `speech.output`、`obs.scene`、`game.goal`、`game.input` |

`authorize(意图)` 返回允许或拒绝及原因：

- 依次检查：状态存储可用 → 当前模式允许输出 → 来源插件持有所需能力 → Rule of Two → 目标没有结果未知的意图（否则隔离该目标）→ 速率 → 守卫。任一项不通过即拒绝。
- 守卫只能拒绝或弃权，任何一个拒绝即拒绝；异常、超时、依赖缺失都按拒绝处理。守卫判定期间若进入了安全停止，结果仍为拒绝。
- 每次判定都写入状态存储。
- 决策模型采用“动作选择”模式：只能从枚举的意图类型里选，参数由确定性代码校验（见[决策模型](director.md)）。
- **Rule of Two 约束**：决策模型读取弹幕（不可信输入），又要公开发声（对外通信），所以它的上下文里不得出现凭据、OBS 管理能力和私密记忆。闸门据此拒绝来源含不可信输入、却申请 `obs.scene`、`obs.audio`、`obs.source`、`obs.stage-url`、`obs.stream`、`secret.read`、`memory.private` 的意图。读 OBS 音量表的插件权限 `obs.meters` 不在此列（见[插件内核](plugin-kernel.md#权限)）。

## 执行许可与急停

执行器（Stage 音频输出、OBS 控制、游戏输入）只在持有有效**执行许可**时动作：

| 字段 | 含义 |
| --- | --- |
| 持有者 | 哪个插件实例 |
| 资源与能力 | 例如“Stage 音频输出”“游戏输入” |
| 令牌 | 每个资源一个计数器，每次授予或吊销都递增；计数器保存在状态存储中，重启后不回退 |
| 到期时间 | 由 profile 按能力设定，持有者需要续约 |

- 设备只接受**等于当前令牌**且未过期的指令；被吊销的持有者即使令牌未过期也会被拒。
- 授予与吊销都递增令牌并写入状态存储；续约只延长到期时刻，不改令牌，也不写入。吊销先在内存中生效，不等待写入成功。
- 初始时长（均待测）：Stage 音频输出约 2 秒；游戏输入约 500 毫秒，每 250 毫秒内续约一次。
- 许可过期或被吊销后，设备自己停止，不依赖持有者配合。
- 重启后所有许可作废，不自动恢复。

**急停**的步骤：

1. 吊销全部执行许可；
2. 在控制通道广播停止；
3. 经安全核自己的 OBS 应急连接静音 Stage 源并切到安全场景，完成后在控制通道广播结果（是否成功），发声仲裁据此处理写回（见[发声](speech.md#播放游标与写回)）。

这条路径不需要执行许可，不经过插件、决策模型或普通事件队列。Stage 不可用、关键平面插件失效时，也走这条路径。

**OBS 热键**（R-27）：操作员在 OBS 里把“切到安全场景”“静音 Stage 源”绑到热键上，按下即在 OBS 内完成，不依赖宿主与看门狗。安全核的 OBS 应急连接订阅场景与输入两类事件（obs-websocket 的 EventSubscription 位 Scenes 与 Inputs），处理 `CurrentProgramSceneChanged`（`sceneName`）与 `InputMuteStateChanged`（`inputName`、`inputMuted`）：

- 真实输出模式（M1–M3）下节目场景变为安全场景、或 Stage 源被静音，先记事实 `safety.obs-external`（场景变化还是静音、场景或输入名、是否重连后核对发现），再走完整的急停路径：上面三步照做，第 3 步经应急连接把静音与切安全场景再做一遍（两个动作都幂等，热键可能只绑了其中一项）。原因记为“OBS 外部切到安全场景”或“OBS 外部静音了 Stage 源”：可能是热键，也可能是手动操作或别的客户端，不断言是热键。OBS 控制经授权切到安全场景或静音 Stage 源时同样如此。
- 已在安全停止、M0 或维护态时只写日志，不重复急停：安全核自己急停、看门狗动作引起的这两个事件都落在这里。宿主卡死期间看门狗先动了手，恢复后 OBS 的事件可能先于 `watchdog.acted` 到达：这时来源记为 OBS 外部变化，随后的看门狗报告按“已在安全停止”只记录；两种顺序的结果都是安全停止。
- 应急连接断开后重新连上时，若处于真实输出模式，读一次当前节目场景与 Stage 源的静音状态（断开期间的事件收不到），已是安全场景或已静音就按上面处理。
- 别的场景、别的输入、取消静音都不触发。

## 监督模式

| 模式 | 含义 | 可用能力 |
| --- | --- | --- |
| M0 仿真 | 只连模拟设备；`sim` profile 下唯一允许的模式 | 全部，但都是模拟 |
| M1 严格 | 真实输出；逐句人工放行，或固定延迟加一键否决 | 按 profile |
| M2 在场 | 操作员在场、可随时急停 | 按 profile |
| M3 无人值守 | 自动安全机制代替人工在场 | 收窄后的能力集 |
| 安全停止 | 不产生新输出，已切安全场景，等待操作员 | 无（唯一例外见下） |

- 当前模式、在场确认与维护态以安全核内存中的状态为准，变化作为事件记录；写入失败不影响降级与急停。
- **升级**只能由操作员显式执行，并重新检查目标模式的前置条件：输出模式都要求状态存储可用、OBS 应急连接可用；M1 起还要求外部看门狗已连接；M2 要求在场确认有效。
- **在场确认**：M2 要求操作员定期主动确认在场；操作台页面在线不算在场。
- **自动降级**的触发条件：审核插件启用时判定为不可说的比例异常、内容重复或漂移、超出速率或预算、关键依赖停用、看门狗报警、在场确认过期、状态存储故障。降级目标：从 M2 或 M3 降级且在场确认仍有效时降到 M1，其余情况进入安全停止（走急停路径）。恢复必须由操作员重新升级。
- **安全停止下的唯一例外**：只申请 `obs.stage-url` 能力的意图、`obs.stage-url` 资源的许可，在安全停止下照常判定与授予；维护态中、状态存储不可用时仍然拒绝。这个动作只把 URL 写进急停时静音的那个 Stage 源，不产生观众能看到或听到的输出：安全场景不含 Stage 源，Stage 源也已静音。这样 Stage 能在进入输出模式之前完成认证（开播预检要求）。
- **维护态**只能从安全停止进入，期间不授予任何执行许可，关键平面此时才能替换。
- **进入 M3 的门槛**：审核插件已在 profile 中显式启用（D-18，未显式设置视同未启用），且在中文红队语料上的召回率达标；急停与看门狗演练有实测数据；在 M2 下累计运行足够时长且无严重事件；平台规则已核对；值班呼叫可达。具体数值在进入无人值守阶段前登记，现在为 PENDING。

## 速率与异常检测

- 发声速率、单位时间的意图数、外发请求费用都有上限，超限即拒绝新意图并降级。
- 检测连续重复、与人设显著偏离、同一主题被反复诱导等模式，触发降级或冷却。
- 宿主内监测事件循环延迟，超过阈值视为异常。

## 外部看门狗

- 独立的 Node 小进程，由启动器拉起，不是宿主的子进程，宿主崩溃后仍然存活；从 SecretStore 读取本次会话的连接信息（R-14、R-23）。
- 经本机通道接收宿主心跳。心跳超时或连接意外断开时，用一次 obs-websocket 的 `RequestBatch` 静音 Stage 源、切到安全场景，按策略决定是否停止推流，然后呼叫操作员。呼叫渠道待定，P0 只记录事件。
- 执行过一次后，直到再次收到心跳才重新武装，不反复动作。
- 执行后告知宿主（`watchdog.acted`，含原因与 OBS 是否确认）：心跳超时时连接还在，就在原连接上发，宿主恢复后读到；连接已断开则在重连后补报。宿主据此记录事件并走急停路径进入安全停止；已在安全停止时只记录，但看门狗的 OBS 动作未成功时仍用自己的应急连接再做一次。
- 宿主计划内停止时先自己走急停路径，再通知看门狗；看门狗收到通知后不动作。
- 真实输出模式（M1–M3）下，宿主与看门狗的连接意外断开即走急停，作为报告之外的兜底：看门狗可能已经接管现场，也可能自己失效。
- 三道兜底互相独立：看门狗不依赖宿主与 Stage；Stage 页面收不到宿主心跳时自行静音；Game Runtime 在输入许可过期时自行释放全部输入。

## 失败与恢复

- 安全核自身出错时宿主退出，由看门狗接管现场。
- 重启后监督模式回到安全停止，等待操作员确认。
- 状态存储写入失败不能阻塞急停或拒绝；此时新的副作用一律拒绝，直到存储恢复。
