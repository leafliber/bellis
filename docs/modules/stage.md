# Stage、OBS 与形象

Stage 是运行在 OBS 浏览器源里的页面，负责播放音频、显示字幕，并回报播放游标。Stage 服务与 OBS 控制属于关键平面；形象（VTube Studio）是普通插件。P0 用模拟 Stage 与模拟 OBS，P1 接真实 OBS。

## 职责

- **Stage 页面**：接收已授权的音频与字幕，用 AudioWorklet 播放，回报播放游标、欠载与完成。
- **Stage 服务**（宿主内）：提供页面、管理连接与认证，只转发带有效 Stage 音频输出许可令牌的音频；转发时按句计算响度包络，供形象驱动口型。
- **OBS 控制**（宿主内）：经 obs-websocket 切场景、静音源、写来源设置（例如浏览器源的 URL），每次操作都需持有执行许可。急停不走这里，走安全核自己的 OBS 应急连接。
- **形象**：按播放游标驱动口型，并管理表情与待机动作。
- **呈现延迟**（普通插件 `stage-sync`）：按 OBS 音量表估计声音比画面晚多少，字幕与口型据此推迟（见[对齐](#对齐)）。
- **公开展示层**：投票、致谢等只读信息，与 Stage 分开。

## 不负责

决定说什么、审核、合成。Stage 没有键鼠能力，也不能提交自由内容。

## Stage 页面

- **加载方式**：宿主用 `node:http` 只在 `127.0.0.1`（字面地址，不用 `localhost`）上提供页面，端口每次会话随机，作为 OBS 浏览器源的 URL 加载（R-08）。AudioWorklet 与 WebCrypto 都要求安全上下文；按规范 `http://127.0.0.1` 属于可信来源，而 OBS 的“本地文件”模式经 OBS 自定义的来源加载，不是安全上下文，因此不用。是否满足以探针 S-01 为准。
- **连接**：WebSocket 服务端用 `ws`，以 `noServer` 方式在 HTTP 升级阶段认证（R-08）。音频用二进制消息，控制用文本消息；单条消息设上限，不用默认值。
- **来源校验**：OBS 里的其他浏览器源和停靠面板也能访问本机端口，本机其他网页也可能经 DNS 重绑定找上门。因此（R-08）：
  - 每个 HTTP 请求与 WebSocket 升级都要求 `Host` 等于 `127.0.0.1:端口`。
  - 脚本、AudioWorklet 模块、样式表等子资源与 WebSocket 升级还要求 `Origin` 等于 `http://127.0.0.1:端口`，缺少即拒绝。样式表默认以 no-cors 方式请求、不带 `Origin`，页面里的 `<link>` 因此加 `crossorigin` 属性。
  - 页面文档本身是顶层导航，浏览器不为它带 `Origin`（OBS 32.2.x 中已确认，刷新时 `Sec-Fetch-Site` 为 `same-origin`，初次加载与改 URL 时为 `none`），只在 `Sec-Fetch-Mode` 为 `navigate` 且 `Sec-Fetch-Dest` 为 `document` 时放行。文档是静态的，不含任何秘密，令牌在 URL 片段里不随请求发出；别的网页把它嵌进 iframe 时 `Sec-Fetch-Dest` 为 `iframe`，仍被拒绝。
- **会话令牌**：浏览器源的 URL 以明文存在场景集合里，`GetInputSettings` 也能读出，因此 URL 里只放一次性令牌：
  - 宿主启动时以及每次重新下发时，生成 128 位、短时效的一次性令牌，经 OBS 控制写进 URL 的片段（`#` 之后，不会出现在 HTTP 请求与日志里）。宿主启动时处于安全停止，这一步是安全停止下唯一允许的动作（见[安全核](safety-core.md#监督模式)）。
  - 页面读出令牌后立即用 `history.replaceState` 从地址中去掉，以首条 WebSocket 消息出示，换取只存于内存的会话密钥。连接断开后，页面在时限内用会话密钥重连；超过时限，宿主重新下发 URL。
  - 同时只允许一个已认证会话，第二个升级请求直接拒绝；心跳超时回收半开连接。
  - 刷新浏览器源时，OBS 32.2.x 重新加载的是已去掉片段的地址，页面没有令牌，照样以首条消息报到；宿主拒绝并限频重新下发 URL。重放用过的令牌同样被拒并重新下发。
  - 页面不在 localStorage、IndexedDB 中保存任何密钥：OBS 的全部浏览器源共用一个浏览器配置。
- **播放**：PCM 经 MessagePort 送入 AudioWorklet 的缓冲，不依赖 SharedArrayBuffer（它要求跨源隔离，在 OBS 浏览器源中是否可用由 S-01 验证）。页面按句把 PCM 线性插值重采样到 AudioContext 的采样率（OBS 32.2.2 中为 192kHz），游标仍按原始采样数回报。欠载时补零，但补零不推进播放游标。
  - AudioContext 的 latencyHint 用 `interactive`，`playback` 留作退路（`stage-page-obs` 的 `latencyHint`）。OBS 32.2.2 中浏览器自报的输出时延 `interactive` 约 10ms + 32ms，`playback` 约 20ms + 64ms，整条链路短约 60ms。`interactive` 在 OBS 最小化下连续播放 30 分钟实测：页面无欠载，录音无断流、音高偏差不超过 0.01 音分。
- **唤醒信号**：OBS 浏览器源只在页面“有声”时采集它的音频。真机实测（OBS 32.2.2）：页面连续数字静音 2 秒后的句子完整，3 秒及以上（到 60 秒）每次句首丢 20–80ms（20ms 的整数倍），页面刚加载后的第一句同样丢；静默期间填 -60dBFS 噪声则不丢，填 -84dBFS 仍丢。丢失与页面渲染无关，取决于输出是否高于 Chromium 判定“有声”的阈值（约 -72dBFS）；推断是 CEF 静默一阵后停止采集，再次有声时重新开始。因此 AudioWorklet 按渲染帧记连续数字静音的时长（含句中欠载的补零）：即将输出正文、而此前连续数字静音已超过 1.5 秒时，先放 150ms 唤醒信号再放正文。句首与句中欠载恢复同一条规则。唤醒信号是 20Hz、峰值 -50dBFS 的正弦，两端 10ms 升余弦淡入淡出。
  - 只在队首有句子、且已收到要播的音频时才放；句子只在持有许可、未静音时入队，所以空闲、安全停止与自静音时仍是数字静音。唤醒信号放完才算有声，中途作废（没有句子了、静音、截断）不算。代价是这些句子（或欠载后恢复的那一段）多约 150ms 延迟。
  - 开始回报在正文开始时发出；唤醒期间游标不推进，唤醒样本不计入已播出。
  - 实测依据：唤醒信号 100ms、峰值 -50/-55/-60dBFS 时，静默 3–60 秒后的句子与页面加载后的第一句共 51 次，句首缺失都不超过 0.5ms；50ms 不够（6 次中 1 次仍丢 20ms）。采集在唤醒信号开始后 20 到 80 多毫秒才启动（51 次中 3 次超过 80ms），所以取 150ms 留出余量。150ms、-50dBFS 复测：静默 3、15、60 秒后各 3 次加页面加载后的第一句，句首缺失都不超过 0.4ms，开始回报比发出晚 130–163ms；句中欠载 3 秒、15 秒后恢复各 2 次，恢复的那一段缺失都不超过 0.2ms，欠载 0.5 秒的不放唤醒信号、也不缺。录音里唤醒信号被采集启动截掉的开头处留下一个短暂的突变：-50dBFS 时高于 150Hz 部分的 5ms RMS 最高约 -58.5dBFS，比正文低约 45dB（-60dBFS 时约 -68dBFS）。截断之后的唤醒信号在 AAC 编码后以 20–40Hz 为主，60Hz 以上不高于约 -70dBFS。
- **令牌校验**：页面只播放带当前许可令牌的音频；令牌变更后，旧令牌的缓冲立即丢弃。令牌消息带许可时长，续约时重发；页面在时长内收不到续约即视为许可过期，自行停止并清空缓冲。
- **计时**：许可时长与心跳超时都在 AudioWorklet 里按已渲染的样本帧计时，不用页面定时器：来源隐藏时 Chromium 会把定时器节流到每秒一次，隐藏且无声 5 分钟后再降到每分钟一次（[Chrome 定时器节流](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)）。
- **播放游标**：页面回报每句的实际开始、已播采样数、结束与截断（定义见[发声](speech.md#播放游标与写回)）。字幕（见下文[字幕](#字幕)）与口型随游标推进，而不是随文本到达或墙钟推进。游标是页面渲染的样本数，不含浏览器的输出缓冲、OBS 自身的音频缓冲与同步偏移，也反映不了 OBS 侧的静音或来源不在节目场景中；字幕与口型据此推迟多少见[对齐](#对齐)。
- **自保护**：收不到宿主心跳时自行静音并清空缓冲；收到心跳即应答。Stage 服务在截止时间内收不到应答，视为 Stage 不可用，安全核走急停路径（D-30）。宿主自己卡住时发不出心跳，页面也就不应答：Stage 服务的心跳定时器晚到超过一个心跳周期时，这一轮不判页面失败，先发心跳、从现在起重新计时并记日志（宿主卡死由外部看门狗负责）。
- **AI 标识**：试播起，页面常驻 AI 生成内容标识；标识层不可见即视为不可播出（D-09，见[合规](../compliance.md)）。

### 字幕

页面只显示经发声管线放行的字幕文本，按播放游标逐字推进。

- **显示规则**：显示字幕文本中开始时刻不晚于显示位置的码点组成的前缀；显示位置是呈现延迟（见[对齐](#对齐)）之前这一句的已播采样数。已显示的字不收回，映射细化后某个字的开始变晚也不收回。没有映射时，这一句一开始显示就整句显示。句子播完后推迟呈现延迟再清除；还在播放的句子被截断（含急停、许可令牌变化与页面自静音）时立即清除。都不保留到下一句。
- **与写回的关系**：写回只计结束时刻不晚于游标的字（见[播放游标与写回](speech.md#播放游标与写回)），而一个字的结束就是下一个字的开始，所以页面显示的总包含写回的部分，多出的至多是正在播的那一个字，外加不朗读的符号。
- **映射**：字幕文本第 k 个码点从第 `starts[k]` 个原始采样开始显示，按码点不减。发声仲裁把这一句的时间映射（采样偏移 → 朗读码点，两段式且是活的，R-11）换算成 `starts`：
  - 有朗读码点的字取它第一个朗读码点的开始；不朗读的符号（引号、括号等）随后面第一个朗读的字显示，句末的随最后一个字；
  - 映射中没有时间点的朗读码点取后面最近一个的开始，后面都没有的不给出，页面暂不显示这些字。
- **传递**：Stage 服务在句子开始、每转发一块音频之后与音频流结束时现读映射，有变化就整份发给页面（文本消息 `timing`，带句编号与许可令牌）。插值、随音频到达的细化、流结束后按实际采样数的修正因此都会送到。映射发送前按 Schema 校验（非负整数、按码点不减、不多于字幕的码点），不合格的不发，页面沿用上一份，每句记一次日志。只为令牌有效、没有被要求截断的句子发送；页面同样丢弃旧令牌与已截断句子的映射。
- **进度**：AudioWorklet 只把正文计入已播采样数，正文播出、已播采样数有变化时至多每渲染 10ms 向页面报一次进度。这个进度只给页面，不转给宿主；给宿主的游标仍是每 100ms 一次。唤醒信号与欠载补零期间已播采样数不变，字幕也就停住；只出字幕时播的是静音帧，照样推进。不用页面的 `currentTime` 外推：它在唤醒信号与欠载期间照样前进，外推会让字幕超前，而已显示的字不收回。
- **渲染**：版面固定：一句开始播放时整句就排好，还没显示的字放在不可见（`visibility: hidden`）的占位元素里，整句的位置与换行从一开始就不变，字只是逐个变得可见；清除时两段都清空。两段都只用 `textContent`，不解析 HTML；各自只在内容变化时写，不逐帧重建；样式只在样式表里，不用内联样式。模拟 Stage 页面用同一套推进规则，确定性仿真据此检查字幕不早于游标（见[运维](operations.md#确定性仿真)）。

## OBS 控制

- 只执行别的插件已授权的意图，不自己决定做什么；意图的载荷就是动作。动作与意图须申请的能力：切场景 `obs.scene`，静音源 `obs.audio`，写来源设置 `obs.source`，写 Stage URL `obs.stage-url`（只写急停时静音的那个 Stage 源的 `url`，安全停止下也能执行）。这些都不允许来自不可信输入（见[安全核](safety-core.md#执行闸门)的 Rule of Two）；意图没有申请对应能力时不执行。
- 每个动作执行时取得 `obs.control` 资源的执行许可，发出请求前再核对一次令牌，完成后交还；动作逐个执行。安全停止与维护态下拿不到许可，因此什么都不做。
- 用自己的 obs-websocket 连接，由宿主建立并交出已认证的连接：凭据不进插件，只有被授予 `obs.control` 权限的实例能连接。

## OBS 配置要求

- Stage 浏览器源开启“Control audio via OBS”（R-09）：页面自身不向系统设备出声，声音只进 OBS，OBS 的静音和切场景因此能直接切断 TTS 声音。不用虚拟声卡或 sidecar 直接出声，它们在 OBS 静音后仍可能经系统设备漏出。
- 不开启“Shutdown source when not visible”和“Refresh browser when scene becomes active”，避免切场景时页面被卸载或重载；页面权限设为不授予任何 OBS 访问权限。
- Win11 曾因忽略被遮挡且无声进程的定时器精度请求，导致浏览器源音频失真（[obs-studio #7588](https://github.com/obsproject/obs-studio/issues/7588)、[obs-browser #406](https://github.com/obsproject/obs-browser/issues/406)）。OBS 31.1 已修复（[obs-browser #484](https://github.com/obsproject/obs-browser/pull/484)），32.2.x 包含此修复；长时间运行的表现仍由 S-01 实测。
- 基线版本 OBS 32.2.x（D-24）；OBS 与浏览器内核版本写进 Stage 握手，便于对照兼容矩阵。迁移到 OBS 33 前须复测页面导航或刷新后声音仍只经 OBS：33 的测试版曾有此后绕过 OBS 的缺陷（[obs-browser 修复](https://github.com/obsproject/obs-browser/commit/de7e68f33f76f76312ea4c2237ca3c8f809de363)），否则急停的静音会失效。
- 安全场景与静音目标在配置中固定，开播预检确认它们存在、浏览器源的上述设置无误，并确认安全场景里不含 Stage 源。

## 形象

普通插件 `avatar-vts`，经 [VTube Studio 插件 API](https://github.com/DenchiSoft/VTubeStudio) 注入参数（R-15），提供 `avatar@1`。

- **连接**：只连本机，默认 `ws://127.0.0.1:8001`，端口可在插件配置中改成 VTS 里设置的值。客户端用 `ws` 并关闭 permessage-deflate（R-10）：Node 自带的 WebSocket 会请求压缩，VTS 接受后把每条消息编码成以结束块收尾的完整 deflate 流，自带客户端只解得出第一条，之后的应答都成了空消息（VTS 1.35.10 实测）。VTS 不在或连接断开时，插件保持激活但报告未就绪，按固定间隔重连；开播预检据此判断形象未就绪。
- **认证**：插件令牌经凭据服务读写 SecretStore 的 `vts` 条目，profile 授予 `secret:vts`。每次连接都用已存令牌重新认证；没有令牌，或令牌被 VTS 拒绝（例如维护者在 VTS 中撤销了插件）时发令牌申请，VTS 弹窗由维护者点允许，拿到的令牌写回 `vts` 后再认证。维护者在弹窗中拒绝后，本实例不再申请，重新加载插件才会再弹窗。令牌与插件名、开发者名绑定，令牌的值不进日志与事件。
- **口型**：Stage 服务转发音频时按句计算响度包络（按原始采样率，每 20ms 窗口一个 RMS），经 `stage@1` 的 `envelope(句子)` 提供，句子播完或截断后即不再提供。形象插件取最近一次游标回报的采样位置，加上按墙钟外推的时间（上限可配，不超过 200ms），再推迟（呈现延迟 − k_mouth）（见[对齐](#对齐)），在包络上取 RMS，按配置的上下限线性映射到 0–1；欠载中、截断、页面静音时立即为 0，句子播完后同样推迟再归 0。包络在句子开始播放时取到就留着，推迟的那段时间里还要用。口型只跟随播放游标，不跟随文本或音频的到达。
- **注入**：以 30–60Hz（默认 30Hz；OBS 输出 30fps 时实测 60Hz 的口型时延并不更稳，逐句标准差与 30Hz 同为约 9ms，见[对齐](#对齐)）注入嘴型参数（默认 VTS 的 `MouthOpen`，可配置），用 `set` 模式并声明已检测到面部，避免播放“追踪丢失”动画；不说话时也按同一频率注入 0。VTS 要求每个参数至少每秒重发一次，否则视为丢失并交还原来的控制方，宿主失联时口型因此在约 1 秒内归位。嘴型参数在 VTS 中的平滑设为 0。
- **参数占用**：一个参数只由一个插件写入。VTS 报告嘴型参数已被其他插件占用（或以其他错误拒绝注入）时，记录 `avatar.injection-stopped` 事实并在日志中报告，本实例停止注入、报告未就绪，不重试抢占；重新加载插件才再尝试。
- **表情**：`avatar@1` 的 `expression` 执行已授权的意图：意图须申请 `avatar.expression`，载荷为表情名；插件配置把表情名映射到 VTS 热键 ID，经 `HotkeyTriggerRequest` 触发。安全停止下闸门不授权，执行前再核对一次模式。P1 中没有调用方。
- VTS 画面用 OBS 自带的游戏采集（允许透明，配合 VTS 的透明输出）接入，不安装 OBS 插件。安全场景不包含形象画面，急停切场景即同时隐藏形象。
- 不把 TTS 音频再交给 VTS 的麦克风口型，避免两条路径不同步。
- Bellis 不包含 Live2D 代码；VTS 与模型的许可要求见[合规](../compliance.md#素材与数据)。
- VTS 未公布从注入到出画的延迟；它与字幕路径的差在 OBS 录制中实测，作为 k_mouth 标定（见[对齐](#对齐)），不提前输出尚未生成的内容。包络映射的上下限待真机调校。

## 对齐

页面渲染出的声音还要经过浏览器的输出缓冲、OBS 的音频缓冲与混音才出现在 OBS 的输出里，字幕（浏览器源的画面）与口型（游戏采集的 VTS 画面）走视频路径，比声音早。实测（OBS 32.2.2、30fps 录制、测试音，不补偿）：字幕比声音早约 82ms（`interactive`）或 142ms（`playback`），页面会话之间相差约 20ms；口型比字幕晚约 40ms。浏览器自报的输出时延（`baseLatency`、`outputLatency`）按它预测，残差约 13ms；OBS 音量表看到出声的时延减去约 4ms，残差约 6ms。所以按 OBS 音量表实测。

- **呈现延迟 D**：页面播出的声音再过约 D 才出现在 OBS 的输出里。Stage 服务持有 D（`stage@1` 的 `presentation`：D、样本数与来源，没有估计插件时为 0），由估计插件写入，变化时与每句开始前发给页面（文本消息 `presentation`，0–300 的整数毫秒，发送前按 Schema 校验）。
- **测量**：普通插件 `stage-sync` 经宿主提供的只读音量表连接收 Stage 源的音量表读数（约每 50ms 一次）。每句一个样本：宿主收到这一句的开始回报之后，Stage 源各声道推子前峰值的最大值第一次从 -30dBFS 以下升到以上的时刻，减去收到开始回报的时刻，再减去这一句的音频第一个采样达到 -30dBFS 的时刻（Stage 服务转发音频时随包络记下；测试音约 0，修剪过句首静音的本地 TTS 语音约 30–100ms）。起音之前页面上静音不足 D + 100ms 的句子不取样本，免得把上一句的余音当成这一句的起音；500ms 内没看到上升沿的放弃。
- **估计**：取最近 21 句的中位数（单个样本因读数间隔有约 ±25ms 的量化，中位数约 ±4ms），加上 Stage 源的音频同步偏移（每 10 秒读一次 `GetInputAudioSyncOffset`，音量表的读数不含它；负值按 0 计，OBS 32.2.2 实测负的同步偏移不改变输出），减去 k_sub，取整后限制在 0–300ms；与当前值相差超过 5ms 才更新。不足 5 句时用初值加同步偏移。初值是按 latencyHint 标定的常数，不持久化：同一页面会话里 D 不变，页面重新加载后变化约 ±10ms，上次的值并不比初值更接近新会话，约 5 句后就按实测。
- **字幕**：页面把开始、进度与播完的回报都推迟 D 才生效，显示位置因此是 D 之前的已播采样数，播完后的清除也推迟 D；推迟期间没有新回报时按定时器到点生效。截断与页面自静音不推迟，立即清除并丢掉推迟中的回报；许可令牌变化（含急停）时还在播放或排队的句子同样立即清除，已经播完、只差推迟清除的那一句照常到点清除：每段发言播完、许可交还时令牌也会变，那一句的声音已全部交给 OBS。急停时 OBS 同时静音并切到不含 Stage 源的安全场景，这一句至多多留 D。D 改小时已到期的回报立即生效。
- **口型**：形象取（D − k_mouth）之前的位置，不小于 0（见[形象](#形象)）。
- **写回**：急停时写回扣掉 D，规则见[发声](speech.md#播放游标与写回)。
- **标定**：k_sub 是音量表的时延比字幕该推迟的多出的部分（`stage-sync` 的 `kSubMs`，缺省 4ms），k_mouth 是口型从注入到出画比字幕多出的时延（`avatar-vts` 的 `kMouthMs`，缺省 40ms），初值是 `stage-sync` 的 `initialDelayMs`（缺省 82ms，即 `interactive` 的标定值；Stage 页面改用 `playback` 时改成 142ms），都写在 profile 的插件配置里。重标用 `spikes/drill-av-offset.ts --stage-sync`：它录下的就是补偿后的剩余偏差，字幕取首字与末字的中位数、口型取时延的中位数（画面减声音，早为负），新的 k_sub = k_sub + 字幕剩余偏差，新的 k_mouth = k_mouth + 口型剩余偏差；初值取演练结束时的 D 减去同步偏移。换了 OBS 版本、浏览器源的 latencyHint、输出帧率、音频设备或采样率，或换了 VTS 版本、模型、嘴型参数的平滑、注入频率或采集方式时重标；演练的剩余偏差超过半帧时也重标。
- **补偿后实测**（OBS 32.2.2、`interactive`、30fps，画面减声音）：测试音逐字偏差中位数约 -1ms（-31…26ms），清除约 -7ms，口型约 -6ms（-24…18ms，60Hz 注入时 -4ms，-30…8ms）；修剪过静音的本地 TTS 语音首字约 -25ms（-31…-8ms），口型约 -14ms，清除比 -40dBFS 处的句末晚约 44ms，这是修剪保留的 30ms 余量与衰减尾巴，相对音频本身的末尾约 -9ms。一次会话里 D 在 79–89ms 之间变动。
- **只读连接**：宿主用同一份 OBS 凭据另开一条 obs-websocket 连接，认证时只订阅 InputVolumeMeters；交给插件的对象只能收音量表读数、读输入的音频同步偏移，发不出别的请求。只有被授予 `obs.meters` 的实例能连接（见[插件内核](plugin-kernel.md#权限)）。
- **降级**：音量表连不上或断开时沿用上一次的 D（来源为 `held`）或初值（`initial`），记日志，每 5 秒重连，不阻断播出，也不进开播预检：D 只影响字幕与口型显示的时刻，沿用的值至多差一个会话间的变化（约 ±10ms）。
- **可观测**：D 或来源的变化记日志 `stage-sync.delay`，每句的样本或不取样本的原因记 `stage-sync.sample`，连接的变化记 `stage-sync.meters-*`，都不进事件。`pnpm operator status` 的 `presentation` 给出当前的 D、样本数与来源。
