# Stage、OBS 与形象

Stage 是运行在 OBS 浏览器源里的页面，负责播放音频、显示字幕，并回报播放游标。Stage 服务与 OBS 控制属于关键平面；形象（VTube Studio）是普通插件。P0 用模拟 Stage 与模拟 OBS，P1 接真实 OBS。

## 职责

- **Stage 页面**：接收已授权的音频与字幕，用 AudioWorklet 播放，回报播放游标、欠载与完成。
- **Stage 服务**（宿主内）：提供页面、管理连接与认证，只转发带有效 Stage 音频输出许可令牌的音频；转发时按句计算响度包络，供形象驱动口型。
- **OBS 控制**（宿主内）：经 obs-websocket 切场景、静音源、写来源设置（例如浏览器源的 URL），每次操作都需持有执行许可。急停不走这里，走安全核自己的 OBS 应急连接。
- **形象**：按播放游标驱动口型，并管理表情与待机动作。
- **公开展示层**：投票、致谢等只读信息，与 Stage 分开。

## 不负责

决定说什么、审核、合成。Stage 没有键鼠能力，也不能提交自由内容。

## Stage 页面

- **加载方式**：宿主用 `node:http` 只在 `127.0.0.1`（字面地址，不用 `localhost`）上提供页面，端口每次会话随机，作为 OBS 浏览器源的 URL 加载（R-08）。AudioWorklet 与 WebCrypto 都要求安全上下文；按规范 `http://127.0.0.1` 属于可信来源，而 OBS 的“本地文件”模式经 OBS 自定义的来源加载，不是安全上下文，因此不用。是否满足以探针 S-01 为准。
- **连接**：WebSocket 服务端用 `ws`，以 `noServer` 方式在 HTTP 升级阶段认证（R-08）。音频用二进制消息，控制用文本消息；单条消息设上限，不用默认值。
- **来源校验**：OBS 里的其他浏览器源和停靠面板也能访问本机端口，本机其他网页也可能经 DNS 重绑定找上门。因此（R-08）：
  - 每个 HTTP 请求与 WebSocket 升级都要求 `Host` 等于 `127.0.0.1:端口`。
  - 脚本、AudioWorklet 模块、样式表等子资源与 WebSocket 升级还要求 `Origin` 等于 `http://127.0.0.1:端口`，缺少即拒绝。样式表默认以 no-cors 方式请求、不带 `Origin`，页面里的 `<link>` 因此加 `crossorigin` 属性。
  - 页面文档本身是顶层导航，浏览器不为它带 `Origin`（OBS 32.2.x 中已确认，刷新时 `Sec-Fetch-Site` 为 `same-origin`，初次加载与改 URL 时为 `none`），只在 `Sec-Fetch-Mode` 为 `navigate` 且 `Sec-Fetch-Dest` 为 `document` 时放行。文档是静态的，不含任何秘密，令牌在 URL 片段里不随请求发出；别的网页把它嵌进 iframe 时 `Sec-Fetch-Dest` 为 `iframe`，仍被拒绝。
- **会话令牌**：浏览器源的 URL 以明文存在场景集合里，`GetInputSettings` 也能读出，因此 URL 里只放一次性令牌：
  - 宿主启动时以及每次重新下发时，生成 128 位、短时效的一次性令牌，经 OBS 控制写进 URL 的片段（`#` 之后，不会出现在 HTTP 请求与日志里）。宿主启动时处于安全停止，这一步是安全停止下唯一允许的动作（见[安全核](safety-core.md#监督模式)）。
  - 页面读出令牌后立即用 `history.replaceState` 从地址中去掉，以首条 WebSocket 消息出示，换取只存于内存的会话密钥。连接断开后，页面在时限内用会话密钥重连；超过时限，宿主重新下发 URL。
  - 同时只允许一个已认证会话，第二个升级请求直接拒绝；心跳超时回收半开连接。
  - 刷新浏览器源时，OBS 32.2.x 重新加载的是已去掉片段的地址，页面没有令牌，照样以首条消息报到；宿主拒绝并限频重新下发 URL。重放用过的令牌同样被拒并重新下发。
  - 页面不在 localStorage、IndexedDB 中保存任何密钥：OBS 的全部浏览器源共用一个浏览器配置。
- **播放**：PCM 经 MessagePort 送入 AudioWorklet 的缓冲，不依赖 SharedArrayBuffer（它要求跨源隔离，在 OBS 浏览器源中是否可用由 S-01 验证）。页面按句把 PCM 线性插值重采样到 AudioContext 的采样率（OBS 32.2.2 中为 192kHz），游标仍按原始采样数回报。欠载时补零，但补零不推进播放游标。
- **唤醒信号**：OBS 浏览器源只在页面“有声”时采集它的音频。真机实测（OBS 32.2.2）：页面连续数字静音 2 秒后的句子完整，3 秒及以上（到 60 秒）每次句首丢 20–80ms（20ms 的整数倍），页面刚加载后的第一句同样丢；静默期间填 -60dBFS 噪声则不丢，填 -84dBFS 仍丢。丢失与页面渲染无关，取决于输出是否高于 Chromium 判定“有声”的阈值（约 -72dBFS）；推断是 CEF 静默一阵后停止采集，再次有声时重新开始。因此 AudioWorklet 按渲染帧记连续数字静音的时长，超过 1.5 秒后的第一句先放 100ms 唤醒信号再放正文：20Hz、峰值 -50dBFS 的正弦，两端 10ms 升余弦淡入淡出。
  - 只在队首有句子、且已收到这一句的音频时才放；句子只在持有许可、未静音时入队，所以空闲、安全停止与自静音时仍是数字静音。代价是这些句子多约 100ms 延迟。
  - 开始回报在正文开始时发出，游标与已播出的采样只算正文。
  - 实测依据：唤醒信号 100ms、峰值 -50/-55/-60dBFS 时，静默 3–60 秒后的句子与页面加载后的第一句共 51 次，句首缺失都不超过 0.5ms；50ms 不够（6 次中 1 次仍丢 20ms）。采集在唤醒信号开始后 20 到 80 多毫秒才启动，录音里只剩它后面的一段，截断处留下一个短暂的突变：-50dBFS 时高于 150Hz 部分的 5ms RMS 最高约 -58.5dBFS，比正文低约 45dB；-60dBFS 时约 -68dBFS。截断之后的唤醒信号在 AAC 编码后以 20–40Hz 为主，60Hz 以上不高于约 -70dBFS（-50dBFS 时）。句中欠载超过 1.5 秒后恢复时没有唤醒信号。
- **令牌校验**：页面只播放带当前许可令牌的音频；令牌变更后，旧令牌的缓冲立即丢弃。令牌消息带许可时长，续约时重发；页面在时长内收不到续约即视为许可过期，自行停止并清空缓冲。
- **计时**：许可时长与心跳超时都在 AudioWorklet 里按已渲染的样本帧计时，不用页面定时器：来源隐藏时 Chromium 会把定时器节流到每秒一次，隐藏且无声 5 分钟后再降到每分钟一次（[Chrome 定时器节流](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)）。
- **播放游标**：页面回报每句的实际开始、已播采样数、结束与截断（定义见[发声](speech.md#播放游标与写回)）。字幕与口型随游标推进，而不是随文本到达或墙钟推进。游标是页面渲染的样本数，不含 OBS 自身的音频缓冲与同步偏移，也反映不了 OBS 侧的静音或来源不在节目场景中。`getOutputTimestamp()` 在 OBS 接管音频时究竟对应哪个时钟，由 S-01 实测；与推流混音之间的偏差在 OBS 录制回环中校准。
- **自保护**：收不到宿主心跳时自行静音并清空缓冲；收到心跳即应答。Stage 服务在截止时间内收不到应答，视为 Stage 不可用，安全核走急停路径（D-30）。宿主自己卡住时发不出心跳，页面也就不应答：Stage 服务的心跳定时器晚到超过一个心跳周期时，这一轮不判页面失败，先发心跳、从现在起重新计时并记日志（宿主卡死由外部看门狗负责）。
- **字幕安全**：只显示经发声管线放行的字幕文本，用 `textContent` 渲染，不解析 HTML。
- **AI 标识**：试播起，页面常驻 AI 生成内容标识；标识层不可见即视为不可播出（D-09，见[合规](../compliance.md)）。

## OBS 控制

- 只执行别的插件已授权的意图，不自己决定做什么；意图的载荷就是动作。动作与意图须申请的能力：切场景 `obs.scene`，静音源 `obs.audio`，写来源设置 `obs.source`，写 Stage URL `obs.stage-url`（只写急停时静音的那个 Stage 源的 `url`，安全停止下也能执行）。这些都不允许来自不可信输入（见[安全核](safety-core.md#执行闸门)的 Rule of Two）；意图没有申请对应能力时不执行。
- 每个动作执行时取得 `obs.control` 资源的执行许可，发出请求前再核对一次令牌，完成后交还；动作逐个执行。安全停止与维护态下拿不到许可，因此什么都不做。
- 用自己的 obs-websocket 连接，由宿主建立并交出已认证的连接：凭据不进插件，只有被授予 `obs.control` 权限的实例能连接。

## OBS 配置要求

- Stage 浏览器源开启“Control audio via OBS”（R-09）：页面自身不向系统设备出声，声音只进 OBS，OBS 的静音和切场景因此能直接切断 TTS 声音。不用虚拟声卡或 sidecar 直接出声，它们在 OBS 静音后仍可能经系统设备漏出。
- 不开启“Shutdown source when not visible”和“Refresh browser when scene becomes active”，避免切场景时页面被卸载或重载；页面权限设为不授予任何 OBS 访问权限。
- Win11 曾因忽略被遮挡且无声进程的定时器精度请求，导致浏览器源音频失真（[obs-studio #7588](https://github.com/obsproject/obs-studio/issues/7588)、[obs-browser #406](https://github.com/obsproject/obs-browser/issues/406)）。OBS 31.1 已修复（[obs-browser #484](https://github.com/obsproject/obs-browser/pull/484)），32.2.x 包含此修复；长时间运行的表现仍由 S-01 实测。
- 基线版本 OBS 32.2.x（D-24）；OBS 与浏览器内核版本写进 Stage 握手，便于对照兼容矩阵。迁移到 OBS 33 前须复测页面导航或刷新后声音仍只经 OBS：33 的测试版曾有此后绕过 OBS 的缺陷（[obs-browser 修复](https://github.com/obsproject/obs-browser/commit/de7e68f33f76f76312ea4c2237ca3c8f809de363)），否则急停的静音会失效。
- 安全场景与静音目标在配置中固定，开播预检确认它们存在、浏览器源的上述设置无误，并确认安全场景里不含 Stage 源。

## 形象

普通插件 `avatar-vts`，经 [VTube Studio 插件 API](https://github.com/DenchiSoft/VTubeStudio) 注入参数（R-15），提供 `avatar@1`。

- **连接**：只连本机，默认 `ws://127.0.0.1:8001`，端口可在插件配置中改成 VTS 里设置的值。VTS 不在或连接断开时，插件保持激活但报告未就绪，按固定间隔重连；开播预检据此判断形象未就绪。
- **认证**：插件令牌经凭据服务读写 SecretStore 的 `vts` 条目，profile 授予 `secret:vts`。每次连接都用已存令牌重新认证；没有令牌，或令牌被 VTS 拒绝（例如维护者在 VTS 中撤销了插件）时发令牌申请，VTS 弹窗由维护者点允许，拿到的令牌写回 `vts` 后再认证。维护者在弹窗中拒绝后，本实例不再申请，重新加载插件才会再弹窗。令牌与插件名、开发者名绑定，令牌的值不进日志与事件。
- **口型**：Stage 服务转发音频时按句计算响度包络（按原始采样率，每 20ms 窗口一个 RMS），经 `stage@1` 的 `envelope(句子)` 提供，句子播完或截断后即不再提供。形象插件取最近一次游标回报的采样位置，加上按墙钟外推的时间（上限可配，不超过 200ms），在包络上取 RMS，按配置的上下限线性映射到 0–1；欠载中、句子结束或截断、页面静音时为 0。口型只跟随播放游标，不跟随文本或音频的到达。
- **注入**：以 30–60Hz（默认 30Hz）注入嘴型参数（默认 VTS 的 `MouthOpen`，可配置），用 `set` 模式并声明已检测到面部，避免播放“追踪丢失”动画；不说话时也按同一频率注入 0。VTS 要求每个参数至少每秒重发一次，否则视为丢失并交还原来的控制方，宿主失联时口型因此在约 1 秒内归位。嘴型参数在 VTS 中的平滑设为 0。
- **参数占用**：一个参数只由一个插件写入。VTS 报告嘴型参数已被其他插件占用（或以其他错误拒绝注入）时，记录 `avatar.injection-stopped` 事实并在日志中报告，本实例停止注入、报告未就绪，不重试抢占；重新加载插件才再尝试。
- **表情**：`avatar@1` 的 `expression` 执行已授权的意图：意图须申请 `avatar.expression`，载荷为表情名；插件配置把表情名映射到 VTS 热键 ID，经 `HotkeyTriggerRequest` 触发。安全停止下闸门不授权，执行前再核对一次模式。P1 中没有调用方。
- VTS 画面用 OBS 自带的游戏采集（允许透明，配合 VTS 的透明输出）接入，不安装 OBS 插件。安全场景不包含形象画面，急停切场景即同时隐藏形象。
- 不把 TTS 音频再交给 VTS 的麦克风口型，避免两条路径不同步。
- Bellis 不包含 Live2D 代码；VTS 与模型的许可要求见[合规](../compliance.md#素材与数据)。
- VTS 未公布从注入到出画的延迟；音画偏差在 OBS 录制中实测后再定补偿方式，不提前输出尚未生成的内容。包络映射的上下限同样待真机调校。

## 公开展示层

投票、致谢、提示等观众可见信息放在另一个来源的页面，只读公开数据，没有控制能力和私密数据。

## 验收

| 阶段 | 内容 |
| --- | --- |
| P0 | 模拟 Stage：游标回报、欠载不推进游标、旧令牌音频被丢弃、心跳丢失自静音、会话令牌认证 |
| P1 | 真实 OBS 32.2.x：安全上下文与 AudioWorklet 可用；错误的 Host、Origin 与重放的令牌被拒；最小化或遮挡 30 分钟的欠载与漂移；来源隐藏后心跳丢失仍能自静音；停止到静音时延；字幕与口型偏差 |
| T1 | AI 标识常驻；开播预检通过 |
