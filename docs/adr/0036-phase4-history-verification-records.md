# ADR 0036：历史清单的核验批次与逐项结论

状态：持久核验记录及真实安装验证已完成；全量重验与安全解除未完成。日期：2026-09-07。

ADR 0034 的公开接口返回某一读取快照、某一时刻的 Recall 结论。ADR 0035 保存了完整原请求，但 HTTP 响应尚不能在宿主重启后用于核对进度。Bellis Migration 20 增加不可变核验批次及其清单项绑定，DB Worker 提供可信的记录与分页读取端口；模型、Stage 回执和普通 Memory Outbox 不获得写入此记录的权限。

批次保存独立 batchId、runId、完整清单摘要、`recall-current-v1` 核验方案、公开响应的 checkedAt，以及最多 16 项 ordinal/原请求摘要/requestId/valid 或 unavailable。一个批次中的 ordinal 与 requestId 均须唯一；同一原请求的不同准备尝试应安排在不同批次，不能把重复 requestId 塞入公共批量接口。单批正文最多 16 KiB。每个清单项至多归属一个批次，清单最多 4096 项，因此不会无限追加同项核验历史。

记录事务先取得写锁，再复核当前 scope/provider/gap/generation、全部原始清单事实及逐项原请求身份。只有摘要匹配的 `recall_request` 可以接受这个核验方案。新批次通过磁盘准入后，将批次与全部项绑定原子插入；部分插入失败整体回滚。相同批次的完整原输入可以去重；同 ID 改正文、已有项换批次或沿用旧清单均拒绝。若需要重新核验，应创建新的清单 run，旧 run 的结论随其义务一起删除，原始事实保留。

读取在一个本地快照中重新检查清单是否仍有效，核对已读取批次的正文摘要、身份、原请求绑定及全部成员；成员缺失在空页或已遍历到末尾时也不能伪装成尚未核验。未检查项明确返回 null，unavailable 保留独立状态。Provider 状态、迟到效果、真实 ACK 或策略变化导致清单失效时，旧结论读取和迟到响应写入均拒绝。

批次时间是远端结论的评估时间，不能当作跨批次共同快照、水位或新授权。持久记录证明可信调用者保存了这份响应及对应原请求绑定，不证明远端状态在读取时仍然相同，也不证明原请求已被模型采用。分页 done 仅表示遍历结束；一项或所有 Recall valid 都不清除历史缺口，不改 Usage/Observation ACK，不恢复投递。全部事实的公开核验、生产调度、跨批次一致性及原子安全解除仍是独立的未关闭要求。

验证覆盖真实 DB Worker 重启、原批次重试、valid/unavailable/未核验的区分、部分插入失败、损坏摘要/成员、清单与策略变化，以及公开 Core 响应落盘和再次重启读取。完整 Phase 4 Gate 继续开放。

最终根检查通过 1043 项单元/性质测试与 260 项集成测试，164 个生成契约无漂移；其中新增四项真实 Worker 集成测试。最终构建的 Core/Chromium 联合回归退出 0，工具及既有 24 组恢复冒烟通过，完整恢复入口继续退出 2。见 [本轮证据](../evidence/phase4-history-verification-probe.json)。
