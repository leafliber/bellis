# Bellis V2 架构概览

本文只定义不可妥协的安全边界、进程拓扑、快慢双主 Agent 事件流骨架与单仓边界。未到当前切片的细化设计不预先展开；待讨论拍板的细节显式标为 `OPEN`。

## 一、单仓边界与进程拓扑

单仓统一采用 **Python 3.12 + Rust**（仅 OBS Stage 与操作台网页为纯原生 HTML/JS）。合并仓库用于消除跨仓契约同步与重复造轮子，**物理安全边界仍由独立进程维持**：

```text
┌─────────────────── Host 进程（Python，非提权）────────────────────────┐
│ 【确定性安全与媒体底座】                                               │
│   安全核（闸门 · 单调 Lease 令牌 · 监督模式 · 急停） · SQLite WAL      │
│   操作台 / CLI（直连安全核） · OBS 应急连接 · 媒体管线(TTS→Stage→VTS)  │
│ 【慢主 Agent 事件流循环（~0.2–1Hz / 事件驱动）】                        │
│   弹幕/投票 · 公开记忆(Iris) · 播放游标回执 · 游戏离散事件              │
│   ──► 口播文本流(→媒体管线) · 游戏高层目标/暂停/选项决策(→快循环)        │
└────────────────────────┬─────────────────────────────▲────────────────┘
                         │ 极简本机通道(Py↔Py)          │ 许可续约/急停直连
                         ▼                             │（不经快循环转手）
┌── Game Agent（Python，非提权）─────────┐             │
│ 【快主 Agent 事件流循环（通用交互）】   │             │
│   读共享内存最新帧/VAD + 当前目标事件    │             │
│   → 轻量感知(CV/OCR/UI)                │             │
│   → 通用交互技能 / VLM / 未来 VLA       │             │
│   → 提交动作块 & 新帧效果核验           │             │
│   → 向慢循环上报离散语义事件            │             │
└───────────────────┬────────────────────┘             │
                    │ 共享内存(帧/音频) + 统一单套 RPC  │
                    ▼                                  ▼
┌── Realtime Core（Rust，按需提权，最小可信核）─────────┐
│ WGC 采集 · WASAPI 进程回环 · 共享内存写端              │
│ 唯一键鼠写入者：三方权威 · 持键账目 · SendInput · 钩子  │
└───────────────────────────────────────────────────────┘

┌── Watchdog（Rust 独立小二进制，非子进程）─────────────┐
│ 监听 Host 心跳；超时直连 obs-websocket 静音并切安全场景 │
└───────────────────────────────────────────────────────┘
```

- **独立练游戏模式**：只启动 `Game Agent` + `Realtime Core` + 极简 CLI/许可控制台，无需拉起直播模块。
- **纯直播模式**：只启动 `Host` + `Watchdog`，无需拉起 `Game Agent` 与 `Realtime Core`。
- **本地 TTS（可选降级）**：启用本地 PyTorch TTS 时以独立子进程按需拉起，隔离重型 CUDA 依赖。

## 二、不可妥协的 5 条安全底线

1. **确定性把关不可绕过**：所有对外动作（发声、切场景、键鼠输入）必须经安全核/实时核授权与单调递增 Lease 令牌核验；AI Agent 永不自授权限。
2. **控制通道独立（Out-of-Band）**：急停、暂停、许可吊销、OBS 热键触发与真人键鼠接管直接作用于安全核/实时核，绝不进入 Agent 普通事件队列排队。
3. **三方输入权威与 Fail-Closed 释放**：Rust 实时核仅在“有效输入许可 + 有效控制源心跳 + 帧龄未过期”同时成立时注入输入；失焦、断连、超时、真人接管或急停时立刻释放全部持键并核验物理抬起。
4. **不可信数据隔离（Rule of Two）**：弹幕、观众信息、游戏画面、OCR 与模型输出一律视为不可信数据，不接触凭据，不授予越权能力。
5. **副作用先落盘、重启不重做**：关键副作用经 SQLite WAL 先记意图再执行；重启只恢复状态，永不重放有时效的发声或键鼠操作。

## 三、快慢双主 Agent 事件流循环

智能层摒弃 V1 的三级 LLM 串行接力（Director → Planner → Vision Agent）与重型插件内核，收拢为两个主循环，并遵守以下硬约束：

- **慢主 Agent（System 2，主播与高层任务大脑）**：
  - 消费合并后的弹幕事件、投票事件、播放游标结果与游戏离散事件（完成/卡住/决策点/看点）。
  - 弹幕采用时间窗合并与有界丢旧，避免洪峰压垮推理；收到高优打断时取消当前在途生成。
  - 只向独立时钟的高频媒体管线输出文本流，并向快循环下发/取消高层目标，不逐帧参与播放或操控。
- **快主 Agent（System 1，通用游戏交互循环）**：
  - 画面采用共享内存**最新值覆盖（按需拉取）**，绝不将视频帧排入事件队列；仅离散控制/目标事件走有界队列。
  - 以**通用交互**而非视觉小说为核心，内部维持严格单向分层：`io -> perception -> skills -> loop`（禁止反向引用）。
  - 动作提交后基于新帧做独立效果核验；遇到未知界面、卡住或业务决策点时停止相关输入并上报离散事件。

## 四、装配、通道与遥测极简化

- **显式模块化装配**：各组件直接构造与依赖注入，关闭时按确定顺序执行 `quiesce()`/`close()`；零插件内核、零 Profile/Patch DSL。
- **单套通道与许可协议**：本机通道统一使用双向认证（Windows 命名管道 / POSIX UDS），只做传输与认证，不反向耦合业务解析；独立控制台与 Host 对 Rust 实时核使用**同一套许可控制协议**。
- **轻量遥测**：统一写入精简 JSONL（trace/span/耗时与关键属性），配极小统计脚本输出 p50/p95/p99；不自研 OTLP 闭合 Schema 校验器。

## 六、待对齐的架构细节（`OPEN`）

以下细节在 Step 1 动工前与维护者逐项拍板后再冻结：

1. **`OPEN-1` 单仓目录与检查门禁细节**：`core/`、`py/`、`web/`、`games/`、`tests/`、`lab/` 的具体边界，以及按路径分层的快速 check 与循环依赖/单文件行数红线脚本。
2. **`OPEN-2` 实时核统一单套协议设计**：Host 与独立控制台共用一套控制/许可协议的最小消息集，以及 Rust ↔ Python 共享内存头与 RPC 边界如何做到“零重型代码生成且跨语言不漂移”。
3. **`OPEN-3` 通用交互层的核心模型**：面向 HSR（菜单、对话、3D 探索、回合制战斗）及未来原神的统一动作空间、感知算子接口、技能原语与新帧核验闭环。
4. **`OPEN-4` 快慢双循环的事件契约与进程启停**：Host、Game Agent、Realtime Core、Watchdog 四进程由谁拉起、连接信息如何经凭据存储交付、慢↔快最小事件集定义。
5. **`OPEN-5` 直播底座移植节奏与优先级**：先跑通 HSR 独立闭环（Step 1→2）再迁入直播底座（Step 3），还是双线并行；本地 Watchdog 用 Rust 还是 Python 极简脚本。
