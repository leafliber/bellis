# 总体架构

本文描述 Bellis 的分层、进程、通道、事件与状态。各模块的细节见 [modules/](modules/)。下文的 D-xx 指[技术基线](plan/tech-baseline.md)中已批准的决策，R-xx 指技术路线；技术基线中仍为“待审核”的 R-xx，正文只写作“推荐”，批准前不是定论。

## 术语

| 术语 | 含义 |
| --- | --- |
| 意图 | 一次对外动作的申请，例如“播出一句话”“切到某场景”。所有副作用都先表达为意图，由安全核授权 |
| 执行许可 | 安全核授予执行器的短期许可（lease），带到期时间和递增令牌；执行器只在持有有效许可时动作 |
| 播放游标 | Stage 回报的“这句话实际播到了哪里” |
| Stage | 运行在 OBS 浏览器源里的页面，负责播放音频、显示字幕 |
| sidecar | 宿主管理的独立子进程，承担重计算或第三方代码 |
| profile | 决定启用哪些插件、用什么配置的组合 |
| 静止中 | 插件停用前的收尾状态：停止接新工作、吊销许可、等待物理确认 |
| 维护态 | 已切到安全场景、无人持有执行许可，此时才能替换关键平面 |
| VLA | 视觉-语言-动作模型：看画面、理解指令、直接输出操作 |

## 分层

```text
┌──────────────────────────── Bellis 宿主进程（非提权，用户交互会话）─────────────────────────────┐
│ 安全核（随宿主构建、启动时直接装配，不经过插件加载器，不可卸载）                                │
│   执行闸门 · 执行许可与急停 · OBS 应急连接 · 监督模式 · 速率与异常检测 · 状态存储                 │
│ 操作员入口（宿主装配，不经过插件加载器，不可热替换）                                            │
│   命令行（本机通道）、操作台（127.0.0.1 上的网页）                                              │
│ 插件内核                                                                                        │
│   服务与依赖激活 · 可撤销注册 · 生命周期(含静止中) · 事件分发 · 加载器 · profile/patch · 热替换   │
│ 关键平面（只在维护态替换）                                                                      │
│   发声仲裁 · Stage 服务 · OBS 控制                                                              │
│ 普通插件（可热替换）                                                                            │
│   决策模型 · 审核(可关闭) · 弹幕接入与分诊 · 投票 · 形象 · 记忆客户端 · 游戏桥 · 遥测              │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
      │本机通道 JSON-RPC           │loopback HTTP/WS          │HTTP+SSE        │本机通道
      ▼                            ▼                          ▼                ▼
 sidecar（Python 原生）       Stage 页面（OBS 浏览器源）     Iris 记忆服务     Game Runtime（独立仓库）
 TTS · 审核模型 · 本地模型   播放 · 字幕 · 回报播放游标     （独立仓库）       采集 · 感知 · VLA · 输入代理

 外部看门狗（独立进程，不是宿主的子进程）── obs-websocket ──► OBS
```

| 层 | 内容 | 能否替换 |
| --- | --- | --- |
| 安全核 | 授权所有对外动作、执行许可与急停、OBS 应急连接、监督模式、状态存储 | 不可卸载，永不热替换（D-15、D-19） |
| 操作员入口 | 命令行与本机操作台：调用同一套操作员动作，插件出问题时照样可用（见[运维](modules/operations.md#操作台)） | 随宿主发布，不经插件加载器，不可热替换 |
| 插件内核 | 让插件按依赖激活、注册可撤销、停用前安全收尾 | 随宿主发布 |
| 关键平面 | 发声仲裁、Stage 服务、OBS 控制：任何时刻只有一个实例在发声或控制场景 | 只在维护态替换 |
| 普通插件 | 其余能力 | 直播中可热替换 |
| sidecar | 重计算与第三方代码，独立进程 | 由宿主内的代理插件管理，崩溃即撤回其服务 |

宿主进程内只加载本项目的插件；第三方代码一律以 sidecar 接入（D-20）。同进程内的权限声明只能防误用，真正的安全边界在进程之间。宿主运行时为 Node 26 LTS + TypeScript（R-01）。

## 进程与部署

先单机部署（D-22），除 Iris 以 Docker 部署在本机外，全部 Windows 原生运行（D-23）：

| 进程 | 运行身份 | 说明 |
| --- | --- | --- |
| 启动器 | 当前用户、交互会话 | 由“登录时运行”的计划任务启动，分别拉起宿主与看门狗，并把本次会话的连接信息写入 SecretStore（R-23） |
| Bellis 宿主 | 当前用户、交互会话、非提权 | 由启动器拉起；不做 Windows 服务（服务运行在 Session 0，无法和桌面交互） |
| sidecar | 宿主的子进程 | 本地 TTS、审核模型、本地模型等 |
| 外部看门狗 | 由启动器拉起，不是宿主的子进程 | 宿主崩溃后仍然存活；宿主心跳丢失时经 obs-websocket 静音并切安全场景，并呼叫操作员（R-14） |
| OBS Studio 32.2.x | 当前用户 | Stage 页面作为浏览器源运行其中（D-24） |
| VTube Studio | 当前用户 | 形象，宿主经其 WebSocket API 注入参数 |
| Iris | 本机 Docker 容器，由维护者启动 | 长期记忆，HTTP + SSE；端口只映射到 127.0.0.1 |
| Game Runtime | 独立进程，游戏需要时提权 | 无法由非提权宿主拉起；宿主始终不提权，并作为本机通道的服务端 |

非子进程（看门狗、Game Runtime）从 SecretStore 读取本次会话的连接信息（R-23）。宿主与看门狗共用一份配置文件（存储位置、心跳、安全核参数、应急目标），不含凭据；OBS 的地址与密码也在 SecretStore 中。仓库自带 `config/sim.json`，`sim` 配置下由启动器运行模拟 OBS。是否增加独立推理机，在真机测出 GPU 争用后再定（[探针](plan/spikes.md) S-02）。

## 三条通道

| 通道 | 内容 | 规则 |
| --- | --- | --- |
| 控制通道 | 停止、急停、切安全场景、打断 | 独立队列，不经过决策模型，不排在普通事件或音频数据之后 |
| 实时通道 | 音频播放、游戏控制 | 时钟由 Stage 的 AudioWorklet 或 Game Runtime 持有；Bellis 只下发目标和执行许可，不逐帧参与 |
| 慢速通道 | 决策模型、记忆召回、摘要 | 随时可取消；任何等待都带截止时间 |

## 编排模型

采用混合模型（D-16）：

- **决策状态用 reducer。** 发言队列、投票、监督模式等由纯函数归约，可以从事件日志完整重放。
- **设备与连接用 actor。** Stage 连接、OBS 连接、sidecar、Game Runtime 连接各有唯一所有者和邮箱，生命周期与资源清理都归它管。
- **语音用数据流管线。** 文本流 → 分句 → （可选）审核 → TTS → 播放，各级之间有界、可背压、可取消。

每个任务树挂在一个取消作用域下，取消向下传播；每次等待都有截止时间。

## 事件

| 域 | 用途 | 规则 |
| --- | --- | --- |
| 持久事实 | 已经发生、重启后仍需存在的事实 | 命名为 `对象.过去式`，例如 `utterance.played`；先写入状态存储再广播 |
| 扩展点 | 进程内拦截与策略挂接 | 按分发模式声明，见[插件内核](modules/plugin-kernel.md) |
| 控制信号 | 停止、急停、维护态切换 | 只走控制通道 |

命令命名为 `对象.动作`，例如 `speech.request`。

## 状态与重启

单个 SQLite（WAL）文件保存事件、投影与意图（D-17）。副作用先写意图再执行；重启只回放事件重建状态，永不重做说话或游戏输入这类有时效的动作。详见[状态存储](modules/state-store.md)。

## 发声链路

```text
决策模型文本流 ─► 分句与双文本 ─► 发声前检查（审核插件，可关闭）─► 发声仲裁 ─► TTS 插件 ─► 云端或本地 TTS
                                                                      │                        │
                                         持有 Stage 音频输出许可，按来源定优先级          音频回到宿主
                                                                      ▼                        ▼
                                                                   Stage 服务（核验许可令牌）─► Stage 页面
                                                                                                    │
                                              字幕与口型按播放游标推进 ◄── 回报播放游标 ◄───────────┘
```

审核是可关闭的普通插件，启用时用独立的审核模型逐句判定一次（D-18）。音频经宿主转发，Stage 服务只转发带有效许可令牌的音频帧（D-21、D-31）。被抢占或停止的发言按播放游标截断，上下文只记录观众实际听到的部分。详见[发声](modules/speech.md)、[审核插件](modules/moderation.md)与 [Stage](modules/stage.md)。

## 游戏控制分层

| 层 | 归属 | 频率（参考量级，待测） | 职责 |
| --- | --- | --- | --- |
| G4 主播决策 | Bellis | 事件驱动，约 0.1–1Hz | 人格、观众、投票、选择交给游戏的目标、解说 |
| G3 规划与理解 | Game Runtime | 约每秒一次或事件触发 | 剧情理解、子目标、识别决策点 |
| G2 快策略 | Game Runtime | 观测 5–10Hz，动作块约 30Hz | VLA 异步执行动作块 |
| G1 输入代理 | Game Runtime（受信） | 60Hz 以上 | 时序调度、持有输入许可、白名单检查 |
| G0 急停 | Game Runtime 与物理热键 | 持续 | 释放全部输入 |

频率参考公开研究的量级。Bellis 与 Game Runtime 之间只传语言子目标和结构化字段，输入许可短周期续约，过期即释放全部输入（D-27），详见[游戏桥](modules/game-bridge.md)。

## 监督模式

| 模式 | 含义 |
| --- | --- |
| M0 仿真 | 只连模拟设备；`sim` profile 下唯一允许的模式 |
| M1 严格 | 真实输出；逐句人工放行，或固定延迟加一键否决 |
| M2 在场 | 操作员在场、可随时急停 |
| M3 无人值守 | 自动安全机制代替人工在场 |
| 安全停止 | 不产生新输出，已切安全场景，等待操作员 |

升级只能由操作员执行；安全核可以自动降级。详见[安全核](modules/safety-core.md)。

## 时延目标

以下是初始目标，以 Windows 真机实测为准，没有实测的仍为 PENDING：

| 指标 | 目标 | Windows 真机实测 |
| --- | --- | --- |
| 停止到静音 | ≤200ms | P1：p50 52ms，最大 59ms（9 次，OBS 32.2.2） |
| 操作员急停到安全场景 | ≤1s | P1：p50 16.7ms，最大 18.2ms（10 次，到 OBS 执行完 RequestBatch） |
| 宿主卡死到看门狗切安全场景 | 心跳超时（初值 1s）加 OBS 执行时间 | P1：p50 771ms，最大 1007ms（10 次，挂起宿主进程） |
| 弹幕到首个音频 | p95 ≤4s（观众端拉流本身有数秒延迟） | PENDING（P2） |
| 输入许可过期到全部按键释放 | ≤100ms | PENDING（P3） |

Windows 11 x64 是唯一的生产平台；P0 在 macOS 验收，P1 起只认 Windows（D-11）。工程约束见 [Windows 平台](platform/windows.md)。
