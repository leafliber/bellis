# P1 任务卡：无模型的增量媒体闭环

**前置：**P0 门禁 PASS。

**目标：**固定合法文本与 PCM 分批进入 Stage，首段在 EOS 前输出；播放期间可停止，刷新后不重播旧流，能查询输出与清理事实。

**契约：**[P1 契约简报](../generated/P1.md)列出本阶段的媒体状态机（Scene、Utterance、UtteranceAdmission、Segment、AudioProduction、TextPresentation）和配对状态机 StagePairing、守卫、不变量与测试 ID、命令、事件和字段结构；StopOperation 复用 P0。

**必读规范：**第 11.5–11.6、12、17.2、17.4、17.8、19、20.5、21.1、21.3–21.4、21.6、24.1、24.5 节，附录A.14。

## 步骤

1. **先跑平台探针。**用固定 localhost Origin 的浏览器探针验证密钥持久与 AudioWorklet 基础，再在目标 OBS/CEF 跑同一页面（见[技术探针](spikes.md) S-1、S-2）。S-1/S-2 未通过时，只允许在受控本地测试中人工重新配对，不宣称持久配对或真实输出水位成立。
2. **实现媒体对象与追加规则。**在 `packages/scene-runtime/` 按记录绑定实现 Scene、Utterance、UtteranceAdmission、Segment、AudioProduction、TextPresentation。先用固定合法文本和固定许可，不把模型或 TTS 的外部变量混入首个闭环。
3. **实现受信 Stage 与配对。**在 `apps/stage/` 接入有限控制消息和媒体缓冲，实现 StagePairing、角色/Origin 校验、短连接凭据，以及新实例与旧许可的隔离；Overlay 不共享凭据。IndexedDB 能保存密钥不等于已获播出授权。
4. **实现有限媒体管线。**固定 PCM 分批送入，覆盖乱序、重包、缺包和 EOS，明确 segment 与 utterance 两种作用域；首段在 EOS 前输出；欠载补零不推进内容游标。字幕由已审双文本和真实（或注明误差）的内容位置驱动。
5. **先测停止，再测正常完成。**覆盖软收尾的尾部 ACK、零已播、停止与自然完成竞争、QUEUED 子效果未知、Stage 刷新不重播。媒体清理在媒体契约内闭合；完整 Settlement 服务属于 P3。
6. **测容量与依赖，收集证据。**在模拟弹幕输入、慢消费者和满缓冲下确认停止通道持续可用；normal 依赖不能由过渡语或 text_only 满足。保留真实 OBS 输出、音画与失败样本；普通 Chrome 通过不能代替 OBS 证据。

## 完成判据

`pnpm gate --phase P1 --evidence <证据文件>` 返回 PASS（自动包含 P0）。
