# P1 任务卡：真实媒体

**目标**：在 Windows 真机的 OBS 中，固定文本能真实发声、出字幕、驱动口型；停止、急停与看门狗在真实 OBS 上实测可靠；本地降级 TTS 以 sidecar 接入，崩溃可恢复。

**平台**：在 Windows 11 x64 真机上验收（D-11）。Windows、macOS、Linux 三平台 CI 照常运行完整检查并必须通过；模拟通过不等于真机通过。

**必读**：[愿景](../vision.md)、[总体架构](../architecture.md)、[Stage、OBS 与形象](../modules/stage.md)、[发声](../modules/speech.md)、[安全核](../modules/safety-core.md)、[运维](../modules/operations.md)中的开播预检与确定性仿真两节、[插件内核](../modules/plugin-kernel.md)中的 sidecar 代理一节、[Windows 平台](../platform/windows.md)、[真机探针](spikes.md)、[合规](../compliance.md)中与 TTS 和素材有关的条目。

## 范围

## 步骤

1. **凭据录入与真实配置。** 实现维护者自己录入凭据的命令（设置、删除、列出）：值从不回显的输入读取，不打印、不写日志，列出时只显示名字。给出真实配置与 profile 的样例，只含脱敏占位值；真实配置不入库。

2. **真机探针。** 跑 S-06、S-05、S-10、S-01、S-03、S-07、S-02，方法与记录要求见[探针](spikes.md)。
   - S-10、S-01、S-02 需要 OBS；S-03、S-05 的 sidecar 部分、S-07 的本地部分、S-02 需要 Python sidecar 工具链已批准；S-07 的云端部分需要密钥已录入、外发已同意。
   - S-02、S-07 在游戏运行时测，用目标游戏中负载最重的一款。
   - 后续步骤以对应探针有结果为前提：第 3 步看 S-10，第 4 步看 S-01，第 5 步看 S-07 的云端部分，第 6 步看 S-03、S-05、S-07 的本地部分与 S-02。
   - 探针结论改变设计时，直接改对应模块文档与技术基线；需要改选路线的交维护者决定，本任务卡的后续步骤随之调整。

3. **真实 OBS 与看门狗。**
   - 安全核的 OBS 应急连接与看门狗接真实 OBS 32.2.x，用 SecretStore 中的密码认证。
   - 宿主内的 OBS 控制（切场景、静音源、写浏览器源设置）每次操作都持有执行许可。
   - 看门狗执行过应急动作后告知宿主，宿主据此进入安全停止并记录事件；不再只靠“断开即急停”兜底。
   - 模拟 OBS 改用 `ws`（R-08），去掉自写的 WebSocket 服务端。

4. **Stage。** 按 R-08、R-09 实现真实 Stage 页面与 Stage 服务，取代模拟 Stage 用于真实 profile。
   - 页面经 `node:http` 在 `127.0.0.1` 的随机端口提供；每个请求与升级都严格校验 Host 与 Origin；一次性令牌经 OBS 控制写进浏览器源 URL 的片段，页面出示后换成只存于内存的会话密钥；同时只允许一个会话。
   - AudioWorklet 播放；许可时长与心跳按已渲染的样本帧计时；旧令牌的音频丢弃；收不到心跳自静音；回报播放游标。字幕随游标推进，用 `textContent` 渲染。
   - OBS 与浏览器内核版本写进握手。
   - Host、Origin、令牌重放与第二个会话的拒绝有自动化测试，在三平台 CI 运行。

5. **云端 TTS 与字幕对齐。**
   - 按 R-10 自写不绑定厂商的 TTS 插件，以 `tts@1` 接 MiniMax 与火山引擎的双向流式接口：增量出音频、中途取消、字/词级时间戳。
   - 外发只在 profile 显式开启后启用，只发送已通过发声前检查的朗读文本；没有登记算法备案编号的厂商不启用。
   - 主备按 S-07 的结论配置。主引擎不可用时按 profile 切到备用或只出字幕，切换记入事件日志并提示操作员。
   - 按 R-11 实现两段式对齐：句段一到即按字数插值，随后用 TTS 返回的时间戳细化。

6. **本地降级 TTS sidecar。**
   - 按 R-10 以 sidecar 运行 Qwen3-TTS；TTS 代理插件把 sidecar 的 RPC 与二进制音频适配成 `tts@1`。
   - 本地合成的句段用 Qwen3-ForcedAligner 细化对齐（R-11）。
   - 按 D-21 由 TypeBox 生成 Pydantic 模型；sidecar 用 Job Object 管住自己派生的进程（R-06）。

7. **形象。** 按 R-15 接 VTube Studio 插件 API。
   - 插件令牌经 VTS 弹窗由维护者允许后存入 SecretStore。
   - 按播放游标以 30–60Hz 注入嘴型参数，声明已检测到面部，每个参数至少每秒重发一次；表情经热键接口触发；参数已被其他插件占用时报告，不抢写。
   - VTS 画面经 OBS 自带的游戏采集接入，安全场景不含形象。调试用 Live2D 官方免费素材模型，遵守其条款。

8. **真实输出模式与开播预检。**
   - M1 采用固定延迟加否决：每句播出前等待 profile 配置的延迟，期间操作员可用 `pnpm operator veto` 否决；被否决的句子不播出，并记入事件日志。
   - 真实 profile 显式关闭审核插件（真实审核模型在 P2，R-12），关闭状态常显并记录。
   - 实现开播预检中与 P1 相关的项：监督模式有效、安全场景与 Stage 静音目标存在、看门狗已连接、Stage 已认证、审核插件状态已显式设置、TTS 与形象按 profile 就绪。任一失败都不允许进入 M1、M2。

9. **登录时运行。** 按 R-23 用“登录时运行”的计划任务拉起启动器，提供注册与注销命令。

10. **实测与演练。** 在真机上完成下面出口中的全部实测与演练，结果写入 `reports/`。

## 出口

以下全部在 Windows 11 真机上实际运行通过，且三平台 CI 绿：

**平台**
- P0 的全部测试与固定种子仿真在真机上重跑通过。
- 计划任务在登录后拉起启动器，宿主、看门狗与真实 OBS 连接成功。
- 真实密钥只经录入命令写入 SecretStore，不出现在日志、事件和报告中。

**OBS 与安全核**
- 停止到静音、急停到安全场景的时延实测，与[时延目标](../architecture.md#时延目标)对照。
- 宿主崩溃、事件循环阻塞、管道断开三种情况下，看门狗到安全场景的时间实测；看门狗动作过后，宿主进入安全停止。
- M1 与 M2 下固定文本真实播出；M1 中被否决的句子没有播出；急停后没有新的输出。
- 开播预检任一项失败时无法进入 M1、M2。

**Stage**
- OBS 浏览器源中安全上下文、AudioWorklet 可用；错误的 Host、Origin、重放的令牌与第二个会话都被拒绝。
- OBS 最小化或被游戏遮挡 30 分钟，播放无欠载与音高漂移（OBS 录制比对）。
- 来源隐藏超过 5 分钟后，心跳丢失时页面仍能自静音。
- 页面刷新或导航后，声音仍只经 OBS 输出。

**发声与形象**
- 云端 TTS 的首包与取消实测（S-07 的指标）；主备切换与只出字幕的降级各演练一次。
- 时间戳与对齐结果相对人工标注的字偏差实测；字幕、口型与音频的偏差在 OBS 录制中实测。
- 被打断的发言，上下文只包含真实 Stage 回报已播出的部分。
- 宿主失联后口型在 1 秒内归位；急停切到安全场景后形象不可见。

**sidecar**
- 本地 TTS sidecar 崩溃与恢复演练：服务被撤回，依赖方回到 WAITING，按 profile 降级，重启后恢复；它派生的进程随之退出。

实测指标报告样本数与 p50/p95/p99，失败样本不剔除；目标数值在实测前仍为 PENDING。
