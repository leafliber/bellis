# 真机探针

探针用来验证会影响设计的外部假设，结果不能替代阶段验收。所有探针都在目标 Windows 真机上运行，记录日期、系统与驱动版本、OBS 版本、命令、样本数、原始结果与限制。探针脚本放在仓库的 `spikes/` 下，与其他代码一样通过完整检查；结果写入 `reports/`（不入库），报告引用运行的命令。探针结论改变设计时，直接修改对应模块文档和[技术基线](tech-baseline.md)。

| 编号 | 要验证的假设 | 方法 | 不成立时的影响 | 阶段 |
| --- | --- | --- | --- | --- |
| S-01 | OBS 32.2.x 浏览器源中，经 `http://127.0.0.1` 加载的 Stage 页面处于安全上下文，AudioWorklet、WebCrypto 可用；开启“Control audio via OBS”后，OBS 最小化或被游戏遮挡 30 分钟无欠载与音高漂移；来源隐藏超过 5 分钟时心跳丢失仍能自静音；页面刷新或导航后声音不绕过 OBS | 页面自检加长时间播放已知 PCM，OBS 录制回环比对，游标对照墙钟与录制；另测错误 Host、Origin 与重放令牌被拒 | 改选音频路由（R-09）或调整运行要求 | P1 |
| S-02 | 单机能同时承载游戏、OBS 编码、TTS 与本地模型 | 游戏限 60fps，测 OBS 渲染丢帧、TTS 首包、显存；对比 HAGS 开关、OBS 是否管理员运行、显存回落设置 | 决定是否加推理机（D-22） | 暂缓（见 [P1](P1.md#范围)） |
| S-03 | 命名管道满足控制面需求，且未认证者拿不到数据 | Node↔Python 往返时延 p50/p99，对比 127.0.0.1 TCP；另一本地用户与远程访问的可达性；抢注时的告警 | 调整通道认证或改用其它通道 | P1 |
| S-04 | 非提权宿主与提权的 Game Runtime 能正常互通；OBS 能采集提权运行的游戏 | 管道连接与认证；OBS 游戏采集与窗口采集各试一次 | 调整进程身份与部署方式 | P3 |
| S-05 | 宿主定时与 sidecar 推理不受 Windows 节流显著影响 | Node `setTimeout` 实际延迟分布；sidecar 被归为 EcoQoS 前后的推理时延 | 调整调度方式或进程设置 | P1 |
| S-06 | SQLite 在 Windows NTFS 上的崩溃窗口符合状态存储的重启语义 | 在每个写入点强制终止进程后重启核对；磁盘满注入 | 调整写入与确认顺序 | P1 |
| S-07 | 云端 TTS（MiniMax、火山引擎）与本地降级（Qwen3-TTS）在游戏与 OBS 编码同时运行时能增量出首包、真正取消，时间戳可用 | 固定短句与取消样本：提交到首个 PCM、到 Stage 游标起步的时间（p50/p95，冷启动与热启动，整句提交与流式提交）；取消到最后一个字节的时间与之后仍到达的音频时长；云端取消后是否仍计费、会话能否复用、网络抖动与重连时间；时间戳到达时机及对约 20 句人工标注的字偏差；本地另记实时率、显存峰值与游戏帧时间变化 | 定主备厂商；改选 TTS 或调整降级策略（R-10、R-11） | P1 |
| S-08 | 候选审核模型能在逐句预算内给出判定，准确率可接受 | 中文红队语料（谐音、拼音、emoji、分步诱导、昵称注入）与正常语料，统计延迟、召回与误判 | 改选审核模型（R-12） | 暂缓，随 R-12 |
| S-09 | iris-core 在本机 Docker 中稳定运行，宿主经 127.0.0.1 访问，召回在预算内 | 按 iris-core 的发布版以容器部署，端口只映射到 127.0.0.1；宿主接口契约测试（写入的幂等、召回准备、定向查询、使用反馈）；召回判断关闭与打开时的延迟分布；重启容器后数据仍在 | 调整 Iris 部署方式或推迟接入 | P2 |
| S-10 | 看门狗在宿主卡死或崩溃时及时切安全场景 | 分别模拟宿主崩溃、事件循环阻塞、管道断开，测到安全场景的时间 | 调整心跳周期或看门狗形态 | P1 |
| S-11 | 决策模型（R-17）流式输出时首 token 与首个可用意图够快，结构化输出可靠，取消即停 | 用决策插件真实的提示词组装、模型客户端与合成的弹幕上下文样本（`spikes/s11-llm.ts`），GLM-5.3-flash（`reasoning_effort: low`）与方舟上一款可关思考、支持结构化输出的型号各测：请求到首个 token（第一个数据块，含思考）、到首个正文 token（不含思考）、到意图完整（累计输出第一次能解析并通过校验）的时间（p50/p95，冷与热；冷指距上一个请求超过连接保活、要新建连接）；思考 token 数；`json_schema`、`json_object`、指定函数调用与只靠提示词各自的可用性（被拒的错误如实记录）与合法输出比例；中途取消后是否仍有输出；计费在流里看不到，到方舟控制台按请求核对 | 换决策模型型号，或调整弹幕到首音的目标（R-17） | P2 |
