# 真机探针

探针用来验证会影响设计的外部假设，结果不能替代阶段验收。所有探针都在目标 Windows 真机上运行，记录日期、系统与驱动版本、OBS 版本、命令、样本数、原始结果与限制；结果写入 `reports/`（不入库）。探针结论改变设计时，直接修改对应模块文档和[技术基线](tech-baseline.md)。

| 编号 | 要验证的假设 | 方法 | 不成立时的影响 | 阶段 |
| --- | --- | --- | --- | --- |
| S-01 | OBS 32.2.x 浏览器源中，经 loopback HTTP 加载的 Stage 页面处于安全上下文，AudioWorklet、WebCrypto、IndexedDB 可用；开启“Control audio via OBS”后，OBS 最小化或被遮挡 30 分钟无欠载与音高漂移 | 页面自检加长时间播放已知 PCM，OBS 录制回环比对；Win10 与 Win11 各测一次 | 改选音频路由（R-09）或调整运行要求 | P1 |
| S-02 | 单机能同时承载游戏、OBS 编码、TTS 与 L1 审核 | 游戏限 60fps，测 OBS 渲染丢帧、TTS 首包、显存；对比 HAGS 开关、OBS 是否管理员运行、显存回落设置 | 决定是否加推理机（D-22） | P1 |
| S-03 | 命名管道满足控制面需求，且未认证者拿不到数据 | Node↔Python 往返时延 p50/p99，对比 127.0.0.1 TCP；另一本地用户与远程访问的可达性；抢注时的告警 | 调整通道认证或改用其它通道 | P1 |
| S-04 | 非提权宿主与提权的 Game Runtime 能正常互通；OBS 能采集提权运行的游戏 | 管道连接与认证；OBS 游戏采集与窗口采集各试一次 | 调整进程身份与部署方式 | P3 |
| S-05 | 宿主定时与 sidecar 推理不受 Windows 节流显著影响 | Node `setTimeout` 实际延迟分布；sidecar 被归为 EcoQoS 前后的推理时延 | 调整调度方式或进程设置 | P1 |
| S-06 | SQLite 在 Windows NTFS 上的崩溃窗口符合状态存储的重启语义 | 在每个写入点强制终止进程后重启核对；磁盘满注入 | 调整写入与确认顺序 | P1 |
| S-07 | 候选 TTS 能增量出首包并真正取消 | 固定短句与取消样本，记录首个可解码包时间、取消后是否仍有数据 | 改选 TTS 或调整降级策略（R-10） | P1 |
| S-08 | L1 审核在逐句预算内给出判定，召回率可接受 | 中文红队语料（谐音、拼音、emoji、分步诱导、昵称注入）与正常语料，统计延迟与召回、误报 | 改选模型或调整 L2 策略（R-12、R-13） | P2 |
| S-09 | iris-core 能在 Windows 原生稳定运行，召回在预算内 | 安装运行、主机接口契约测试、召回延迟分布 | 调整 Iris 部署方式或推迟接入 | P2 |
| S-10 | 看门狗在宿主卡死或崩溃时及时切安全场景 | 分别模拟宿主崩溃、事件循环阻塞、管道断开，测到安全场景的时间 | 调整心跳周期或看门狗形态 | P1 |
