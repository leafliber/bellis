# P0 任务卡：安全骨架

**目标：**有限消息进入宿主，经真实守卫授权后驱动可观测的假设备；撤权能停止，旧授权与重复消息不能增加效果，结果和清理事实可查询。

**契约：**[P0 契约简报](../generated/P0.md)列出本阶段的 3 个状态机（SupervisionMode、ExecutionGrant、StopOperation）、守卫、不变量与测试 ID、命令、事件、错误码和字段结构。

**必读规范：**第 4.11、5.3、7.9、11、20.1–20.2、22.2、22.5–22.6、25.4、25.7 节。

**当前状态：**契约 SDK、模拟端点和工具测试已具备；第 2 步的真实宿主职责和第 3–6 步都未实现。工具检查通过不等于 P0 完成。

## 步骤

每步交付可执行的命令、使用的版本、期望结果与实际结果；不用“有接口”代替“已实现”。

1. **复现环境。**按 [AGENTS.md](../../AGENTS.md#命令) 安装并跑通 `pnpm check`。阅读 `packages/contract-sdk/src/index.ts`：输入一律先用生成的校验器验证、使用生成的类型，不要另写 Manifest 或记录类型。
2. **接一对有限协议端点。**先用 `SimulationEndpoint` 和 `tools/simulate-plugin.ts` 验证握手、摘要不兼容、错误信封、operation 去重、有限 stdio framing 和日志分离。再为真实宿主实现受信安装清单、进程监督、断线重连和授权。方法与载荷只引用 `commands.json`；握手不是执行授权。
3. **实现宿主的安全归约与假设备。**在 `packages/runtime/` 实现 SupervisionMode、ExecutionGrant、StopOperation，复用 SDK 的 `transition()` 转换表。先实现本地撤权栅栏和独立清理责任，再接审计与数据库。假设备要有可观测的许可、输出队列和停止状态，并能模拟：不回 cancel、ACK 乱序、自然完成与停止竞争、数据库失败。守卫必须是真实校验。
4. **落实有限执行范围。**分别核验 Manifest、RuntimeProfile、阶段闭包和消息 scope；默认禁用所有真实效果。验证旧实例、旧代次、过期授权与重复命令都不会增加效果；test_only、public 和监督模式三个维度保持独立。
5. **建立存储边界。**为授权与停止事实实现事务和 Outbox（SQLite，见[技术基线](tech-baseline.md)）；安全栅栏不能等待事务成功。通用 Task/Attempt/Effect/Settlement 表属于 P3，本阶段不做。
6. **执行 P0 门禁。**把真实测试绑定到 `verification.json` 中已登记的测试 ID，填写 runner 与实现状态，提交运行证据。

## 完成判据

`pnpm gate --phase P0 --evidence <证据文件>` 返回 PASS：简报中的全部 `sut.*` 测试和 `exit.P0` 已实现并在当前契约源上通过，证据文件位于 `reports/` 且哈希匹配。现有 SDK 模拟测试不能替代 `sut.*` 或 `exit.P0`。
