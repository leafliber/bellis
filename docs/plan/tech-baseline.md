# 技术基线与路线审核

本文件是 Bellis 技术选型的唯一登记处。规则：

- 只有“已批准”的决策和路线可以写进架构、模块文档与任务卡，作为实现依据。
- 需要新选型时，先在“待审核路线”登记候选、推荐与依据，由维护者审核；审核前不得在代码或文档中把候选写成定论。
- 批准、否决或改选都直接修改本表对应行，不另写评审记录。

## 待审核路线

候选按推荐顺序排列；“何时需要”是最晚必须定下的阶段。

| 编号 | 模块 | 候选（首项为推荐） | 依据与取舍 | 何时需要 |
| --- | --- | --- | --- | --- |
| R-01 | 宿主运行时 | Node 24 LTS + TypeScript（类型剥离直接运行，tsc 只做类型检查） | 与 dsh 同栈；Windows 支持成熟。开工时复核 Node 各版本的 LTS 状态 | P0 开工前 |
| R-02 | 工程工具 | pnpm workspace、node:test、Biome | 依赖少、三平台一致；需要属性测试时再加 fast-check | P0 开工前 |
| R-03 | Schema 库 | TypeBox / Zod 4 | TypeBox 本身就是 JSON Schema，生成链最短；Zod 4 生态更大，`toJSONSchema` 默认 2020-12 | P0 开工前 |
| R-04 | SQLite 驱动 | `node:sqlite`（Node 内置）/ better-sqlite3 | 内置模块免原生编译；better-sqlite3 更成熟。需确认所选 Node 版本中内置模块的稳定度 | P0 |
| R-05 | 本机通道认证 | 每次启动生成随机管道名与共享密钥，经环境变量交给子进程，HMAC 双向挑战 / Ed25519 签名 | 威胁模型不含同用户恶意进程，HMAC 已能防错连与抢注；Ed25519 适合将来跨机 | P0 |
| R-06 | 子进程寿命 | 先发 RPC shutdown，再关 stdin 让子进程读到 EOF 自退，超时 kill；sidecar 用 Job Object 管自己的孙进程 | Windows 的 kill 等于强制终止、没有宽限期；libuv 只保证“父死子亡”，不管孙进程 | P0 |
| R-07 | 确定性仿真 | 自研：时钟、随机数、传输与所有外部服务都作为插件服务，sim profile 用种子驱动调度 | 参照 TigerBeetle VOPR 与 dsh 的 llm-replay；无需外部框架 | P0 |
| R-08 | Stage 连接与认证 | 宿主经 loopback HTTP 提供页面，localhost WebSocket + 一次性会话令牌；页面 URL 不带长期凭据 | 浏览器源不能用命名管道；须在安全上下文中运行 | P1 |
| R-09 | Stage 音频路由 | OBS 浏览器源 + “Control audio via OBS” + AudioWorklet / 虚拟声卡 | 只有前者能被 OBS 静音和切场景直接控制；Win11 最小化或遮挡时有音频失真报告，需探针 S-01。按 D-24 不写 OBS 插件 | P1 |
| R-10 | TTS 引擎 | CosyVoice 3 / Qwen3-TTS / GPT-SoVITS / MiniMax 或豆包云端 | 据各项目自述：前两者 Apache-2.0、支持中日文与流式；GPT-SoVITS 适合角色音色但只到句级；云端带字级时间戳，需外发许可。首包与取消以探针 S-07 为准 | P1 |
| R-11 | 字幕时间对齐 | TTS 自带时间戳 / Qwen3-ForcedAligner / 退化为整句字幕 | 本地开源 TTS 普遍不出时间戳 | P1 |
| R-12 | L1 审核模型 | Qwen3Guard-Stream（0.6B 或 4B，本地）/ 云端中文审核 | 逐 token 打分、含“有争议”档；Stream 版暂不支持 vLLM，需实测延迟 | P1 |
| R-13 | L2 审核 | 直接丢弃“有争议”句 / Qwen3Guard-Gen 复判 / 云端复判 | 丢弃最安全但损失表达；复判增加延迟 | P1 |
| R-14 | 外部看门狗 | 独立 Node 小进程，经 obs-websocket 5 一次 RequestBatch：静音 Stage 源 + 切安全场景（必要时停流） | 不依赖宿主与 Stage 存活；P0 对接模拟 OBS | P0 |
| R-15 | 形象 | VTube Studio API，口型参数按 Stage 播放游标注入，≥30Hz 并每秒心跳 | 不把 TTS 音频再交给 VTS 麦克风口型，避免两条路径不同步；Live2D“可扩展应用”许可需另行确认 | P1 |
| R-16 | SecretStore 实现库 | @napi-rs/keyring（凭据管理器与 Keychain）+ DPAPI 原生绑定 | keytar 已归档；DPAPI 无纯 JS 方案 | P1 |
| R-17 | 决策 LLM | 已备案的云端模型 / 本地开源模型 | 合规要求对公众输出使用已备案模型；本地模型与游戏、OBS 争 GPU | P2 |
| R-18 | 弹幕接入 | B 站直播开放平台（open_id、HMAC 签名、项目心跳） | 官方接口；不提供 uid，以 open_id 作稳定身份 | P2 |
| R-19 | Iris 客户端 | 按 iris-core HTTP 契约自写薄客户端（HTTP + SSE） | iris-connectors 的 TS 客户端为 AGPL-3.0，直接引入会影响 Bellis 的许可 | P2 |
| R-20 | 操作台 | 本机 Web 页（独立 Origin）/ 桌面壳 | Web 页最轻；急停不能只依赖操作台 | P2 |
| R-21 | 遥测 | OpenTelemetry，GenAI 语义约定锁定版本，自定义属性用 `bellis.*` | agent 相关 span 仍处于 Development 状态 | P2 |
| R-22 | 打包与分发 | 暂不定（候选：Node SEA、安装器、签名） | 个人开发者的代码签名渠道受地区限制；试播前再定 | T1 前 |
| R-23 | 进程启动与连接信息分发 | 一个轻量启动器由“登录时运行”的计划任务启动，分别拉起宿主与看门狗（看门狗不是宿主的子进程）；本次会话的管道名与密钥写入 SecretStore，供看门狗和单独启动的 Game Runtime 读取 / 宿主与看门狗各由计划任务启动 | 看门狗必须在宿主崩溃后存活；提权的 Game Runtime 无法由非提权宿主拉起；不做 Windows 服务（Session 0 无法与桌面交互） | P0 |

Game Runtime 的采集、OCR、VLM、输入代理与 VLA 路线在其仓库登记和审核，不在本表。
