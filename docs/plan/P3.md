# P3 任务卡：游戏桥与魔女审判

**目标**：与 Game Runtime 冻结游戏桥契约，实现游戏桥插件与游戏输入许可；决策模型在《魔法少女的魔女审判》的决策点上投票或自选、在看点处解说；在私有测试直播间里由 AI 自主推进一段完整剧情，操作员全程在场；急停、许可过期与真人接管后全部输入释放的时延实测。

**平台**：在 Windows 11 x64 真机上验收（D-11）；Game Runtime 与游戏在同一台机器上运行，《魔女审判》不需要提权（Game Runtime 的 GS-05）；Iris 同 P2（D-23）。Windows、macOS、Linux 三平台 CI 照常运行完整检查并必须通过；模拟通过不等于真机通过。

**必读**：[愿景](../vision.md)、[总体架构](../architecture.md)中的游戏控制分层与时延目标、[游戏桥](../modules/game-bridge.md)、[决策模型](../modules/director.md)、[发声](../modules/speech.md#发声仲裁)中的发声仲裁、[观众接入与投票](../modules/audience.md#投票)中投票的游戏决策点、[安全核](../modules/safety-core.md)中的执行许可与急停、隔离与结案、[状态存储](../modules/state-store.md#重启)中的重启、[运维](../modules/operations.md)中的开播预检与观测、[Windows 平台](../platform/windows.md)中采集与输入一节、[合规](../compliance.md)中《魔女审判》与决策模型备案的条目、[真机探针](spikes.md)中的 S-02 与 S-04；Game Runtime 侧的[游戏桥](https://github.com/leafliber/bellis-game-runtime/blob/main/docs/modules/game-bridge.md)、[Bellis P3 契约提案](https://github.com/leafliber/bellis-game-runtime/blob/main/docs/plan/bellis-p3-proposals.md)、[《魔女审判》适配](https://github.com/leafliber/bellis-game-runtime/blob/main/docs/games/witch-trial.md)与[核协议](https://github.com/leafliber/bellis-game-runtime/blob/main/docs/modules/core-protocol.md)中的输入许可。

## 开工前置

**契约审核**：Game Runtime 提出的八条契约提案须由维护者逐条批准，批准结果写进[技术基线](tech-baseline.md)（R-28、R-29 已登记为待审核）与[游戏桥](../modules/game-bridge.md)的契约；批准前，下面的步骤以提案为假设。推荐与取舍：

| 提案 | 推荐 | 取舍 |
| --- | --- | --- |
| P-01 实时核的控制连接 | 接受 | 令牌直达实时核，符合 D-31 的“设备只认当前令牌”与“许可过期设备自己停止”；主进程只能让输入停下。宿主的本机通道因此要接受 `game-runtime.main` 与 `game-runtime.core` 两种角色，每种同时只接受一个连接 |

| P-04 坏结局、卡住与重读 | 接受 | 已试过的选项是否排除、是否重开投票由决策模型决定，投票插件不做特殊处理 |

## 步骤

1. **契约冻结。** 按批准的提案在 `packages/protocol` 写游戏桥契约（TypeBox，D-21）：两种连接角色与握手（契约主版本、适配包声明、操作员前置条件及确认状态）、下行命令（`goal.submit`、`decision.resolve`、`lease.renew`、`input.stop`、`pacing.hold`、`pacing.release`）、上行事件（`situation.observed` 含画面类型、看点标记与配音忙闲，`decision_point.opened` 含候选，`action.committed`、`input.released`、`health.reported`）；画面类型按 Game Runtime 的通用分类枚举。`pnpm run gen` 生成 JSON Schema 与 Pydantic 模型，另给控制连接消息的 fixture 供 Game Runtime 的 Rust 类型双向校验；Game Runtime 锁定这一提交的生成物（GD-03）。冻结后字段只加不改，不兼容的改动升主版本。

2. **真机探针。** 跑 S-02 与 S-04 的非提权部分，方法与记录要求见[探针](spikes.md)。S-02 与 Game Runtime 的 GS-07 合在一次测；结论改变设计时直接改对应模块文档与技术基线，需要改选路线的交维护者决定。

3. **本机通道与游戏桥插件。**
   - 宿主的本机通道接受 `game-runtime.main`（语义连接）与 `game-runtime.core`（控制连接）两种角色，认证同 R-05，每种角色同时只接受一个连接；Game Runtime 从 SecretStore 读本次会话的连接信息（R-23）。
   - 游戏桥插件提供 `game@1`：连接状态、握手结果、健康；上行事件先写成持久事实（`对象.过去式`）再分发；下行命令只由本插件发出。只持 `game.goal` 与 `game.input` 能力，不持凭据；控制连接不在时不申请也不续约 `game.input`。
   - 握手主版本不兼容、适配包与 profile 不一致时停在 WAITING 并说明原因。
   - 用假的 Game Runtime（本机通道客户端）做自动化测试，覆盖认证、角色冲突、断连重连与不兼容版本，在三平台 CI 运行。

4. **游戏输入许可。**
   - 安全核按 D-31、D-34 授予 `game.input` 许可：游戏桥插件申请，令牌与到期时间经控制连接直接发给实时核，按时长续约；吊销与到期时实时核自行释放全部输入并上报 `input.released`，记为事实。
   - 急停吊销全部许可之后，经控制连接发 `input.stop`；安全停止、维护态与重启后不授予。
   - 真人接管、本地急停热键与风险分超阈值的上报按安全事件处理：吊销许可、进入人工模式；交还控制只能由操作员执行。

5. **决策模型。**
   - 上下文加入局面摘要、决策点与候选、看点、坏结局与已试过的选项；来自游戏的内容一律标为不可信输入。
   - 时机：决策点打开（有计时的最高优先，可取消尚未开口的在途调用）、看点标记（带频率上限）、坏结局与卡住；普通局面更新只更新上下文。
   - 意图：选择（`decision.resolve`）、游戏目标（`goal.submit`，模式为自主、等待投票、暂停或人工）、发起投票时绑定决策点编号（只用于没有计时的决策点，D-07）。投票结束时按结果 `decision.resolve`；平票或无有效票时由决策模型自选。
   - 有计时的决策点：截止时间取余量线；到余量线仍没有回复时由 Game Runtime 执行排第一的候选，解说只讲 `action.committed` 里出现的事。
   - 坏结局：解说后以 `goal.submit` 给出继续的目标；卡住时决定开投票、自选或请操作员处理。
   - 用录制的局面与决策点夹具测时机的合并与取消，在三平台 CI 运行。

6. **发声仲裁。**
   - 游戏事件触发的解说以“游戏关键反应”来源发出（D-33），抢占规则不变。
   - 播出游戏关键反应或决策模型标为解说的发言时，以确定性代码发 `pacing.hold`（到期时间必填），播完或放弃时发 `pacing.release`；按配置在配音为忙时等配音结束再开口。

7. **运维。**
   - 开播预检中“Game Runtime 按 profile 就绪”：两条连接在、握手主版本兼容、适配包与 profile 一致、操作员前置条件全部已确认、没有结果未知的游戏意图。
   - `pnpm operator` 与操作台增加人工接管与交还控制；`status` 与操作台显示游戏状态（连接、模式、当前目标、等待中的决策点与截止、最近的被拒动作与风险分）；接管、卡住与被拒动作进近期告警。

8. **遥测。** 语义连接的消息带 `traceparent`，Game Runtime 的 span 与宿主在同一 trace；加直方图：游戏首动作时间（`goal.submit` 或 `decision.resolve` 到对应的 `action.committed`）与决策耗时（`decision_point.opened` 到 `decision.resolve`）。

9. **仿真。** 确定性仿真加入模拟 Game Runtime：局面、有计时与无计时的决策点、投票绑定、坏结局与卡住、真人接管、控制连接断开、许可过期，以及决策点等待中与许可持有中的宿主崩溃重启。不变量：没有有效许可时没有任何输入被执行；急停或许可过期后在许可时长内有 `input.released`；每个决策点至多一次 `decision.resolve`，绑定投票的在投票结束后才决定；解说不早于它所讲的 `action.committed`；`pacing.hold` 到期即恢复；重启后游戏输入意图停在结果未知，目标隔离直到操作员结案。

10. **真机联调与实测。** 与 Game Runtime 的 G3 同步：先真机互通（GR-28），再把 G2 的独立运行换成 Bellis 宿主；在真机上完成下面出口中的全部实测与演练，结果写入 `reports/`。顺带补测 P1 中要在游戏运行时测的项（被游戏遮挡时的 Stage 欠载与音高漂移、游戏负载下的 TTS 首包），结果写回对应模块文档。

## 出口

以下全部在 Windows 11 真机上实际运行通过，且三平台 CI 绿：

**平台与契约**
- 全部测试与固定种子仿真在真机上重跑通过。
- Game Runtime 锁定的生成物与 Bellis 契约出自同一提交；握手主版本不兼容时游戏桥停在 WAITING，开播预检不通过。
- 会话连接信息只经 SecretStore 交付，`pnpm secret audit` 在会话进行中与停止后各核对一次。

**许可与释放**
- 急停到全部输入释放、许可过期到全部输入释放的时延实测，对照[时延目标](../architecture.md#时延目标)；释放后按键状态核验没有残留。
- 控制连接断开、宿主强制结束时实时核自行释放，不依赖宿主配合。
- 安全停止与维护态下不授予许可，Game Runtime 不发任何输入。

**决策点与解说**
- 没有计时的选项：投票或自选都正确执行；投票的规则在开始时冻结，结果绑定到决策点；平票或无有效票时自选。
- 有计时的选项：在截止前自选；到余量线仍没有决定时由 Game Runtime 执行排第一的候选并上报，解说以实际发生的动作为准。
- 坏结局后解说、提交继续目标、重来；已试过的选项带标记进入上下文。这次游玩没遇到坏结局时记为 PENDING。
- 看点解说的次数不超过配置的上限；解说期间游戏不推进，到期自动恢复。

**完整剧情**
- 私有测试直播间中，M2 下操作员全程在场，AI 自主推进一段完整剧情，含对白、至少一次选项与一段审判讨论；同时录制。
- 重启不重做副作用的演练：在决策点等待中、许可持有中强制结束宿主，重启后不重复决定、不重发目标；游戏输入意图停在结果未知，操作员结案后才恢复真实输出。
- 真人接管后进入人工模式，不再发出目标与决定；交还控制只由操作员执行。

**运维与观测**
- 开播预检中 Game Runtime 一项的任一子项失败都不允许进入 M1–M3。
- 一个决策点从打开到执行的链路追踪完整，跨进程处带同一 trace；游戏首动作时间与决策耗时的直方图写出。

实测指标报告样本数与 p50/p95/p99，失败样本不剔除；目标数值在实测前仍为 PENDING。
