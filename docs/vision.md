# 愿景与目标

## Bellis 是什么

Bellis（贝莉）是一个 AI 主播的内核。一个角色在直播中同时做三件事：和弹幕观众交流、发起投票、自己玩游戏并解说。

内核把“想做什么”和“能不能做、怎么停”分开：

- **决定做什么**的是语言模型（下称“决策模型”）。它读取局面，选择要说的话、要发起的互动和要交给游戏的目标。
- **决定能不能做、怎么停**的是确定性的安全核。所有对外动作（说话、切场景、游戏输入）都要先经过它授权，它也负责停止和兜底。
- **完成具体工作**的是插件。说话、形象、弹幕、记忆、游戏桥等每项能力都是可以单独开关、加载和替换的插件。

## 最终目标

在已适配的游戏中，以 VLA（视觉-语言-动作）方式完全自主游玩原神这类游戏，覆盖即时战斗、剧情理解和多样的小游戏解谜，同时完成直播互动。长期目标包含无人值守直播。

游戏控制在独立仓库 [bellis-game-runtime](https://github.com/leafliber/bellis-game-runtime) 中实现；Bellis 作为主播内核，负责决策、表达、安全监督和两者之间的契约。

## 里程碑

1. **内核成立**：插件内核与安全核在全模拟环境中跑通一条完整的发声链路，停止与急停可证。
2. **能播**：在 Windows 的 OBS 中真实发声、出字幕、驱动形象，停止与急停实测可靠。
3. **能互动**：读弹幕、选择回应、发起投票、召回直播间的公开记忆。
4. **首次公开试播**：《魔法少女的魔女审判》，AI 自主游玩；无计时的选项由 AI 决定要不要交给观众投票，有计时的选项 AI 自己选；操作员全程在场。
5. **原神**：从探索和剧情开始，逐步加入解谜和战斗，由 VLA 自主游玩并直播。
6. **无人值守**：在自动安全机制满足门槛后，逐步减少人工在场的要求。

每个阶段的范围和门禁见[路线图](plan/roadmap.md)。

## 不做什么

- 零样本通关没有适配过的游戏。新游戏需要适配和离线训练。
- 在直播中在线训练并自动上线模型。模型更新先离线验收，再由人批准。

## 设计原则

这些原则来自对当前语音 agent、机器人 VLA 与 agent 安全研究的调研，具体依据见[参考资料](references.md)。

1. **快慢分离。** 慢的语言决策（秒级）只给出目标，快的本地执行（播放、停止、游戏控制，毫秒级）各自持有时钟，不等待慢路径。这与机器人领域的双系统 VLA（慢 VLM + 快策略）和语音 agent 的做法一致。
2. **观众输入只是数据。** 弹幕、昵称、礼物留言永远不授予任何权限。决策模型读了不可信输入、又要对外说话，所以它的上下文里不能有凭据、管理权和私密记忆（Meta 的 Agents Rule of Two）。
3. **一切动作经过安全核。** 动作表达为意图，由安全核按能力授权；守卫只能拒绝，失败即拒绝；执行器只在持有未过期的执行许可时才能动作。
4. **说出的以实际播放为准。** 已经说出的内容以播放端回报的实际播放位置为准，上下文只记录观众真正听到的部分。内容审核是可关闭的插件，用独立的审核模型逐句判定；关闭时不允许无人值守。
5. **一切皆插件，但安全核不是。** 能力以插件提供，按依赖自动激活，停用时先安全收尾再撤销注册；安全核随宿主一起构建，不经过插件加载器，不能被配置移除。
6. **重启不重做。** 每个副作用先记录意图再执行；重启只重建状态，永不重放说话或游戏输入这类有时效的动作。
7. **Windows 优先。** 直播机、OBS、游戏都在 Windows 上；代码不得依赖 POSIX 专有语义。
8. **证据说话。** 没有实测的数字写 PENDING；模拟通过不等于真机通过。
