## 8. 资源与就绪调度

### 8.1 资源类别

资源类别唯一登记在resources.json，ResourceClaim的Schema与其一致：

{{resource_kinds}}

speech/<persona>、Stage发声权和OBS场景写入使用排他资源；不可变画面/证据/投票冻结结果使用快照读；模型/TTS/Guard槽位与PCM字节使用容量资源。

游戏物理输入为`input/<host>/<interactive_desktop>`，由目标主机唯一Broker仲裁。`game_session_id`与会话租约是它下面的逻辑授权，不使两个共享桌面的游戏可以同时抢鼠标。Bellis不持有一把与Broker并列的物理输入锁。

#### control_critical资源类别

将本地快策略推理、必要感知和控制监督标为`control_critical`资源消费者，与普通`interactive_model`、`auxiliary_analysis`、`background`分开接纳。它仍是有界CAPACITY，不赋予绕过Broker、停止通路或安全审核的权力。

{{task_classes}}

该模式启用前验证可用预算；运行时优先保护本地停止、现有媒体消费和输入安全。若当前硬件无法同时满足这些底线，不启动对应continuous_local任务，或先减少非关键分析/批次/准备。不能单靠提高软件优先级声称抢占了GPU。

### 8.2 就绪优先的调度

```text
可运行 = 依赖结果成立 ∧ 证据仍有效 ∧ 服务质量可用
      ∧ 当前affordance允许 ∧ 授权/监督有效
      ∧ 资源可分配 ∧ 预算与时限允许 ∧ 无安全阻断
```

优先级只对可运行集合排序。一个等待游戏静音、依赖未完成的高优先级Task不能堵住所有其他兼容工作。确实必须阻止其它发言的节目安静范围，应以有限`quiet_scope`政策显式声明，而不是借队首阻塞实现。

相同类别内稳定排序与老化；老化不绕过权限和页面合法性。不得用“业务优先”让来源无界的业务队列永久挤掉普通聊天。

### 8.3 分阶段资源

推理、TTS合成、记忆检索不持有实际发声权；等待投票不持有鼠标；纯路线/证词计算不持有前台。资源需求由受信Manifest给出，模型不能自报“只读”豁免。

同一阶段需要的多个排他资源采用本地原子申请或固定申请序加有限失败回收。不能先持A无限等B。跨Runtime不做分布式长锁：先准备/预登记，再通过有界交接协议确认远端owner；失败时按已发生事实恢复。

### 8.4 父子任务委托

**同根授权内部委托：**父任务保留根owner，子控制器取得受限委托，不能再申请第二个相同根租约；根owner对输入合成与清理仍负责。委托含范围、期限、允许能力、父代次，子不能转授更大权限。

**释放后正式交接：**父任务停发、撤尾部、完成必要清理并确认释放，子任务再取得独立租约。父任务等待子结果时不持有子需要的冲突资源。

禁止“父持有资源→子重新申请→父等待子”。PlanValidator检查显式冲突，运行时再用等待图、超时和资源诊断发现动态冲突。无法确认隔离时，资源QUARANTINED，不强制把新控制器挂上去。

### 8.5 兼容矩阵

| 组合 | 策略 |
|---|---|
| 贝莉正在发言＋下一片段合成 | 同Utterance允许；有限预缓冲 |
| 贝莉正在发言＋另一普通回复准备 | 允许有限准备；不能抢占发声 |
| 游戏本地控制＋被动剧情采集 | 可并行，采集不自动推进页面 |
| 游戏控制＋打开菜单获取信息 | 需要前台交接，不是后台只读 |
| 投票计时＋聊天分析 | 可并行，投票确定性结束不等模型 |
| 两个游戏共享桌面输入 | 不并行，主机Broker统一仲裁 |
| 背景总结＋首段审核/合成 | 仅在前台保留额度满足时并行 |
| 原发言安全中止＋后续承接草稿 | 只让显式依赖失效，重新校验，不无脑续播 |

进程分离和优先级不是操作系统硬抢占保证。已经提交给GPU/供应商的工作未必可抢占，重点在接纳前预留、批次限制和累计预算。

### 8.6 局部计算的资源准入

区域重排、局部定位、编码缓存、候选编辑／打分、恢复审查分别登记资源与最大工作量。定位产生的多个crop数量有上限；候选块、编辑次数、审查点和反思项均有界。不允许一个“轻量辅助模型”以不计费、不计显存的方式默认常驻。

必要的本地连续策略按control_critical准入；剧情定位通常是受限交互计算，恢复诊断通常是auxiliary_analysis。静默／停止、当前音频消费和Broker watchdog不依赖这些模型完成。CPU/GPU不足时优先不接纳可选计算，按profile选择已批准的简单后端；没有可靠后端时报告unavailable，而不是隐式降级成无审核或长开环输入。

缓存淘汰、模型冷启动、ROI上传和失败重试的开销进入同一预算；共享GPU上需在游戏、OBS、皮套、媒体和必要模型共载时验证。独立进程、不同优先级或共享embedding均不构成硬资源隔离。
