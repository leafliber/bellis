## 21. 软实时预算、队列与费用

> 冻结的后续阶段设计，不参与生成与校验；现行部分见 [docs/spec/21-budgets-metrics.md](../../spec/21-budgets-metrics.md)。

### 21.2 统一预算字段

统一预算形状为附录B.7的WorkBudget，TaskRecord持久化其快照；task_class枚举来自resources.json。每项明确单位、起算点、范围和生效边界；最晚启动不得早于not_before，实际执行时限仍与Node/Activity/授权期限取最早者。

跨端传递剩余预算或明确时钟域，不拿不同单调时间直接相减。未知音频时长先保守估计，得到采样后更新，不能因未知无限接纳。新普通消息不能改变已采用发言的输出预算来截断它。

### 21.5 费用、429与身份连续性

公开profile必须设置session_cost_cap、rolling_hour_cost_cap、LLM Token、TTS字数/音频、VLM帧数、RPM/TPM、Guard额度、重试和推测浪费预算。价格来自所用Provider版本化配置；不填未知单价时采用有限调用上限，不视为无限。

已派发未返回成本暂占保守额度，取消不意味着退款。429按Provider提供的Retry-After和有限抖动退避，只重试仍有效且安全幂等请求；熔断后先推迟后台/推测、降低非关键感知，再进入同音色预录/文字或暂停。

必要审核不能因额度耗尽被绕过。当前已播流不因Provider限流从头重试；备用模型切换在明确边界重建安全上下文并通过人设/质量验证，不声称过去从未发生。

### 21.7 控制TimingContract与端到端指标

每个ControlCapability/Profile组合定义自己的TimingContract：观察最大年龄、估计/决策预算、提交期限、预期控制监督节奏、最多无新有效观察时间、动作承诺窗口、hold上限、健康续租期限、连续违约容忍和本地退出策略。字段单位、时钟域、配置范围和起算点必须明确，unknown不是无限期。

本设计不规定通用的10/30/60Hz达标口径，也不把外部实验的决策延迟作为目标硬件承诺。公开连续控制模式缺少这些有限门槛或缺少实测证据时标PENDING，不能用聊天首段1.5秒指标替代控制反应窗口。

```text
capture_started / frame_captured
→ state_estimated / local_policy_started / local_policy_decided
→ control_frame_built / broker_accepted / input_submitted
→ observed_effect / progress_confirmed
```

另记lease_renewal_rejected、control_deadline_missed、stale_action_rejected、target_lost、no_progress、degraded、takeover_started、input_settled。PolicyUpdate阶段时间采用第15.13节的对象字段；唯一应用事实为`control.policy_applied`，`PolicyUpdate.applied_at`从其来源发生时间派生。接收、重放与对账发现的时间单独记录，不双计应用，不把查询返回时刻当成应用时刻。

| 指标 | 口径 |
|---|---|
| 决策时观察年龄 | 采用状态时刻减原始关键证据采集时刻；跨域有映射/不确定度 |
| 观察到提交延迟 | 输入提交边界减该动作实际所依据的观察时刻 |
| 提交到效果延迟 | 由可见反馈估计，标明效果识别不确定度与无法观测样本 |
| 控制时限违约 | 所有被接纳控制工作中的deadline miss及拒绝比例，不能删除迟到样本 |
| 信息更新与动作频率 | 分报捕获率、新有效观察率、决策率、输入提交率，不互相冒充 |
| 闭环进展 | 停滞时长、振荡/过冲事件、目标失锁、局部恢复成功率与接管原因 |
| 策略更新 | 来源同域接收至实际应用、等待边界时间、冲突/过期、应用后质量；跨域另报通知延迟/不确定度，按唯一事实去重 |
| 直播影响 | 同时报告音频欠载/字幕偏差/OBS输出异常/停止尾部和GPU/CPU压力 |

“实际效果时间”无法直接测量时只报可测提交延迟与识别区间，不填假精确值。最终任务成功、平均循环频率或模型Token速度都不能代替上述指标。控制有效性和安全准入不与娱乐性总分抵消。

### 21.8 队列与资源的控制扩展

最新观察快照允许丢弃旧帧；关键剧情、Effect、接管、策略应用和清理回执仍走可追溯事件。纯持续输入状态可以在明确接纳边界前合并；一次性脉冲/相对增量不能按最新覆盖后悄悄补发。控制通道不与大量录像上传或示范导出共享阻塞队列。

control_critical本地模型资源不与一个长云端主控请求共用单一串行锁；同GPU不同进程也不代表硬隔离。完整负载不能满足声明时限时，先停推测准备/后台训练与非关键分析，限制批次/采样/加载；仍不足则不启用该连续模式。离线训练默认不与正式直播控制同时运行。

学习后端、规则后端和预测后端都按相同准入与回执契约评估。声明“更快模型”不改变取消、隐私、Effect或监督要求。

### 21.9 首段1.5秒的工程预算与验收口径

1.5秒是普通短回复、热连接、发声权空闲、无需额外上下文的待测目标，不是任意远端LLM＋任意审核＋任意TTS都可保证的默认能力。固定提示/“让我想想”不计实质回应。用户接入→入选→可说→真实首声分别报告，不能移走排队时间美化端到端体验。

| 顺序串行关键阶段 | 热路径工作预算上限（待测配置） | 实现约束 |
|---|---:|---|
| 决策快照/调度/请求准备 | 70ms | 有界上下文、预热连接；不读完整日志。 |
| LLM到首个完整稳定语义片段 | 500ms | 计到可审完整短句，不用TTFT代替；超时仍保留失败样本。 |
| 规范化、最小外发/隐私与结构检查 | 50ms | 本地确定性规则、固定词典/许可缓存；拒绝不外发。 |
| 必需内容Guard | 200ms | 固定模板可复用匹配的预审凭据；自由内容用已验收低延迟审核器，不把主控自审当许可。 |
| 普通TTS请求至首个可解码音频 | 300ms | 审核通过后请求；保留同voice/profile。 |
| 当前片段启动预缓冲 | 200ms | 与后续音频接收重叠；短片段完整EOS可提前就绪。 |
| Stage本地启动 | 50ms | AudioWorklet/字幕已热；装饰不阻塞。 |
| 抖动余量 | 130ms | 不用作额外无上限重试。 |
| **串行预算总计** | **1500ms** | **预算分配，不是各分位数相加得到的P50证明。** |

实测P50/P95从同一条trace的reply_admitted到output_started计算；逐阶段报告分布及等待/重叠。各阶段中位数之和不保证总链路中位数，各阶段P95也不能简单相加当总P95。通用目标仍为P50≤1.5s/P95≤3s，但未测达标的profile必须标PENDING或提高其公开声明预算。

NEEDS_MORE_CONTEXT、跨地域审核、复杂推理、冷启动或高风险音频抽检走独立慢路径，显式报告原因，不能省掉审核追1.5秒。speculative_tts仍默认关闭；已单独批准后可并行Guard和隔离合成，关键路径变为max(审核耗时,TTS首包耗时)，但最小外发门禁在两者之前，音频在正式许可前不能进入可播缓冲。

每次性能验收记录机器、游戏/OBS负载、模型/voice/Guard/profile版本、样本数、冷/热、被拒/超时/欠载和费用。达不到时先收短片段、预热/选已验收后端或放宽真实服务目标，不降低内容安全门槛。

### 21.10 后端内部预算与对照测量

首段语音预算继续采用第21.9节，不把定位或游戏控制的模型前向时延混入同一SLO。新的控制测量拆分为：

```text
capture／传输 → preprocess／ROI → 必要重排 → vision_encode
→ language_encode（cache miss时） → action_head／可选edit和rank
→ 解释／Broker接纳 → 实际提交 → 可见效果／清理
```

并行阶段按trace中的关键路径计算，不相加各阶段独立P50推导端到端P50。单独报告根观察在决策和输入提交时的年龄。定位的“一次最终模型调用”不免除重排、裁剪和上传成本；语言缓存命中不能把视觉或授权核验时间省略。

每个profile固定有界的capture／grounding／edit／review预算、最大候选／crop数量、最大模型并发、缓存字节、输出长度及任务累计费用。业务Action和TimingContract仍取最早deadline；子计算剩余预算不足就跳过可选步骤或明确失败，不能层层各获一个全新的timeout。

| 实验路径 | 分层报告 |
|---|---|
| 定位 | 正确目标定位、目标缺失误报、歧义拒绝、coverage／接受率、freshness拒绝、错误点击、总延迟与调用数。 |
| 计算复用 | cold／hit／miss／失效、各编码耗时、内存／显存、任务质量和完整端到端尾部延迟。 |
| 候选修正 | 原始先验年龄、新执行依据年龄、可编辑后缀长度、拒绝／冲突／延迟、实际任务收益与输入安全。 |
| 反思与恢复 | 同类错误重复率、审查次数／成本、恢复深度、未决效果、无效重试、剧情泄漏、人工接管与最终进展。 |

所有失败、拒绝和超时保留在分母；质量提升不能靠大量拒绝且不报告覆盖率来获得。验证使用目标游戏＋OBS＋皮套＋媒体＋必要模型的共载，可选模型的冷启动和显存占用也纳入。没有本机证据时只保留PENDING，不将论文硬件数值填成配置默认值。
