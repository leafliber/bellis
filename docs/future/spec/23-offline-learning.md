## 23. 离线能力学习与示范数据治理

控制示范与离线能力学习是默认关闭的可选路线：它没有输入授权、正式发言或Iris直接写入权；模型制品只在批准后于安全边界部署，不在线自动改权重（第3.8节）。

### 23.1 用途许可与采集范围

控制示范默认关闭。开启需单独指定用途、游戏/窗口范围、参与者许可、是否外发、保留期限、训练/评估边界、数据集访问者与退出机制。公开直播、Iris保存经历、允许截图用于当前决策，不自动等于允许用这些数据训练模型。

默认训练记录排除弹幕、昵称、SC正文、麦克风、管理页面、凭据和无关桌面。原游戏画面和人工输入只在声明最小范围采集；观众可识别内容出现在画面中时应屏蔽/脱敏或排除片段，不能仅因“来自游戏录像”视为无个人信息。

删除与撤回传播到本系统可控的数据集索引、派生样本、缓存、待导出和训练队列；记录模型制品的数据血缘。已完成训练后的处理按实际义务、许可和可行手段评估，必要时停用相关制品/重新训练；不承诺删除样本已自动消除权重影响。供应商、平台录像和第三方副本范围单列。无法完成所需治理时不启用该采集/训练用途。

Iris只可接收经过PrivacyGateway许可的语义经历或训练制品公开说明，不作为逐帧动作/原始示范仓库，也不因数据集存在提高某个观众声称的可信度。

### 23.2 三类记录的用途分离

| 类型 | 目标 | 默认内容／权限 |
|---|---|---|
| ExecutionJournal／控制审计 | 解释权限、输入、效果、清理与失败 | 必要关联与有限证据；不自动进入训练/公开上下文 |
| Iris语义经历 | 保留受许可的有意义经历、证据和来源 | 稀疏语义记录／引用；不保存全量帧与键盘轨迹 |
| DemonstrationDataset | 为特定局部控制技能提供示范和离线评估 | 独立批准的数据用途、精确时间/动作/模式对齐、来源标签与保留期 |

原始直播录像不自动满足控制训练要求。人工接管可以积累示范，但这只是方向，不是任何录像都能直接训练游戏能力的保证；学习后端一律要求独立验收。

### 23.3 示范episode最小契约

至少关联：`episode_id / dataset_scope / consent_or_authority_ref / purpose / game_profile / goal_ref / control_mode / action_schema_ref / calibration_ref / controller_and_model_versions / capture_clock / input_clock / alignment_uncertainty / observation_refs / decision_refs / executed_input_refs / result_refs / intervention_type / retention / deletion_lineage`。

每个动作样本分别记录：

| 标签层 | 内容 | 禁止混淆 |
|---|---|---|
| proposed | 模型/规则原本建议的动作、当时的依据与期限 | 不等于已提交到设备 |
| admitted | Interpreter/Broker允许的动作及被拒原因 | 不等于游戏接受或产生效果 |
| submitted | 实际后端输入起止、持续状态与组合关系 | 不以请求时刻代替真正提交 |
| human_observed | 允许范围内的真实人工操作及其可确认身份/时钟 | 无可靠合成/真实区分时不伪造来源 |
| outcome | 后续观察、进展、失败/未知、接管原因 | 不由动作模型自己写“成功” |

观测使用动作前信息，不能将动作后画面错配为策略输入。示范中同时保持的键、镜头增量、短按及控制模式必须对齐；未经验证的时间关联标低质量并隔离，不能填零误差。

### 23.4 人工接管与专家示范

intervention_type至少区分`rescue / deliberate_teaching / ordinary_play / administrative / unknown`作为数据标签，不是运行时权限枚举。救场可能包含探索或失败，普通娱乐操作也可能不服务当前任务，均需后续筛选。

人工物理输入能可靠映射到ActionSchema时才产生语义标签；按下某键在不同菜单/镜头/键位配置下含义不同。无法归一化时保留受许可的原始局部记录与不确定性，不自动发明“向目标前进”等高层标签。输入密码、切换管理界面、平台聊天等行政操作默认排除，不能开启全系统键盘记录来追求数据完整。

数据采集不阻塞Broker控制和撤权，独立有界队列/磁盘额度；丢失示范样本可标gap，不因此丢弃控制安全日志或停止已批准的关键本地行为。许可撤销先停止新采集，再清理控制范围内的记录和派生。

### 23.5 离线能力制品的批准与启用

```text
用途批准与最小采集 → episode质量/来源/时间对齐检查
→ 去敏、版本化数据集和固定留出集
→ 离线训练或局部模型校准
→ 无输入回放／契约测试／Shadow
→ 受控真机新动作对照＋完整直播负载
→ 人工批准模型制品、profile兼容与覆盖范围
→ 停用/安全边界新实例启用 → 运行指标与回归
```

留出集按episode、场景/视角/目标和时间范围划分，避免把几乎相邻的帧同时放入训练与测试夸大泛化。基准固定简单规则/VLM逐步控制/现有后端，比较相同任务、观察输入、硬件与全负载。学习方法没有实际收益可继续使用简单后端，不为算法名称引入必要性。

ModelArtifact记录内容digest、代码/动作Schema/Profile依赖、数据集/许可血缘、输出格式、资源需求、覆盖/限制、审核与批准证据。启用不等于允许模型扩大目标或修改看门狗；默认没有在线训练、自动改权重或未经批准部署。新模型在目标硬件未验证时保持PENDING。

### 23.6 当前三类模型实验的独立门槛

| 研究方向 | 前置数据／基线 | 不得跳过的验证 |
|---|---|---|
| DEM式解耦技能后端 | 当前已覆盖技能的授权示范；相同观测／动作/profile；规则或现有后端基线 | 训练任务范围与未见任务分开；cold／cache hit成本；真实输入和完整直播负载。 |
| EXPO-FT式编辑／价值后端 | 当前动作语义、真实提交前缀、延迟／抖动和有效编辑范围；无编辑基线 | 候选修正与脉冲去重；部分提交；新观察不足时拒绝；编辑器／critic制品分版本。 |
| RankGround式区域选择后端 | 有许可且包含相似／缺失／边界目标的界面数据；固定简单定位与整图基线 | 场景／语言／DPI／动画迁移；拒绝和覆盖；总开销而非仅最终VLM时间。 |

这三项是可选模型路线，不改变C4要求。S36包含学习适配机制，S37限定训练任务范围，S39限定其已评估界面条件；本文不声称已训练、下载或复现这些模型。[S36][S37][S39]

失败记录和ReflectionRecord不是天然训练标签。诊断假设、被拒动作、未知效果、跨分支受限知识和救场人工操作必须保留原标签／用途；不得将“模型建议过”当作已执行专家示范。反思在P3/P6作为运行时诊断使用，不需要先训练模型。

公开直播默认不在线探索训练、不更新权重。确需机器人式交互学习只能在独立批准、可复位、受监督的隔离实验范围内进行，仍不得把论文实验许可泛化为用户游戏或账号许可。新制品经数据血缘、留出集、真机和负载门禁后，才在安全边界启用。
