# Bellis V2 垂直切片路线图

本文件记录当前受控推进的垂直切片目标与真机验收出口；不记录历史进度、测试计数与本地路径。
每个切片的最小闭环均以“尽快获得 Windows 真机反馈”为目的，**不提前写死**——拿到真机实测结果后，允许随时回看并微调接口与闭环设计。

## Step 0：归档与定规矩

- **目标**：将 V1 两仓代码归档至本地 `dev-1` 分支；本地未跟踪资产隔离存入 `.local/`；建立无历史 `main` 单仓；固化防失控规则（[AGENTS.md](../AGENTS.md)）与已拍板的架构骨架（[architecture.md](architecture.md)）。
- **出口**：本地两仓保留 `dev-1`；远端 `bellis` 仅包含干净无历史的 `main`；目录结构、单套实时核协议、通用交互首版策略、四进程最小契约与推进顺序全部对齐。

## Step 1：单仓骨架与瘦身版 Rust 实时核

- **目标**：
  - 搭建 `core/`、`py/`、`web/`、`games/`、`tests/`、`lab/` 骨架与本机 Windows 快检查脚本（ruff、pyright、依赖方向与单文件行数红线、pytest；含 `core/` 时跑 cargo 检查）。
  - 从 `dev-1` 白名单移植并瘦身 Rust 实时核与通道：合并过薄 crate，统一为单套许可控制协议（`lease.renew`/`lease.revoke`/`input.stop`/`input.released`/`health`），以 `tests/fixtures/` 双向往返测试与共享内存偏移测试防漂移。
  - 实现极简 Python 读帧客户端与独立许可控制台（说同一套协议）。
- **出口**：在 HSR 游戏窗口上真机验证 WGC 读帧、授权点击/按键、窗口失焦停止、真人接管撤权与急停物理释放。

## Step 2：快主 Agent 最小闭环（优先独立游戏闭环，按需演进）

- **目标**：在 `py/bellis_game/` 内按严格单向分层（`io -> perception -> skills -> loop`）构建无插件内核的极简快循环；**首版先只用 VLM + 少量确定性基础动作/模板**，在 HSR 真机跑通一个有明确可观察完成条件的真实短目标。
- **出口**：完整记录单次目标的真实观察、动作执行、新帧独立核验与最终释放；遇未知界面、控制权失效或核验落空即停。跑通后按真机反馈做一次减法与接口微调，再决定是否补入 OCR/本地检测或进入 Step 3。

## Step 3：确定性直播底座、Rust 看门狗与慢主 Agent

- **目标**：
  - 在 `core/watchdog/` 实现 Rust 极简独立外部看门狗。
  - 在 `py/bellis_host/` 与 `web/` 中按白名单移植/重建确定性安全核、SQLite WAL 意图存储、OBS 应急连接、Stage AudioWorklet 媒体管线、本机操作台与慢主 Agent（弹幕合并、流式增量解析、发声与投票）。
- **出口**：Windows 11 + OBS 真机验证弹幕回应发声、打断静音、操作台控制、OBS 热键急停与 Rust 看门狗宿主挂死兜底。

## Step 4：快慢双主 Agent 事件流打通

- **目标**：基于 Step 2 与 Step 3 的真实运行需要，以共享的精简 Python 事件流契约（可按实测微调）接通慢循环与快循环，实现目标下发、离散事件上报、解说暂缓与决策点互动。
- **出口**：Windows 真机跑通边玩 HSR 边直播互动，以及任意时刻的急停与输入物理释放。
