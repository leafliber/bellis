# Bellis V2 垂直切片路线图

本文件记录当前受控推进的垂直切片目标与真机验收出口；不记录历史进度、测试计数与本地路径。
每个切片的最小闭环均以“尽快获得 Windows 真机反馈”为目的，**不提前写死**——拿到真机实测结果后，允许随时回看并微调接口与闭环设计。

## Step 0：归档与定规矩

- **目标**：将 V1 两仓代码归档至本地 `dev-1` 分支；本地未跟踪资产隔离存入 `.local/`；建立无历史 `main` 单仓；固化防失控规则（[AGENTS.md](../AGENTS.md)）与已拍板的架构骨架（[architecture.md](architecture.md)）。
- **出口**：本地两仓保留 `dev-1`；远端 `bellis` 仅包含干净无历史的 `main`；目录结构、单套实时核协议、通用交互首版策略、四进程最小契约与推进顺序全部对齐。

## Step 1：单仓骨架与瘦身版 Rust 实时核

- **目标**：
  - 搭建 `core/`、`py/`、`web/`、`games/`、`tests/`、`lab/` 骨架与本机 Windows 快检查脚本（ruff、pyright、依赖方向与单文件行数红线、pytest；含 `core/` 时跑 cargo 检查）。
  - 从 `dev-1` 白名单移植并瘦身 Rust 实时核与通道：合并过薄 crate，统一为单套许可控制协议（`lease.renew`/`lease.revoke`/`input.stop`/`input.released`/`health`），以 `tests/fixtures/` 双向往返测试与共享内存偏移测试防漂移。
  - 实现极简 Python 读帧客户端与独立许可控制台（说同一套协议）。
- **出口**：在 HSR 游戏窗口上真机验证 WGC 读帧、授权点击/按键、窗口失焦停止、真人接管撤权与急停物理释放。

## Step 2：快主 Agent 最小闭环（优先独立游戏闭环，按需演进）

- **目标**：在 `py/bellis_game/` 内按严格单向分层（`io -> perception -> skills -> loop`）构建无插件内核的极简快循环；**首版先只用 VLM + 少量确定性基础动作/模板**，在 HSR 真机跑通一个有明确可观察完成条件的真实短目标。
- **出口**：完整记录单次目标的真实观察、动作执行、新帧独立核验与最终释放；遇未知界面、控制权失效或核验落空即停。跑通后按真机反馈做一次减法与接口微调，再决定是否补入 OCR/本地检测或进入 Step 3。

## Step 3：确定性直播底座、Rust 看门狗与慢主 Agent

- **目标**：
  - 在 `core/watchdog/` 实现 Rust 极简独立外部看门狗。
  - 在 `py/bellis_host/` 与 `web/` 中按白名单移植/重建确定性安全核、SQLite WAL 意图存储、OBS 应急连接、Stage AudioWorklet 媒体管线、本机操作台与慢主 Agent（弹幕合并、流式增量解析、发声与投票）。
- **出口**：Windows 11 + OBS 真机验证弹幕回应发声、打断静音、操作台控制、OBS 热键急停与 Rust 看门狗宿主挂死兜底。

## Step 4：快慢双主 Agent 事件流打通

- **目标**：基于 Step 2 与 Step 3 的真实运行需要，以共享的精简 Python 事件流契约（可按实测微调）接通慢循环与快循环，实现目标下发、离散事件上报、解说暂缓与决策点互动。
- **出口**：Windows 真机跑通边玩 HSR 边直播互动，以及任意时刻的急停与输入物理释放。

## Step 5：一键启动、提权按需计划任务与凭据 CLI

- **目标**：
  - 在 `core/crates/realtime-core/` 增加经 Windows 凭据管理器读取核通道凭据（`--core-cred`）并以核通道断开作生命线的启动方式，使非提权 `game-agent` 能通过预注册的按需提权计划任务（`HighestAvailable`）直接拉起提权实时核。
  - 提供统一的 `game` / `live` / `all` 启动入口、按需计划任务 XML 生成/读回核对命令（管理员注册命令仅打印，不自提权）与不回显、不落日志的凭据管理 CLI。
- **出口**：在普通（非管理员）Windows 11 终端中一条命令跑通 `all` 模式联动 HSR 与 OBS，验证授权输入、急停物理释放与退出后凭据自动清理；计划任务 XML 读回核对通过。

## Step 6：HSR 真实可玩切片（游戏音频感知、动作扩展与连续目标）

- **目标**：
  - 将 `AudioRing` 与实时核 WASAPI 进程回环接通至 `bellis_game`，以轻量本地配音活跃检测避免角色配音期间误点跳过或慢循环抢话。
  - 按 HSR 真实交互需要扩展基础输入动作（滚轮、受限按住按键等，仍受实时核物理时长上限与失焦/接管即释放约束）。
  - 按真机耗时与误判痛点补齐最小确定性界面快路径与轻量剧情文本感知，向慢循环提供连续叙事上下文并支持多步连续游玩。
- **出口**：在 HSR 真机与本机操作台/OBS Stage 下连续跑通一段真实剧情或组合日常；不吞游戏配音、解说与画面台词一致，遇未知界面、控制权失效或核验落空即停并完成物理释放。

## Step 7：开播预检、重启结案门禁、断线恢复与可观测性

- **目标**：
  - 将开播预检收敛进生产路径（OBS 场景/源/静音、Stage、看门狗、凭据、游戏端连接），不通过禁止进入 `LIVE` 或授权输入。
  - 在操作台暴露重启恢复的 `unknown` 意图并要求人工结案后才恢复操作；为 `ObsClient` 与 `GameSession` 补齐可控断线重连。
  - 补全慢循环、发声、TTS 与游戏链路的 JSONL 遥测与跨进程 `trace_id`，配极简 p50/p95/p99 统计脚本。
- **出口**：预检缺项必拦；强杀 Host 重启不重做副作用且须操作台结案；产出真实首字语音与游戏首动作时延分位数。

## Step 8：完整 AI 主播直播形态（真实弹幕、VTS 形象、SQLite 公开记忆与本地 TTS API）

- **目标**：
  - 接入 B 站直播开放平台真实弹幕（心跳、重连、脱敏入 `AudienceHub`），并为慢循环增加有界冷场/自主节奏。
  - 经 VTube Studio WebSocket API 按 Stage 播放游标与游戏事件驱动口型与基础表情，急停/静音立即闭嘴复位。
  - 在现有 `HostStore` SQLite 中增加轻量公开记忆表供慢循环召回（严格隔离凭据与私密信息）。
  - 保持薄 `TtsSynthesizer` 接口，按需对接本机 TTS API 服务替代或补充云端 MiniMax。
- **出口**：在 B 站私有测试直播间全栈真机跑通真实弹幕互动、VTS 口型与字幕对齐、跨重启公开记忆召回、边玩 HSR 边播及任意时刻急停/接管/看门狗兜底。

## Step 9（T1 出口）：审核开关、合规标识与长稳试播压测

- **目标**：在 `SpeechArbiter` 发声前挂接可开关的内容审核，在 Stage/OBS 呈现 AI 主播合规标识，完成操作员全程在场（M2）下的连续真实负载稳定性压测。
- **出口**：30–60 分钟真实负载压测（HSR + OBS + VTS + 弹幕 + TTS）的音频欠载、帧率影响与时延分位数达标，通过 T1 小流量公开试播门禁。
