# Bellis V2 垂直切片路线图

本文件只记录当前受控推进的垂直切片目标与真机验收出口；不记录历史进度、测试计数与本地路径。

## Step 0：归档与定规矩

- **目标**：将 V1 两仓代码归档至本地 `dev-1` 分支；建立无历史 `main` 单仓；固化防失控规则（[AGENTS.md](../AGENTS.md)）与精简架构骨架（[architecture.md](architecture.md)）。
- **出口**：本地两仓均保留完整 `dev-1` 参考分支；远端 `bellis` 仅包含干净无历史的 `main`；待讨论的 `OPEN-1` 至 `OPEN-5` 明确列出并逐项拍板后进入 Step 1。

## Step 1：单仓骨架与瘦身版 Rust 实时核

- **目标**：搭建 `core/` + `py/` + 自动防失控检查（循环依赖、行数红线）；白名单移植并瘦身 Rust 实时核（统一为单套许可控制协议），以极简 Python 客户端在 Windows 真机跑通采集与授权输入闭环。
- **出口**：在目标游戏窗口（HSR）上真机验证 WGC 帧读取、授权点击/按键、失焦停止、真人接管与急停物理释放。

## Step 2：快主 Agent 最小闭环（通用交互 + HSR 首个短目标）

- **目标**：以“通用交互”为核心，在严格单向分层下构建精简快循环，不依赖插件内核与假设备重基建，在 HSR 真机跑通一个具备可观察完成条件的真实短目标。
- **出口**：完整记录真实目标的感知、动作提交、新帧核验与终止释放；遇到未知界面或失效即停。

## Step 3：确定性直播底座与慢主 Agent

- **目标**：按白名单思路在 Python 侧重建精简的确定性安全核、SQLite WAL、OBS 应急、外部看门狗、Stage 媒体管线与慢主 Agent（弹幕、决策流式增量解析、发声与本机操作台）。
- **出口**：Windows 11 + OBS 真机验证弹幕回应发声、打断静音、操作台控制、OBS 热键急停与看门狗兜底。

## Step 4：快慢双主 Agent 事件流打通

- **目标**：基于 Step 2 与 Step 3 的真实运行需求，用最小共享 Python 事件模型打通慢循环与快循环（目标下发、状态/看点上报、解说暂停与决策点互动）。
- **出口**：Windows 真机跑通边玩 HSR 边直播互动与随时急停释放。
