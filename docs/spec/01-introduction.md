## 1. 引言

> 第 1.8 节属于后续阶段，冻结在 [docs/future/spec/01-introduction.md](../future/spec/01-introduction.md)。

### 1.1 系统定位

Bellis／贝莉是一个角色、多项工作、单一高层采用权的软实时直播运行时。LiveDirector采用目标、计划候选和表达；确定性运行时管理权限、任务、效果、清理和恢复；Stage承担正常音画输出；独立Game Runtime完成受控游戏闭环；Iris只通过PrivacyGateway接入。

```text
可信事件与证据 → LiveDirector采用 → 受限Plan或直接表达
                         ├─ Task → Attempt → 实际结果／Effect → Settlement
                         ├─ Scene → Utterance／TextPresentation → Stage → OBS
                         └─ game.bridge → Game Runtime → 唯一Input Broker
                                                ↓
                                       观察、回执、对账与语义进展
```

### 1.2 目标与保留原则

首批目标为沟通交流、观众投票和《魔法少女的魔女审判》剧情游戏直播。系统需要在LLM、TTS、审核和游戏执行同时进行时保持可控、可追溯、可停止，并逐步扩大已验证覆盖，而不是以接口数量代替可用性。

| 原则 | 统一约束 |
|---|---|
| 单一采用权 | LiveDirector是唯一正式高层采用者；Planner产候选，本地PolicyBackend只在已批准目标内选短动作。 |
| 微内核与可信插件 | 通用运行时不硬编码平台字段、人物、游戏坐标或Provider参数；只加载受信插件。 |
| 非阻塞多工作 | 主控默认一个在途调用；事件归约、已授权工作、Stage、投票和本地游戏循环持续推进。 |
| 普通弹幕非抢占 | 普通消息、礼物正文和@只进入候选队列，不取消当前推理、发言或游戏工作。 |
| 事实分层 | 请求接受、实际完成、效果已确认、资源已清理分别记录；停止请求不覆盖真实结果。 |
| 局部故障隔离 | 未知只封锁冲突效果、资源和依赖；不能因单句异常结束常驻聊天。 |
| 分阶段交付 | 先媒体和受监督交流，再有限计划、投票与剧情选择；连续控制、Iris、学习路线按需启用。 |

### 1.3 范围

交流包括候选选择、回复定位、公平排队、流式表达和冷场政策；投票包括冻结规则、计票、平票处理和结果播报；剧情直播包括采集、证据分析、阅读节奏、受控选择和人工接管；运营包括内容/隐私、配对、监督、OBS兜底与明确的公开准入。

常驻Activity是有限授权期限内可持续接纳多项工作的容器；有限Plan有明确完成条件。两者都受监督、预算和deadline限制，不能依靠“常驻”取得无限授权。

### 1.4 非目标

首播范围不包括未知插件市场、任意Shell或通用桌面任意操作、多个正式发声者、跨系统可回滚副作用、陌生游戏零样本通关、自动在线训练与上线。连续战斗、MPC、示范训练与学习型编辑/价值网络不作为剧情首播前置。阶段未实现的能力必须关闭并报告unsupported，而非空实现通过。

本设计只允许后端声明的有限沙箱快照或游戏读档恢复。公开声音、已发生效果、安全授权、删除墓碑和累计预算不承诺回滚；未实现真实恢复的后端只能重建上下文、另行授权补偿或请求人工。

### 1.5 产品边界

普通弹幕不能产生管理权限。经过身份核验的删除/退出请求走主体范围隐私流程，不因非抢占原则而忽略。只有认证操作员、监督、安全检测或已批准活动策略可以停止相应工作。

正常表达与业务模板都经过Scene／Stage。OBS独立应急路径限固定安全画面、静音和已验收停流，不提供第二套自由发言入口。
