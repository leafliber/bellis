## 24. 验证与验收

> 第 24.6–24.7、24.9–24.11 节及第 24.5 节中只涉及后续阶段的故障项冻结在 [docs/future/spec/24-verification.md](../future/spec/24-verification.md)。

### 24.1 测试层级与证明边界

| 层级 | 验证什么 | 不能证明什么 |
|---|---|---|
| 文档/Schema结构检查 | 锚点、字段、引用、状态目标与枚举一致 | 守卫实现、真实执行或内容安全 |
| 单元/契约 | 解析、权限、状态、资源/依赖、预算、效果键 | 真实设备结果 |
| 模型化/属性测试 | 调度乱序、重复、旧Attempt、死锁、尾部栅栏、EOS、崩溃窗口 | 所有可能轨迹的形式化证明 |
| FakeStage/FakeRuntime | 异步协议、清理、事件游标、暂停/局部更新、失联 | 实际音画和游戏物理 |
| 脱敏录制回放 | 感知、剧情去重、选择策略、证据和内容质量 | 采取不同动作后的反事实游戏结果 |
| 真机固定场景 | 输入效果、停止、音画、恢复、阅读/选择闭环 | 未覆盖游戏的泛化 |
| 完整直播负载 | 游戏/VLM/皮套/TTS/OBS竞争下尾部延迟与接管 | 所有硬件和任意过载下的保证 |

参考模型必须让同一组场景驱动真实SUT适配器比较事件/状态/效果，而不只是对常量断言。可采用fast-check等工具进行命令生成、调度和缩减，但引入前锁定版本。[S24]

P0 在契约落地后先建立最小受信 Node 验收运行器，再随实现增加场景。运行器实际启动宿主、监督、假设备与真实持久化路径，使用隔离测试操作员经正常鉴权入口驱动，执行断言并保存原始轨迹；不能由人工填写 PASS 清单决定状态。端点计数、水位、未执行/未知范围与清理事实必须和宿主投影交叉核验，停止请求不替代端点停止。预期拒绝、故障和 UNKNOWN 可以满足断言，但报告保留真实业务结果，不改写为成功。

P0 归约器经有界 stderr 输出 P0ReductionObservation，只记录真实输入与实际归约结果。状态使用对应生成枚举；未调用守卫时结果为 null，不以 true 代替；timer 记录原计划截止而不是采集时伪造的期限。序号、对象及触发摘要由受测进程产生，runner 只能事后与场景关联，不能给归约器注入 scenario_id、任意 payload 或指定守卫结果。端点按 P0EndpointObservation 写出实际快照，原始描述符直接继承给 runner，不能只收 Host 转发投影；与认证 RPC 返回的端点来源、实例、计数水位、清理事实及 host.query 的实际本地缓存交叉核验。

P0ProcessObservation 记录受信 parent 实际执行的创建尝试、创建结果、失败与退出，或进程自身启动拒绝；预期实例、实际 PID 与真实退出结果分开。EOF、发送 kill 成功或父进程退出不证明子进程退出，无法观测时保留未知。P0ProtocolObservation 来自真实传输发送/接收路径；入队不表示送达，Schema 合法的接收不表示已鉴权或执行，响应保留真实结果或拒绝。原始事件以完整 RpcEvent 观测，Schema 合法不表示通过 writer/epoch 守卫；公告接收使用专用分支，同次接收不重复记作普通事件。本地失败仅保存封闭安全错误分类，不伪造服务端响应；非法帧只可保留完整有界原帧的摘要与长度，不原样倾倒到日志。运行器驱动正常正向链时须实际调用 CLI 并记录其真实进程和协议结果；直接 RPC 负例保留运行器来源，外层 CLI 请求不能代替内部请求的真实接收证据。

### 24.2 不变量与测试映射

不变量登记在`contracts/src/invariants.json`，每条有稳定编号、必测方向、最早实现阶段和验收状态；测试映射与阶段出口登记在`verification.json`。现行阶段的清单见[P0](../generated/P0.md#不变量与测试)与[P1](../generated/P1.md#不变量与测试)契约简报。

标注最早实现阶段不表示该阶段以前可以绕过已启用能力的安全要求；同一性质在新增后端中必须重测。验收状态只有在真实SUT测试运行并提交证据后才能从PENDING_SUT改为PASS，契约工具测试不能关闭SUT不变量。

P0 的 sut_build_digest 是确定性受测输入/制品清单的 SHA-256，覆盖实际启动的 apps/host、packages/runtime、plugins/fake-device、contract-sdk、必要生成物、锁文件、workspace/TypeScript/package 配置及实际运行依赖；不能只哈希单一入口。runner 清单同时覆盖运行器、辅助代码、断言/场景、清单算法和影响行为的实际依赖，包含原生模块实际制品。清单采用唯一排序的仓库/依赖规范相对路径、大小和文件摘要，内容摘要排除 reports、临时路径、时间戳与秘密；实际 Node 可执行文件摘要、版本、pnpm、系统和依赖环境另行记录。

P0BuildManifest 与 P0TestRunEvidence 作为 AcceptanceReport 中按哈希引用的封闭原始证据。gate 自行按受审查覆盖规则遍历当前构建及 runner 依赖，重算清单/摘要并核验原始文件完整性，不能信任报告提供的缩减文件集合或仅检查摘要非空。必需场景、进程实际启动/退出、命令、seed/轨迹、期望/实际断言、效果与清理、三状态机适用转换/守卫拒绝/表外事件/终态不复活及竞争覆盖均须可追溯；P0 禁用模式只验证拒绝。exit.P0 另提供启用 profile 摘要与实际依赖情况，P0 无前置阶段时明确记录空依赖。受信边界是可审查运行器、明确构建、完整原始证据和可复跑过程，不建立签名平台或通用证明框架。

所有 P0 只读观测流按 epochs.json 的唯一写入者与固定作用域分配序号，每次真实观测尝试都占序号，背压或写出失败累计丢失数，不能回退或补零。写出必须有界且不占安全循环；正常收尾限时排空后，由同一写入者最后输出唯一 P0ObservationStreamEnd，之后该流不得再有数据或第二个结束记录。运行器同时核对最终尝试数、累计丢失、完整数据序列和原始采集 EOF；结束记录缺失、尾部丢失、截断、坏行或身份混流均不能悄然算完整覆盖。尚未建立实例的 null 来源仅属于失败即结束的启动流，不能与后来实例拼接。强制崩溃等预期异常可以满足对应故障断言，但受影响应用观测流保留 incomplete/UNKNOWN，不能补尾或伪造零丢失；断言须有真实父进程 exit/signal 及独立认证 RPC 事实支撑，允许的终止边界由受审查场景明确限定。应用观测流不完整不豁免原始采集完整性：即使该流因预期 crash 没有 end，capture 文件、完整性索引、哈希以及 EOF 或实际采集关闭事实仍必须齐全；不得把缺文件、采集截断或任意坏行套成预期崩溃。

观测共同使用去敏 stderr，可保留共享继承描述符；PID、日志字段和管道不是密码学身份。原始来源依靠已绑定构建、实际父子关系和认证 RPC 交叉核验，stderr 不参与生产授权、停止或清理证明。协议观测中的请求/响应由 commands 登记派生，不能手写命令副本或以任意 JsonValue 承载输入与成功结果；仅去除操作员 proof_hmac 或 peer signature，并以固定 redaction 标记和原认证器字符串的 SHA256 表示去敏，其余合法 context/input 保留。禁止输出 authentication_key_sha256、私钥或私有启动材料。保留真实公告签名供验签；去敏后的认证器摘要只用于两端一致性核对，不能宣称离线验证 HMAC。

命令归约通过实际接收观察关联：触发摘要使用现有 authenticationDigest，触发身份绑定连接、接收实例、RPC id 和实际接收观察序号，精确算法见 P0ReductionObservation。元数据沿受信内部调用链传递，不增加 RPC 字段或接受调用方指定；去敏后可重算该认证请求摘要，但完整 transport payload_digest 只能比较两端原承诺，不能声称已重算完整载荷。实际 parent exit 或真实通道关闭/失败可通过内部 process_fact/protocol_fact 触发安全归约，绑定相应完整观察的 JCS 摘要与记录身份；生产代码使用真实回调，不读取 stderr、不伪装尚未到期的 timer。尚未建立实例的启动失败不能冒充已有运行对象来源。

P0 覆盖报告分别保留三种来源：真实 SUT 场景及其正常归约观测；在身份、Schema 或幂等层提前拒绝而未进入归约器的实际入口结果；同一个生产归约器的全表模块测试。模块测试使用受控依赖的事实必须明确标注，不能关闭14个 sut.*，也不能冒充真实进程轨迹。不得为机械覆盖状态表添加额外状态驱动 RPC；禁用准入仅验证拒绝。

### 24.5 故障注入最小集合

首次片段早于EOS输出；同一发言追加时弹幕突发；远端取消永不返回；乱序/重复/缺片；seal早到；Stage重启；审核前缀变化；soft-finish后尾部迟到；前序发言异常；监督假活；数据库满；预算耗尽。

每失败保留固定seed/最短轨迹、版本、期望/实际状态、去敏证据和接管记录。不把测试skip算PASS；真实后端未接入则标NOT_IMPLEMENTED/PENDING，也不引用任何历史通过数量。

P0 按 invariants.json 中的适用场景执行身份冒充、安装替换、配置与 scope 越权、人工租约仅有心跳、时钟/实例/代次失效、重复/冲突 operation、乱序停止/完成、存储阻塞/满/失败、队列满、预算耗尽及重启记录缺口。必须组合注入宿主阻塞或退出、持久化阻塞与 cancel 永不返回，验证独立监督与端点租约仍推进停止。验收工具另外拒绝缺失、跳过、失败、陈旧构建、runner 依赖改变、篡改及不完整原始证据。当前 macOS 以外的宿主验收和 S-4 物理故障未覆盖范围保持 PENDING。
