## 24. 验证与验收

> 第 24.6–24.7、24.9–24.11 节及第 24.5 节中只涉及后续阶段的故障项冻结在 [docs/future/spec/24-verification.md](../future/spec/24-verification.md)。

### 24.1 测试层级与证明边界

| 层级 | 验证什么 | 不能证明什么 |
|---|---|---|
| 文档/Schema结构检查 | 锚点、字段、引用、状态目标与枚举一致 | 守卫实现、真实执行或内容安全 |
| 单元/契约 | 解析、权限、状态、资源/依赖、预算、效果键 | 真实设备结果 |
| 模型化/属性测试 | 调度乱序、重复、旧Attempt、死锁、尾部栅栏、EOS、崩溃窗口 | 所有可能轨迹的形式化证明 |
| FakeStage/FakeRuntime | 异步协议、清理、事件游标、暂停/局部更新、失联 | 实际音画和游戏物理 |
| 脱敏录制回放 | 感知、剧情去重、选择策略、证据和内容质量 | 采取不同动作后的反事实游戏结果 |
| 真机固定场景 | 输入效果、停止、音画、恢复、阅读/选择闭环 | 未覆盖游戏的泛化 |
| 完整直播负载 | 游戏/VLM/皮套/TTS/OBS竞争下尾部延迟与接管 | 所有硬件和任意过载下的保证 |

参考模型必须让同一组场景驱动真实SUT适配器比较事件/状态/效果，而不只是对常量断言。可采用fast-check等工具进行命令生成、调度和缩减，但引入前锁定版本。[S24]

P0 在契约落地后先建立最小受信 Node 验收运行器，再随实现增加场景。运行器实际启动宿主、监督、假设备与真实持久化路径，使用隔离测试操作员经正常鉴权入口驱动，执行断言并保存原始轨迹；不能由人工填写 PASS 清单决定状态。端点计数、水位、未执行/未知范围与清理事实必须和宿主投影交叉核验，停止请求不替代端点停止。预期拒绝、故障和 UNKNOWN 可以满足断言，但报告保留真实业务结果，不改写为成功。

### 24.2 不变量与测试映射

不变量登记在`contracts/src/invariants.json`，每条有稳定编号、必测方向、最早实现阶段和验收状态；测试映射与阶段出口登记在`verification.json`。现行阶段的清单见[P0](../generated/P0.md#不变量与测试)与[P1](../generated/P1.md#不变量与测试)契约简报。

标注最早实现阶段不表示该阶段以前可以绕过已启用能力的安全要求；同一性质在新增后端中必须重测。验收状态只有在真实SUT测试运行并提交证据后才能从PENDING_SUT改为PASS，契约工具测试不能关闭SUT不变量。

P0 的 sut_build_digest 是确定性受测输入/制品清单的 SHA-256，覆盖实际启动的 apps/host、packages/runtime、plugins/fake-device、contract-sdk、必要生成物、锁文件、workspace/TypeScript/package 配置及实际运行依赖；不能只哈希单一入口。runner 清单同时覆盖运行器、辅助代码、断言/场景、清单算法和影响行为的实际依赖，包含原生模块实际制品。清单采用唯一排序的仓库/依赖规范相对路径、大小和文件摘要，内容摘要排除 reports、临时路径、时间戳与秘密；实际 Node 可执行文件摘要、版本、pnpm、系统和依赖环境另行记录。

P0BuildManifest 与 P0TestRunEvidence 作为 AcceptanceReport 中按哈希引用的封闭原始证据。gate 自行按受审查覆盖规则遍历当前构建及 runner 依赖，重算清单/摘要并核验原始文件完整性，不能信任报告提供的缩减文件集合或仅检查摘要非空。必需场景、进程实际启动/退出、命令、seed/轨迹、期望/实际断言、效果与清理、三状态机适用转换/守卫拒绝/表外事件/终态不复活及竞争覆盖均须可追溯；P0 禁用模式只验证拒绝。exit.P0 另提供启用 profile 摘要与实际依赖情况，P0 无前置阶段时明确记录空依赖。受信边界是可审查运行器、明确构建、完整原始证据和可复跑过程，不建立签名平台或通用证明框架。

### 24.5 故障注入最小集合

首次片段早于EOS输出；同一发言追加时弹幕突发；远端取消永不返回；乱序/重复/缺片；seal早到；Stage重启；审核前缀变化；soft-finish后尾部迟到；前序发言异常；监督假活；数据库满；预算耗尽。

每失败保留固定seed/最短轨迹、版本、期望/实际状态、去敏证据和接管记录。不把测试skip算PASS；真实后端未接入则标NOT_IMPLEMENTED/PENDING，也不引用任何历史通过数量。

P0 按 invariants.json 中的适用场景执行身份冒充、安装替换、配置与 scope 越权、人工租约仅有心跳、时钟/实例/代次失效、重复/冲突 operation、乱序停止/完成、存储阻塞/满/失败、队列满、预算耗尽及重启记录缺口。必须组合注入宿主阻塞或退出、持久化阻塞与 cancel 永不返回，验证独立监督与端点租约仍推进停止。验收工具另外拒绝缺失、跳过、失败、陈旧构建、runner 依赖改变、篡改及不完整原始证据。当前 macOS 以外的宿主验收和 S-4 物理故障未覆盖范围保持 PENDING。
