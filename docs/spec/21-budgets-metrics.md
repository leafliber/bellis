## 21. 软实时预算、队列与费用

> 第 21.2、21.5、21.7–21.10 节属于后续阶段，冻结在 [docs/future/spec/21-budgets-metrics.md](../future/spec/21-budgets-metrics.md)。

### 21.1 各类工作分别限额

优先保护本地停止、当前音画连续性和游戏输入安全；其次为确定性业务、当前交互生成；辅助分析与后台整理有独立额度。资源分级不是能抢占已派发GPU或供应商请求的保证，必须在派发前预留。

| 队列／资源 | 限制与过载 |
|---|---|
| 聊天候选 | 条数/年龄/字节/同质簇；合并、过期、拒绝新候选并记录，不抢断当前工作 |
| 决策信号 | 类型/合并窗口/最老年龄；防无限防抖，不每事件都调LLM |
| 分类待播 | business/paid_ack/chat槽位与预计时长＋全局上限 |
| 当前发言 | 未审字节、已冻结时长、隔离音频、PCM字节/毫秒、序号窗口 |
| 最新状态 | 快照合并；关键证词/效果/终态独立可靠处理 |
| 投票事件 | 本地一致性与事务；区分上游不可核验、已知缺口、本地丢失 |
| control_critical | 必需采集/本地快策略/控制监督；模式启用前验证保留预算，超时按控制契约降级 |
| 服务/后台 | 并发、积压与重启预算；服务质量变化及时传递到依赖 |
| 重试/恢复 | Task/Effect共享总次数、时间、成本，不层层倍增 |

### 21.3 首段启动不等于整体体验

```text
实际开口时刻 ≈ max（首片段可播时刻，发声权可用时刻）＋本地启动开销
```

必须分别记录首段生成/审核/合成/准备、发声排队和节目主动等待。响应太长时再快的模型也无法绕过单一嘴巴；改进回复规划长度和有限预缓冲，而不是暗开抢播。

同步启动只看当前必需片段；可选表情并行限时；连接、字体、基础素材开播预热。媒体控制面与大数据面分离，急停不排在音频包后；高频进度合并而非逐次同步落盘。

### 21.6 观测目标

| 指标 | 首轮建议目标 | 边界 |
|---|---|---|
| 本地确定性反馈 | P95≤150ms | 有效事件→本地状态/提示，不含自由LLM判断 |
| 普通聊天首段实质回应 | P50≤1.5s，P95≤3s | 入选且允许发声/通道空闲；另报完整接入到开口 |
| 可播且发声权可用后的启动 | P95≤50ms | 不隐去审核、预热、合成和排队 |
| 本地停止发声 | P95≤200ms | 指定本地输出边界，不包括平台缓冲 |
| 可靠词级字幕偏差 | 绝对偏差P95≤80ms | OBS实际录制；片段字幕另计，不冒充词级精度 |
| 连续输出与游戏闭环 | 报欠载/最长空白/页面失败/恢复耗时 | 不用平均速度掩盖持续性问题 |
| 错误授权、重复不可逆效果、弹幕抢占 | 测试中为0，说明覆盖 | 不是无限执行上的数学保证 |

全部数字未实测。报告样本数、P50/P95/P99、超时/失败/拒绝/合并、冷/热启动、完整负载和降级模式；失败样本不从分母剔除。复杂推理可使用不同预算，不用通用聊天指标迫使它无依据抢答。

时间点至少包含event_received、reply_admitted、model_request_started、text_stable、normalization/egress/guard起止、first_audio_received、segment_committed、startable、output_started、seal/EOS、各对象终态、settlement、effect确认、checkpoint、resume和stop确认。并行阶段不机械相加；跨域用可验证映射。
