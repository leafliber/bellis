## 25. 实施路线与发布门禁

> 第 25.3、25.8 节属于后续阶段，冻结在 [docs/future/spec/25-roadmap-gates.md](../future/spec/25-roadmap-gates.md)。

### 25.1 分阶段路线与最小交付

阶段是交付边界，不要求P0实现全部目标规范。现行契约只登记P0/P1；后续阶段的设计冻结在docs/future，进入该阶段时再迁回、修订并登记。Schema存在不表示能力已实现，disabled/unsupported必须由Manifest和准入检查落实。

| 阶段 | 目标 | 依赖 | 状态 |
|---|---|---|---|
| P0 | 基础约束与安全骨架：严格消息/错误/作用域/时限，SupervisionMode、ExecutionGrant、StopOperation 与假端点安全撤权 | — | 现行，见[P0 契约简报](../generated/P0.md) |
| P1 | 无LLM媒体闭环：媒体状态机、局部媒体清理与 StagePairing | P0 | 现行，见[P1 契约简报](../generated/P1.md) |
| P2 | 真实表达：主控NDJSON、真实Guard、增量TTS与降级 | P1 | 冻结 |
| P3 | 通用执行：Activity/Task/Attempt/Effect/Settlement、静态Plan | P0 | 冻结 |
| P4 | 真实互动：平台接入、两轮投票、付费账本、公平队列 | P2、P3 | 冻结 |
| C0 | 公共控制基线：任何真实自动游戏输入的前置 | P3 | 冻结 |
| P5 | 剧情游戏：只读Bridge与定位先行，有限输入 | P4、C0 | 冻结 |
| P6 | 有限恢复与修订 | P3 | 冻结 |
| P7 | 可选Iris与扩展 | P0 | 冻结 |
| P8 | 按profile发布：试播、完整负载、许可与应急 | P0 | 冻结 |
| C1–C5 | 连续控制、策略更新、覆盖复用、学习后端、局部预测 | C0 | 冻结 |

P1实现Scene、Utterance、UtteranceAdmission、Segment、AudioProduction、TextPresentation六个媒体状态机和StagePairing配对状态机，并复用P0的StopOperation；配对认证是P1必须完成的安全工作，不能因为只关注媒体而省略。P1局部清理证明是媒体对象契约，P3再统一到完整Settlement注册服务，不要求P1提前搭通用任务引擎。

每阶段的不变量按invariants.json的first_required_phase列在对应契约简报中。不变量在最早阶段用当时已有的端点验证基础形式（P0使用假端点）；游戏、媒体、Iris具体端点在其启用阶段扩展同一性质，不拿假端点PASS替代真机。

阶段实施保持串行：上一阶段 gate PASS 且用户验收后才启动下一阶段。可选阶段不自动加入主线前置。P0 只完成第20.2节的假设备安全骨架与独立清理，不接入真实设备，不迁回冻结设计。

### 25.2 三个最小闭环

**媒体闭环：**固定合法片段与延时音频块→首段先于EOS输出→弹幕/慢计算继续→本地停止→旧流拒绝→输出事实和清理记录可查询。

**执行闭环：**静态计划→多个Task按兼容性并行→一个Attempt失败→同Effect安全重试或IN_DOUBT对账→结果与Settlement分开→后继正确放行；常驻观察器不阻止活动完成。

**剧情闭环：**采集一段完整对白→原声/阅读条件满足→当前选项讨论/投票→结果播报normal完成→页面／目标定位再核验→一次选择→可见效果与输入清理确认→剧情笔记更新。

这三个闭环分别证明媒体、通用执行和领域适配。通过其中一个不能代替另外两个。

### 25.4 增量实施边界

当前实施先完成P0安全骨架，再完成P1固定内容的增量媒体闭环。最小实现仍须具备适用的授权、停止、幂等、旧消息拒绝和清理验证；已有模拟端点仅用于协议联调，阶段出口按第25.7节取证。

P0/P1期间，不读取、参考或迁回冻结的后续阶段设计，不扩展通用任务引擎、自动恢复、Iris、连续控制和学习后端。只在当前闭环发现结构矛盾、缺少必要边界或实测假设不成立时修改相关规范与登记；不为可能的未来需求增加抽象或实现义务。

主线保持 P0→P1→P2→P3→P4→C0→P5→适用 P8，逐阶段通过门禁并经用户验收。P3先记录失败事实，P5先验证只读定位再有限输入；需要自动恢复时再启用P6，Iris仍属P7可选。达到对应阶段时再展开实施细节，阶段依赖和验收要求仍以现有登记为准。

控制优化依次比较：简单规则／适配器→精确依赖的语义复用→可选快速专用后端→慢策略确有收益时的执行前修正。训练模型先通过C4；连续控制先通过C1；兼容调参另需C2。新后端的测试许可不要求先拿到尚未产生的该后端质量报告，但必须已有C0及基础安全、白名单、预算、监督和急停；生产启用再等实际质量门禁，避免循环前置。

Bellis只承担公共契约、桥接、受限上下文和投影；Game Runtime承担定位、候选修正、输入前缀、动作解释及真实恢复。不能因为算法接入困难而绕过Broker、另建主控、全局回滚数据库或把未来剧情注入当前上下文。

P0 的合法 simulation 首验准入与证明边界只按第20.2节判断；不要求尚未产生的自身 P0 PASS，不豁免任何实际安全条件。工作包模块交付不等于依赖完整执行链的场景通过，缺持久化前置时保持待集成，不能用成功占位存储或预置 ACTIVE grant 补齐。

### 25.5 发布门禁

| 门禁 | 必需证据 |
|---|---|
| 契约一致性 | 对应profile所用Schema/状态/错误/事件/代次/守卫的单一登记、fixture和生成无漂移；禁止用未实现守卫默许。 |
| 执行安全 | 实际SUT覆盖停止/超时/自然完成竞争、局部UNKNOWN、人工结案、去重与清理；底层端点证据明确。 |
| 真机控制 | C0后持test_only许可测试；目标profile的输入隔离/停止/清理/Effect/页面与接管通过才可public。 |
| 公开播出 | 内容/读音/剧透/隐私、身份配对、监督、许可、AI声明、OBS全部输出与独立兜底、音画/负载测试。 |
| Iris公开召回 | 检索前ACL、来源不升格、墓碑/摘要/缓存/备份恢复与第三方外发测试。 |
| 自主范围扩展 | 对应C1–C5规范、固定对照、真机/负载、失败/接管与费用报告。 |

验收状态为PASS/FAIL/PENDING/NOT_IMPLEMENTED。profile仅启用PASS能力；构建通过不能把未测状态改为PASS。权限、合规、安全与性能分别有门槛，不相互抵消。

### 25.7 机器可判定的阶段出口

verification.json 登记阶段依赖、稳定测试 ID、实际 runner 与实现状态，以及 exit.P0 等阶段出口；性质与必测方向只在 invariants.json，见对应契约简报。未实现项保持 NOT_IMPLEMENTED/PENDING_SUT，SDK 检查使用单独 ID，不能关闭 SUT 项。

门禁工具计算所选阶段的依赖闭包。只有全部必需测试实际实现、执行断言通过，且第24.2节规定的当前契约、构建清单、runner 依赖、环境与完整原始证据匹配才返回 PASS。缺失、跳过、未执行、失败、陈旧、篡改和不完整证据均拒绝，不靠通过数量抵消。gate 必须重算当前文件覆盖与摘要，而不是检查 sut_build_digest 非空或只哈希 runner 入口。

先用真实结果更新登记状态，重新生成、检查并完成提交；再在完成报告引用的最终提交上重跑验收与 gate。最终取证后修改源码、契约或受测配置，必须重跑受影响验证并刷新证据。reports/ 不提交，在实际阶段 worktree 保留原始文件、完整门禁输出与可复跑命令，交接完成前不删除 worktree。

P0 首验准入和假设备证明边界见第20.2节；P0 PASS 不证明真实设备、公开输出或其它系统已通过。验收报告是运行器产物，JSON 本身不创造真实性；不引入通用签名或证明平台。
