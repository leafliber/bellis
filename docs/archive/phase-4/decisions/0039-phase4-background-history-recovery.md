# ADR 0039：受控后台历史核验

状态：后台维护 worker 及真实安装验证已完成；完整恢复与安全解除未完成。日期：2026-09-07。

ADR 0038 已支持发现原 runId，但仍需调用者逐次执行 `resume()`。新增 `MemoryHost.startHistoryRecovery(verifier, options)`，由可信装配显式启用后台维护。启动后立即尝试一次，此后等待固定间隔再发现缺口、恢复清单并核验；开始时没有缺口，后续出现的持久缺口也能被发现。该方法不启动普通 Provider、Persona、Context 或 Outbox。

每个宿主、每个已注册 Provider 只有一个 worker。重复相同配置返回原 worker；不同 Verifier 或配置在活动期间拒绝替换。间隔默认 30 秒，允许 100–60000 ms；单次运行期限最多 60 秒。每次尝试结束后再等待间隔，不累计追赶错过的轮次，不产生并发突发。

宿主失效代际会取消当前调度器；后续轮次由宿主工厂创建新代际调度器，重新读取真实隐私与持久清单。超时或取消提前返回时，worker 仍等待原调度器的实际底层工作结束，不创建新实例来绕过在途上限。已停止但仍有底层调用的 worker 也不能被替换。宿主关闭取消全部 worker 并清除定时器；不合作的外部调用仍保留原容量，不宣称已被强制终止。

暂时不可用及正常清单冲突可在下一轮重试，已持久结论会被跳过。明确不可重试的 Provider/Persistence 错误和身份/响应绑定错误转入 attention，停止定时重试，等待可信装配处理后显式重建。真实隐私 blocked 不发 HTTP；每轮只读取状态等待策略变化。状态快照不包含原异常正文，lastResult 明确为历史结果而非当前授权。

该入口提供受控后台维护服务；生产启动器仍需显式选择维护装配，普通 Runtime 的失败启动语义保持。自动进入运行期/启动期恢复模式、其他事实核验、旧策略请求再授权、跨批次一致性和原子解除仍待完成。任何 incomplete 或 lastResult 都不恢复记忆读取、投递或事件游标。

九项 Runtime 专项通过；最终根检查日志记录 1049 项单元/性质测试、269 项集成测试通过，168 个生成契约无漂移。真实 Core/Chromium 验证后台轮询只核验一次，后续轮次与 Worker 重启复用持久结果；工具及既有 24 组恢复冒烟通过，完整恢复入口保持退出 2。见 [本轮证据](../../../evidence/phase4-background-history-recovery-probe.json)。
