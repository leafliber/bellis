# ADR 0040：Runtime 启动与运行期历史恢复状态

状态：Runtime 恢复装配及真实安装验证已完成；完整事实核验及安全解除未完成。日期：2026-09-07。

ADR 0039 的后台 worker 需要可信调用者显式启动。普通 Runtime 遇到已保存的 Iris 缺口会启动失败，无法提供维护生命周期。新增可信 `Phase4MemoryOptions.historyRecovery`，为每个已注册 Provider 配置一个独立核验端口及轮询参数；不从 JSON 配置、模型、Stage 或网络输入构造凭据与端口。配置固定后，正常启动也注册后台 worker，以发现后续缺口。

宿主先读取持久策略并绑定 Session。发现已保存缺口且配置恢复端口时，直接进入恢复状态，不启动普通 Provider、Persona 或事件流。若 Provider 在启动过程中发现缺口，只有宿主已经收到持久 historyBlocked 才允许转入恢复；先停止已经启动的普通所有者，再启用维护 worker。没有缺口的凭据等启动错误继续失败并清理。未配置恢复端口时不将 Provider 的启动失败变成成功。

Runtime 在恢复状态监听 loopback，live 返回 200，ready 与新会话交换返回 503；新 Control/Media 连接沿用现有 readiness 门禁。启动期未装配的决策 HTTP 入口不可用；运行期已注册的决策 HTTP 入口返回 503。启动期恢复不构造决策宿主，因此不恢复待处理输入、不注册工具或重放决策。运行期缺口首先取消当前 Context 和投递，并中断演出、关闭决策管道；Persona 刷新停止。已有连接的后续输入仍受关闭管道及宿主屏障约束。

历史恢复状态在本次宿主生命周期内保持，单批 valid、历史 lastResult 或后续策略读取均不解除。MemoryHost 的 Context、输入投影、请求存证和投递也检查该状态。Runtime 关闭沿用统一资源清理，取消后台 worker；Verifier 仍由可信装配持有，其网络调用接受宿主取消信号。此决定不添加公开的“强制恢复”入口。

恢复仍只覆盖当前策略代际的原 Recall 请求。其他事实、旧代际重新授权、跨批次一致性、远端权限变化的完整覆盖与安全原子解除继续实施。生产凭据配置加载器、真实旧备份/分叉及完整崩溃矩阵也不由本项替代。

最终根检查退出 0：1049 项单元/性质测试、274 项集成测试通过，168 个生成契约无漂移。十四项历史恢复集成测试包含持久缺口启动、启动发现、运行期发现、重启和错误清理。Node 原生 TypeScript 运行兼容问题已修复，并通过最终完整复跑。真实 Core/Chromium 联合回归及工具验证通过，既有 24 组恢复冒烟通过，完整恢复入口仍退出 2。见 [本轮证据](../../../evidence/phase4-runtime-history-recovery-probe.json)。
