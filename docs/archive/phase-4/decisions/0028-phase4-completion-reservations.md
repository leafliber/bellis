# ADR 0028：活动演出的持久收尾额度

状态：Worker 内的独立收尾预算与确认事务崩溃恢复已实现；完整容量与端到端恢复 Gate 仍开放。日期：2026-09-07。

## 持久预算与所有权

Migration 16 增加 `phase4_completion_reservations`，与 EffectPreparation 同一事务保存每个 Scene 尚未使用的音频绑定数、片段确认数。每行同时代表一次关闭额度。没有新公开 RPC 参数允许调用方自行选择“特权写入”；Worker 只为已有的绑定、确认和关闭操作临时设置相应预算，实际写入前必须存在该 Scene 对应的未用额度。

默认 4 KiB 数据库页下，各操作的 pager cache 预算为：

| 操作                               | 每次缓存预算 | 每个计划最多次数 |
| ---------------------------------- | ------------ | ---------------- |
| 音频绑定                           | 512 KiB      | 32               |
| 片段确认，含全部八个 Provider 投影 | 2 MiB        | 32               |
| 关闭并释放未用额度                 | 512 KiB      | 1                |

字幕计划不预留音频绑定。页大于 4 KiB 时按 `pageSize / 4096` 放大额度；现有 64 KiB 页数据库已验证。预算仍由 ADR 0027 的原生提交检查执行，收尾期间将干净页缓存建议值暂设为 128 KiB 并回收可释放缓存，结束后恢复普通事务设置。启动先校验原生模块私有 ABI 2，旧二进制不会在接纳演出后才暴露小预算不兼容。

四个最大音频计划共保留 322 MiB 的数据库页用量预算，另计算每次提交的 WAL 帧、填充和 wal-index 增长。按 SQLite [WAL 索引实现](https://raw.githubusercontent.com/sqlite/sqlite/master/src/wal.c)，每 4096 个帧号使用 32 KiB 区域，首区域更小；计算额外保留一个区域处理边界。索引额度计入文件系统剩余空间检查，不混入 WAL 文件长度。

## 后台写入不能消费额度

所有经过 state/telemetry 适配器的普通写入，在首个实际写操作前检查持久余额。state 必须为全部未用收尾额度及普通事务最大增量留下逻辑页空间；两个数据库的普通写入都必须留下收尾所需文件系统空间。检查额外计入已提交但尚未由 WAL 写入数据库文件的页，以及本次普通写入的数据库、WAL、索引增量。无法保留时返回 `storage_not_ready`。

普通写入仍受 WAL 软阈值拦截；收尾事务可以使用阈值以上的专用空间，其上限为普通 WAL 边界加四个最大计划的 WAL 额度。每次成功收尾消耗自己的计数，后续调用重新读取余额，因此不能无限绕过阈值。多语句 exec 由 SQLite 自己识别每条语句的长度，逐条执行；在一个 exec 中开始多个事务也会逐个刷新预算，而不是复用旧余额。

`readDiskStatus().capacity` 报告 `stateReservedBytes`、`stateReservedWalBytes`、`stateReservedAuxiliaryBytes` 和 `activeCompletionReservations`。ready 将剩余页和文件系统预算纳入判断，普通事务使用较大缓存配置时也不会假报 ready。现有目录高水位与最小剩余空间检查继续生效。

## 事实、重试与恢复

新音频绑定与绑定额度扣减同事务提交；新回执、确认文本、所有目标的 Observe/Outbox/游标及确认额度扣减同事务提交。重复绑定、重复确认和重复关闭不重复扣减，也不产生新的观察。输入或范围校验失败不会消耗额度。关闭将准备记录标为关闭，并在同一事务删除剩余额度。

新 Worker 启动沿用既有策略：旧 Stage generation 不能恢复为活动演出。恢复对每个旧 Scene 使用其已有关闭额度，各自事务性关闭准备记录并释放未用额度，保留已经提交的绑定、回执、确认文本与 Outbox。部分关闭成功后重试只处理剩余记录；已提交回执的原身份重试仍返回 duplicate，未提交的旧演出回执不能被补写成已发生的新事实。历史无额度记录只走普通预算，不凭空授予收尾额度。

已完成 Migration 的数据库只读验证注册表；没有 in-flight Outbox 或旧演出时不发出空写入。因此外部只读快照跨 Worker 重启并持续阻塞检查点时，可用原关闭额度完成恢复，读取已确认事实，但 ready 保持 `wal_pressure`，新工作仍拒绝。若确有 in-flight Lease 需要恢复，该普通写入不能使用 Scene 的收尾额度；migrate 明确失败且不开放业务操作，外部快照释放后可在同一 Client 重试。成功迁移状态只在全部启动恢复步骤成功后设置。

隐私策略关闭准备记录时，在同一策略事务释放已关闭 Scene 的收尾额度；原事实、抑制记录和 tombstone 保持原语义。普通关闭也兼容清理先前策略路径留下的已关闭记录额度，重复关闭不发出空写入。

新增受控检查点仅走既有私有 IPC observer，不增加 HTTP/WS 故障入口：`before_effect_transaction_commit` 在全部事实和扣减已写入、尚未提交时暂停；`after_effect_transaction_commit_before_ack` 在提交后、向 Client 返回 ACK 前暂停。异步检查点等待期间，连接仍保有该确认事务的预算作用域。

## 证据与边界

最大形状测试覆盖四个计划、每计划 32 个片段、八个大目标描述，以及接近文本长度上限、需要 JSON 转义的内容。真实旧快照阻塞检查点且后台写入已停止时，全部绑定、1024 个 Observe 投影及关闭成功；重复和错误回执不扣额度。另验证接近逻辑页上限时仍可确认，重启释放未用额度并保留事实。

两个确认事务窗口各运行 20 次真实 SIGKILL。每次先使后台写入因 WAL 压力停止；父进程核对提交前后独立连接所见的事实与余额，再杀进程并重新打开同一目录。提交前窗口不留下回执/Observe；提交后丢 ACK 的窗口保留一条回执、八条观察，原身份重试只返回 duplicate。逐例证据包含不同子进程 PID、SIGKILL、原回执身份与恢复断言。

本轮预算不等于向操作系统预分配独占磁盘块。其他进程抢占空闲空间、文件系统元数据与特殊分配粒度、真实 ENOSPC、旧备份及完整容量矩阵仍需验证。外部读者跨重启已覆盖四 Scene 关闭、无额外写入的重复重启，以及 in-flight 恢复受阻后重试；这不证明旧备份或所有进程组合。预算计算和最大形状测试不能替代这些 Gate；新确认事务的 40 个本地崩溃案例也不能替代真实 Core/Stage 的全部进程组合。Phase 4 保持进行中。
