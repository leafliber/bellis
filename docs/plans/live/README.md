# 直播套件工作线 L5–L8

状态：待实施与验收。排期及联合出口见 [双线路线图](../README.md)。本线由 Bellis 负责；Iris 保持独立记忆服务。当前 Fake TTS、DOM Avatar 与测试 Signal 只是基础链路，具体事实见 [能力状态](../../reference/current-status.md)。

## L5：无游戏也能真实直播

目标是开发版最小直播体验：操作者在最小 Studio 中选定配置、连接测试房间，真实弹幕触发模型回复，经真实语音、字幕和 Live2D 在 OBS 呈现；不依赖游戏 Runtime 启动。

| 子项 | 交付内容 | 结束证据 |
| --- | --- | --- |
| **L5.0 基线与契约** | 复验现有 Scene/输出确认/Iris 边界；选定一个实际 LLM、TTS、角色和平台；冻结输入/音频格式、资源映射、延迟采样口径、凭据配置与插件公共面 | 依赖清单、现有检查结果、所选版本及逐项 Gate；不把 Phase 4A 恢复成绩当作声音/角色成绩 |
| **L5.1 模型与真实流式语音** | 复用现有 ModelProvider/SpeechProvider；接一个真实可取消 TTS，覆盖文本分段、首块、背压、超时、字幕时间轴和重连；生产配置明确选择实际 Provider | 真正可理解的语音经过 AudioWorklet/Stage 确认；紧急打断后无尾音继续提交、未播部分不进入“已说”历史；默认夹具不冒充真实 Provider |
| **L5.2 Cubism 与基础主动表现** | 真实 Cubism Adapter、资源/能力映射、Mixer 六层优先级及通道租约；基础眨眼/呼吸/注视、LipSync、Directed 动作与受控 Reactive/Presence | 真实模型在无 LLM 时保持基础表现；Directed/Safety 正确抢占和释放；播放/取消时嘴形与已播音频一致；重连回安全状态，无过期动作补播 |
| **L5.3 首个平台插件** | 默认 Bilibili；通过公共 Plugin SDK 注册房间连接、弹幕/礼物/关注映射；身份、去重、限流、重连与禁用清理；适配已有 Audience Batcher | 测试房间收到真实事件并驱动同一 Loop；重复/乱序/洪峰不会重复回应、无限积压或重复记忆；平台故障不阻塞本地停止 |
| **L5.4 最小 Studio** | 提供会话启停、角色/房间/Provider 选择、连接/readiness、静音/停止演出、可信确认与基本错误提示；配置密钥引用而非在浏览器暴露密钥；复用同一插件宿主 | 不编辑源码即可运行选定组合；操作员能停止演出和禁用插件；可信确认绑定实际目标，普通观众输入不能充当授权；不要求此时完成全部插件市场/回放 UI |
| **L5.5 Windows + OBS 无游戏验收** | 在真实 OBS Browser Source 检查透明画面、音频路由、字幕、WebGL/Worklet、焦点/页面重载和断线恢复；冻结无游戏样例 | 一次记录完整的弹幕→模型→语音/字幕/角色→输出确认→Iris 往返；操作者确认音画真实可用；配置、版本、日志摘要与录屏来源可追溯 |

L5 完成需要 L5.0–L5.5 全部通过。资源缺失时可以完成适配器和模拟验证，但标记真实子项未运行。保留 Recording/DOM/Fake 路径用于 CI；真实模式不能静默降级到测试波形或文字徽标而报成功。

平台输入写入 Iris 前须经宿主可信映射，明确 actor、房间、来源与隐私标签；观众昵称/正文不能自动成为可信用户身份或工具授权。L5.4 将实际需要的确认和受控记忆工具装配到可信操作入口，保留当前 Surface/目标核验限制；未验收的写能力明确停用，不能用演示启动成功代替完整授权链。

L5.3/4 依赖 G5 中 Bellis 所有的公共 SDK 注册/权限生命周期，SDK 只实现一份；L5.1/2 不必等待游戏服务。G5.4 可先以确定性输出证明协议，**J5 必须再用 L5 的真实声音/角色验证**。

## L6：直播稳定性与首款游戏联合

在 L5 上补齐真实播出时的故障与可观测性，不重复建设语音或平台适配器。

| 子项 | 必须完成的行为与验证 |
| --- | --- |
| **L6.1 降级与人工接管** | 模型/TTS/平台/Core 超时、断线、限流分别有有界队列和明确状态；停止演出、静音、停止 Activity 与物理输入急停明确分开；人工命令走可信入口，优先级/取消不因后台工作阻塞 |
| **L6.2 角色与媒体负载** | 游戏同机时检查音频欠载、渲染帧耗时、字幕偏差、动作争用、内存与句柄趋势；录制明确负载下的启动/首音/取消分位数；Mixer/Presence 无持续定时器泄漏 |
| **L6.3 记忆与恢复** | 从 Phase 4B 清单冻结 J6 必需的活动输出/Observe 崩溃组合、事件缺口/迟到结果、容量准入与收尾验证；未证明可安全解除历史屏障时沿用当前 fail-closed、readiness 与决策停用边界并给出可信维护入口，不能带不确定记忆继续宣称恢复成功 |
| **L6.4 运维与联合表现** | 最小 Trace 串联平台事件、Turn/Cycle、Scene、Activity、game/session/operation、已确认输出和记忆来源；可见的停用/重连/恢复状态；游戏事件只进入 Bellis 一套语音与记忆管道 |

Phase 3 的子任务取消 P99 ≤100ms 目标仍开放：分别采样模型流、工具退出/资源释放、Stage 停止，校准时钟并记录误差、样本与负载。游戏 Broker 的输入释放单独测量，不把 Studio 点击到 Turn idle 的一个数同时充当所有指标。音质、嘴形和实际 OBS 输出需要真实检查；自动回执证明的是对应技术事实。

L6 各项完成后参加 [J6](../README.md)：至少 2 小时计划负载、冻结任务链和故障注入都需要证据。G6 独立游戏测试通过不能替代该联合出口。

## L7：直播扩展与长时运行

| 子项 | 范围与验收 |
| --- | --- |
| **L7.1 Provider 与 MCP** | 在既有 Context/Tool/Observe 边界接至少一个额外 Provider 与选定 MCP Adapter；共享 Deadline、预算、来源、权限、取消、隐私失效和缓存隔离可验证；慢 Provider 不串行拖住全部召回 |
| **L7.2 完整表现策略** | 补齐礼物/关注/主题、工具等待、胜负/加载、看游戏/弹幕/镜头的策略；冷却、随机种子、通道仲裁与能力降级可测试；换游戏不重放旧会话动作 |
| **L7.3 恢复与诊断** | 逐项关闭 Phase 4B 剩余旧快照/cursor/容量/恢复范围；支持脱敏诊断和事实回放，回放不重新发送工具/游戏输入或重写记忆；展示成本与降级原因，敏感数据遵守宿主策略 |
| **L7.4 长时直播** | 固定版本、弹幕/媒体/记忆负载，参加至少 8 小时 J7；覆盖重连、配置/权限撤销、不同游戏/Host 切换及单一人格表达；检查资源增长与队列可恢复性 |

本线只承诺首个平台的完整链路；新增更多直播平台需另列真实验收范围，不为“平台化”无限增加插件。Phase 4B 只有原清单全部有证据才关闭，不能因为其工作分配到 L5–L7 就提前宣布完成。

## L8：可安装的直播产品

将 L5 的最小 Studio 扩展成完整配置、插件/权限/Activity、Trace/回放和诊断界面；交付 Bellis Launcher、自带 Runtime、凭据/资源配置、签名更新及回滚。对首次安装、配置迁移、升级失败、资源缺失、离线重启、诊断导出和卸载的数据保留策略形成验收。

与 G8 联合安装时保持独立进程、发布版本和数据归属。managed 只启动受控安装物，游戏模型/代码更新不穿插在未结束 Session 中；无源码机器通过 [J8](../README.md) 才可标记正式交付。真实 TTS、Cubism、平台插件与 OBS 基础均为前序交付，不在此阶段首次接入。

## 当前执行方式

从 [Phase 5 总入口](../phase-5.md) 开工。每个子项补实现、匹配测试、更新同主题证据；外部服务/资源条件见 [支持清单](../README.md)。计划中没有可执行的新 `test:live` 命令，实际落地后才更新构建指南。
